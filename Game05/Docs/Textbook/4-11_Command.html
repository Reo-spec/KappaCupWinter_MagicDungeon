Command ― 操作を「もの」にする

難易度 ／ 前提 2-10

01この章でできるようになること

  • キーコンフィグを作れる
  • リプレイを作れる
  • AIとプレイヤーで、同じ操作の仕組みを使い回せる

02困っている形

void Player::Update()
{
    if (g_pad[0]->IsPress(enButtonLeft))  { m_position.x -= SPEED * dt; }
    if (g_pad[0]->IsPress(enButtonRight)) { m_position.x += SPEED * dt; }
    if (g_pad[0]->IsPress(enButtonA))     { Shot(); }
    if (g_pad[0]->IsTrigger(enButtonB))   { Bomb(); }
}

動きます。でも、こうなると詰みます。

やりたいことこの形だと
ボタン配置を変えられるようにする 全部の if を書き換える
リプレイを録るできない
デモプレイ（AIが遊ぶ） 入力を偽装する仕組みが要る
操作不能状態にする 全部の if にフラグを足す

03考え方 ― 「入力」と「やること」を切る

いまは「Aボタン」と「撃つ」が直結しています。 間に一段はさみます。 

Aボタン ──→ 撃つ               ← いま

Aボタン ──→ 「撃つ」という命令 ──→ 撃つ    ← Command

間にはさんだ「命令」を、もの（オブジェクト）として扱える ようにするのが Command パターンです。

ものになると、保存できます。あとで実行できます。 誰が出したかを問わなくなります。

04軽い作り方 ― enum で足りることが多い

いきなりクラスを作らないでください。 ゲームの操作は種類が少ないので、enum で足ります。 

// GameInput.h
enum EnAction {
    enAction_Left,
    enAction_Right,
    enAction_Up,
    enAction_Down,
    enAction_Shot,
    enAction_Bomb,
    enAction_Num,
};

/// <summary>1フレーム分の操作。</summary>
struct InputFrame {
    bool press[enAction_Num]   = {};    // 押されている
    bool trigger[enAction_Num] = {};    // 押された瞬間
};

/// <summary>操作を作るもの。プレイヤー・AI・リプレイが実装する。</summary>
class IInputSource {
public:
    virtual ~IInputSource() {}
    virtual void Poll(InputFrame& out) = 0;
};
// ゲームパッドから作る
class PadInputSource : public IInputSource {
public:
    void Poll(InputFrame& out) override
    {
        auto* pad = g_pad[0];
        out.press[enAction_Left]  = pad->IsPress(m_config[enAction_Left]);
        out.press[enAction_Right] = pad->IsPress(m_config[enAction_Right]);
        out.press[enAction_Shot]  = pad->IsPress(m_config[enAction_Shot]);
        out.trigger[enAction_Bomb] = pad->IsTrigger(m_config[enAction_Bomb]);
        ...
    }

    /// <summary>キーコンフィグ。</summary>
    void SetButton(EnAction action, EnButton button)
    {
        m_config[action] = button;
    }

private:
    EnButton m_config[enAction_Num] = {
        enButtonLeft, enButtonRight, enButtonUp, enButtonDown,
        enButtonA, enButtonB,
    };
};
// Player は「誰が操作しているか」を知らない
void Player::Update()
{
    InputFrame input;
    m_inputSource->Poll(input);

    const float dt = g_gameTime->GetFrameDeltaTime();
    if (input.press[enAction_Left])  { m_position.x -= SPEED * dt; }
    if (input.press[enAction_Right]) { m_position.x += SPEED * dt; }
    if (input.press[enAction_Shot])  { Shot(); }
    if (input.trigger[enAction_Bomb]) { Bomb(); }
}
この時点で、キーコンフィグができました SetButton() を呼ぶだけです。 Player.cpp は一切触りません。

05リプレイ

// 録る
class RecordingInputSource : public IInputSource {
public:
    explicit RecordingInputSource(std::unique_ptr<IInputSource> inner)
        : m_inner(std::move(inner)) {}

    void Poll(InputFrame& out) override
    {
        m_inner->Poll(out);       // 本物から取って
        m_log.push_back(out);     // 記録する
    }

    const std::vector<InputFrame>& GetLog() const { return m_log; }

private:
    std::unique_ptr<IInputSource> m_inner;
    std::vector<InputFrame>       m_log;
};

// 再生する
class ReplayInputSource : public IInputSource {
public:
    explicit ReplayInputSource(std::vector<InputFrame> log)
        : m_log(std::move(log)) {}

    void Poll(InputFrame& out) override
    {
        if (m_index < m_log.size()) {
            out = m_log[m_index++];
        } else {
            out = InputFrame();   // 記録が尽きたら、何もしない
        }
    }
private:
    std::vector<InputFrame> m_log;
    size_t m_index = 0;
};

これだけでリプレイができます。 Player は、渡されたものが本物か記録かを知りません。

ただし、それだけでは同じにならないことがあります リプレイがぴったり同じ動きになるには、 ゲームが「決定的」である必要があります。
ズレる原因対策
フレーム時間（dt）が毎回違う dt も記録する。または固定 dt で計算する
rand() を使っている 乱数の種を記録して、再生時に同じ種から始める
物理エンジンの誤差これは難しい
厳密なリプレイは、想像よりずっと難しい機能です。 まずは「だいたい同じ」で充分と割り切ってください。

06本来の Command パターン

教科書的な Command は、命令を1つずつクラスにするものです。 

class ICommand {
public:
    virtual ~ICommand() {}
    virtual void Execute(Player& player) = 0;
    virtual void Undo(Player& player) {}      // ★ 取り消せる
};

class MoveCommand : public ICommand {
public:
    explicit MoveCommand(const Vector3& delta) : m_delta(delta) {}
    void Execute(Player& player) override { player.MoveBy(m_delta); }
    void Undo(Player& player)    override { player.MoveBy(-m_delta); }
private:
    Vector3 m_delta;
};
形向いているもの
enum + InputFrame アクション・シューティング。毎フレーム入力を読む形
命令クラス（ICommand） ターン制。エディタ。Undo が要るもの
シューティングに ICommand は重すぎます 毎フレーム、移動命令のオブジェクトを new することになります。 4-06 でやった問題そのものです。
Undo が要らないなら、InputFrame のほうが素直です。

キーコンフィグを作る。F1 のデバッグパネルから割り当てを変えられるようにする。

解答例を見る（まず自分でやってから） 
// KeyConfigPanel.cpp
namespace {

const char* ACTION_NAMES[enAction_Num] = {
    "左", "右", "上", "下", "ショット", "ボム",
};

struct ButtonEntry { EnButton button; const char* name; };

const ButtonEntry BUTTONS[] = {
    { enButtonUp,     "Up"     }, { enButtonDown,  "Down"  },
    { enButtonLeft,   "Left"   }, { enButtonRight, "Right" },
    { enButtonA,      "A"      }, { enButtonB,     "B"     },
    { enButtonX,      "X"      }, { enButtonY,     "Y"     },
    { enButtonRB1,    "RB"     }, { enButtonLB1,   "LB"    },
};
const int BUTTON_NUM = sizeof(BUTTONS) / sizeof(BUTTONS[0]);

int FindButtonIndex(EnButton b)
{
    for (int i = 0; i < BUTTON_NUM; i++) {
        if (BUTTONS[i].button == b) { return i; }
    }
    return 0;
}

void DrawKeyConfig()
{
    PadInputSource* src = GetPadInputSource();
    if (src == nullptr) { return; }

    for (int a = 0; a < enAction_Num; a++) {
        int current = FindButtonIndex(src->GetButton((EnAction)a));

        // 同じ名前の Combo が並ばないよう ID を分ける
        ImGui::PushID(a);
        ImGui::TextUnformatted(U8(ACTION_NAMES[a]));
        ImGui::SameLine(120.0f);

        if (ImGui::BeginCombo("##btn", BUTTONS[current].name)) {
            for (int i = 0; i < BUTTON_NUM; i++) {
                bool selected = (i == current);
                if (ImGui::Selectable(BUTTONS[i].name, selected)) {
                    src->SetButton((EnAction)a, BUTTONS[i].button);
                }
            }
            ImGui::EndCombo();
        }
        ImGui::PopID();
    }

    ImGui::Separator();
    if (ImGui::Button(U8("既定に戻す"))) {
        src->ResetToDefault();
    }
    ImGui::SameLine();
    if (ImGui::Button(U8("保存"))) {
        src->Save("keyconfig.txt");
    }
}

}  // namespace

void RegisterKeyConfigPanel()
{
    nsDbg::DebugGui::RegisterPanel(U8("キーコンフィグ"), DrawKeyConfig);
}

保存・読み込み

エンジンの DebugSettings （k2EngineLow/dbg/DebugSettings.h）がそのまま使えます。 

void PadInputSource::Save(const char* path)
{
    nsDbg::DebugSettings s;
    for (int a = 0; a < enAction_Num; a++) {
        char key[32];
        sprintf_s(key, "action%d", a);
        s.SetInt(key, (int)m_config[a]);
    }
    s.Save(path);
}
PushID / PopID を忘れずに ImGui はラベルの文字列で部品を見分けます。 同じ "##btn" という名前の Combo を6個並べると、 全部が同じ部品だと思われて、1つ開くと全部開きます。

ループの中で同じ部品を並べるときは、 ImGui::PushID(i) で番号を付けるのが定石です。

演習3（録る）

リプレイを作る。ゲームオーバー後に、いまのプレイを再生できるようにする。

解答例を見る（まず自分でやってから）

仕組み

// GameScene.h
private:
    std::unique_ptr<IInputSource> m_inputSource;
    RecordingInputSource*         m_recorder = nullptr;   // 借りポインタ
    unsigned int                  m_randomSeed = 0;

// GameScene.cpp
bool GameScene::Start()
{
    // ★ 乱数の種を決めて、記録しておく
    m_randomSeed = (unsigned int)time(nullptr);
    srand(m_randomSeed);

    auto pad = std::make_unique<PadInputSource>();
    auto rec = std::make_unique<RecordingInputSource>(std::move(pad));
    m_recorder = rec.get();
    m_inputSource = std::move(rec);

    FindGO<Player>("player")->SetInputSource(m_inputSource.get());
    return true;
}

void GameScene::OnGameOver()
{
    m_replayLog = m_recorder->GetLog();      // 記録を取っておく
    NewGO<ResultScene>(enPriority_UI, "result");
}

void GameScene::StartReplay()
{
    srand(m_randomSeed);                     // ★ 同じ種から始め直す
    m_inputSource = std::make_unique<ReplayInputSource>(m_replayLog);
    ResetGame();
    FindGO<Player>("player")->SetInputSource(m_inputSource.get());
}

ズレる原因を1つずつ潰す

原因対策手間
乱数種を記録して、再生時に同じ種から 小。まずこれ
フレーム時間 dt も InputFrame に含めて記録する 小
フレーム落ち 再生中は記録した dt をそのまま使う小
物理エンジン実質むり—
 
// dt も記録する
struct InputFrame {
    bool  press[enAction_Num]   = {};
    bool  trigger[enAction_Num] = {};
    float deltaTime = 1.0f / 60.0f;      // ★ 追加
};
// 再生中は、記録された dt を使う
void Player::Update()
{
    InputFrame input;
    m_inputSource->Poll(input);

    const float dt = input.deltaTime;    // ★ g_gameTime を使わない
    ...
}
記録のサイズ InputFrame は1フレーム約16バイトです。 60FPS で5分遊ぶと 18000 フレーム、約 288KB。

まったく問題ない大きさです。 ファイルに保存して、あとから再生することもできます。
リプレイは、デバッグの道具にもなります 「特定の場面でだけ落ちる」バグを、 毎回同じ手順で再現できるようになります。

再現手順を人に説明する代わりに、リプレイファイルを渡せる というのは、チーム開発では非常に大きいです （4-15）。

08確認

  1. 入力と処理のあいだに一段はさむと、何ができるようになる？
  2. シューティングで ICommand を避けるのはなぜ？
  3. リプレイがズレる原因を2つ。
  4. ImGui でループ中に同じ部品を並べるとき、必要なものは？
答え
  1. キーコンフィグ、リプレイ、AIによるデモプレイ、 操作不能状態の一括制御。
  2. 毎フレーム命令オブジェクトを new することになるから。
  3. 乱数の種が違う。フレーム時間（dt）が毎回違う。
  4. ImGui::PushID() / PopID()。
