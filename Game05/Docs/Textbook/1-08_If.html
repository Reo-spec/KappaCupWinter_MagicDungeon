LV1 入門 ／ 1-08

if文 ― 条件で分ける

難易度 ／ 前提 1-07

01この章でできるようになること

  • 条件によって処理を分けられる
  • == と = の取り違えに気づける
  • 複数の条件を組み合わせられる

02基本の形

if (hp <= 0) {
    isAlive = false;
}

( ) の中が true なら、 { } の中が実行されます。 

if (hp <= 0) {
    isAlive = false;
}
else {
    isAlive = true;
}
if (hp > 70) {
    // 元気
}
else if (hp > 30) {
    // ふつう
}
else {
    // 瀕死
}

上から順に調べて、最初に当てはまったものだけが実行されます。 2つ目以降は調べられません。

03比べる記号

記号意味
==等しい（イコールが2つ）
!=等しくない
> <より大きい／より小さい
>= <=以上／以下
== を = と書くと、エラーになりません 
if (hp = 0) {       // ← 間違い。でもビルドは通る
    ...
}
これは「hp に 0 を代入して、その結果で判定する」 という意味になります。
結果：hp が 0 に書き換わり、 if の中身は実行されません。 しかもコンパイラは何も言いません。
「なぜか HP が 0 になる」バグの正体は、たいていこれです。

Visual Studio は、この形を書くと警告 C4706 を 出してくれることがあります。警告を無視しないでください。

04条件を組み合わせる

記号意味例
&&かつ（両方true） if (isAlive && hp > 0)
||または（どちらかtrue） if (isDead || hp <= 0)
!ではない（反転） if (!isAlive)
bool は == true を書かなくてよい 
if (isAlive == true)  { ... }    // 冗長
if (isAlive)          { ... }    // これでよい

if (isAlive == false) { ... }    // これは読みやすいので可
if (!isAlive)         { ... }    // これでもよい
k2Engine のコードでは == false と書かれていることが多いです。 ! は小さくて見落としやすいので、 あえて == false と書く流儀もあります。

05画面の端で止める

1-07 のコードに if を足します。 

void Game::Update()
{
    m_posX += m_speed;

    // 右端に来たら、向きを変える。
    if (m_posX > 900.0f) {
        m_posX = 900.0f;
        m_speed = -m_speed;      // 速さの符号を反転 → 逆向きに進む
    }
    // 左端でも同じ。
    if (m_posX < -900.0f) {
        m_posX = -900.0f;
        m_speed = -m_speed;
    }

    wchar_t text[256];
    swprintf_s(text, 256, L"posX=%.1f  speed=%.1f", m_posX, m_speed);
    m_fontRender.SetText(text);
}

数字が行ったり来たりするはずです。 これで「画面の中で往復する敵」が作れます。

06よくあるエラー

if のうしろにセミコロンを書いてしまう

if (hp <= 0);        // ← このセミコロンが致命的
{
    isAlive = false;   // ★ 条件に関係なく、必ず実行される
}

エラーになりません。 if (条件); で「条件が真なら、何もしない」という文が完成してしまい、 そのあとの { } はただのブロックとして必ず実行されます。

{ } を省略して間違える

if (hp <= 0)
    isAlive = false;
    OutputDebugStringA("死んだ\n");   // ★ これは条件の外！

{ } が無いと、if に付くのは次の1行だけです。 2行目は、条件に関係なく実行されます。

1行でも { } を書く 省略できますが、省略しないでください。 あとから1行足したときに、この事故が起きます。 実際のゲーム会社のコーディング規約でも、ほぼ必ず「省略禁止」になっています。

07演習

演習1（まねる）

上の「画面の端で往復する」コードを書いて動かす。

演習2（分ける）

HPの値によって、表示する文字を変える。
70より上なら「元気」、30より上なら「ふつう」、それ以下なら「瀕死」。HPはボタンで減らせるようにする。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    // Aボタンで10減らす
    if (g_pad[0]->IsTrigger(enButtonA)) {
        m_hp -= 10;
    }
    // 0より下にはしない
    if (m_hp < 0) {
        m_hp = 0;
    }

    const wchar_t* state;
    if (m_hp > 70) {
        state = L"元気";
    }
    else if (m_hp > 30) {
        state = L"ふつう";
    }
    else {
        state = L"瀕死";
    }

    wchar_t text[256];
    swprintf_s(text, 256, L"HP %d (%s)", m_hp, state);
    m_fontRender.SetText(text);
}

ポイント

  • else if を使えば、上から順に1つだけ選ばれます。 if を3つ並べると、全部調べられて遅くなりますし、 条件が重なったときに困ります
  • IsTrigger を使うこと。IsPress だと 一瞬でHPが0になります（2-10）
  • if (m_hp < 0) { m_hp = 0; } のような「はみ出し防止」は、 忘れると必ずバグになります

演習3（組み合わせる）

「生きていて、かつHPが30以下」のときだけ文字を赤くする。&& を使うこと。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    ...

    if (m_isAlive && m_hp <= 30) {
        m_fontRender.SetColor({ 1.0f, 0.2f, 0.2f, 1.0f });   // 赤
    }
    else {
        m_fontRender.SetColor({ 1.0f, 1.0f, 1.0f, 1.0f });   // 白
    }
}
else を書き忘れると戻りません if だけ書いて else を書かないと、 一度赤くなったら二度と白に戻りません。
「状態が変わったら元に戻す」のを書き忘れるのは、非常によくある間違いです。 「赤くする条件」を書いたら、必ず「白に戻す場合」も考えてください。

なお、点滅させたいなら && にもう1つ条件を足せます。 

if (m_isAlive && m_hp <= 30 && (m_frameCount % 30 < 15)) {
    // 30フレーム周期で、前半だけ赤くする → 点滅
}

08確認

  1. if (hp = 0) と書くと何が起きる？ エラーは出る？
  2. if のあとに { } を必ず書くのはなぜ？
  3. && と || の違いは？
答え
  1. hp に 0 が代入され、if の中身は実行されない。 エラーは出ない（警告は出ることがある）。
  2. 省略すると次の1行しか if に付かず、 あとから行を足したときに事故になるから。
  3. && は「両方true」、|| は「どちらかtrue」。
