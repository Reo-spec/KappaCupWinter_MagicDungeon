【制作課題】シューティングを3D化する

難易度 ／ 前提 2-24 , 3-13

行き詰まったら、完成形を見てください Sample/Goal_LV3 に、 この章に到達した状態のプロジェクトが入っています。
先に見てしまっても構いません。 読んで理解してから、自分のコードに戻ってください。
読む順番は Goal_LV3/readme.txt に書いてあります。

01やること

2-24 で完成させた2Dシューティングを、 3Dに作り変えます。

ゼロから作り直すのではありません。 描画だけを差し替えるのが、この課題の狙いです。

02なぜこれをやるのか

LV2で作ったゲームには、 「遊べる部分」と「見た目の部分」が混ざって書かれている はずです。

3D化しようとすると、その混ざり具合がはっきり見えます。

混ざっていないと混ざっていると
SpriteRender を ModelRender に 替えるだけで済む あちこち書き換えるはめになる
当たり判定はそのまま動く 当たり判定の中に描画の都合が入り込んでいる
これは LV4 の予告でもあります 「ゲームのルール」と「見せ方」を分けて書く — LV4 の設計の話は、ここで感じた痛みが出発点になります。
痛みを感じておくことに意味があります。 今きれいに書けなくても構いません。

03進め方

手順やること確認
1カメラを置く（3-10） まだ何も見えなくてよい
2地面のモデルを1枚出す ここで初めて画面に何か出る
3プレイヤーを ModelRender に差し替える 動かせるか
4敵、弾を差し替える 当たり判定が壊れていないか
5ライトと影を調整（3-11、 3-12） F1 で探して、コードに写す
6UI はそのまま 2D で残す ここは触らない
一気にやらないでください 1つ差し替えるたびにビルドして動かす。 全部書き換えてからビルドすると、 どこが原因で動かないのか、まず分かりません。

04座標の考え方を決める

2Dでは X と Y で動かしていました。 3Dではどの平面を使うか、最初に決めてください。

やり方2Dの X, Y を…向いているもの
見下ろし型 X, Z に対応させる（Y は高さ） おすすめ。縦シューがそのまま作れる
横スクロール型 X, Y のまま（Z は使わない） 2.5D。差し替えがいちばん楽

見下ろし型なら、カメラを真上より少し後ろに置きます。 

g_camera3D->SetPosition({ 0.0f, 900.0f, -400.0f });
g_camera3D->SetTarget  ({ 0.0f,   0.0f,    0.0f });

完全な真上（{0, 900, 0}）にすると、 Up の向きが定まらず絵がおかしくなることがあります。 少しずらしてください。

05達成の目安

全部できなくても構いません。 上から順に、できたものにチェックを入れてください。

  • 3Dモデルのプレイヤーを操作できる
  • 敵が出て、弾が当たって、消える
  • カメラがプレイヤーを追いかける
  • 地面に影が落ちている
  • UI（スコア・HP）が2Dのまま出ている
  • ライティングを調整して、雰囲気を作った
  • プレイヤーが進行方向を向く
  • アニメーションが状態に合っている
  • 被弾したとき、画面が赤くフラッシュする （3-08）
  • 使った素材の出どころを Assets/CREDITS.txt に書いた （素材の用意のしかた）
モデルとアニメーションは自分で用意してください 本文に出てくる player.tkm や walk.tka は ファイル名の例で、実物はありません。 まずは Sample/Sample_09 以降のモデルをコピーして動かすのが早道です。 → 素材の用意のしかた

07演習

演習1（差し替える）

プレイヤーだけを3Dモデルに差し替えて、動かせるようにする。ほかは2Dのままでよい。

解答例を見る（まず自分でやってから）

差し替えは3か所だけです。 

// Player.h
- SpriteRender m_spriteRender;
+ ModelRender  m_modelRender;

// Player.cpp  Start()
- m_spriteRender.Init("Assets/sprite/player.dds", 64.0f, 64.0f);
+ m_modelRender.Init("Assets/modelData/player.tkm");

// Player.cpp  Update()
- m_spriteRender.SetPosition(m_position);
- m_spriteRender.Update();
+ m_modelRender.SetPosition(m_position);
+ m_modelRender.Update();

// Player.cpp  Render()
- m_spriteRender.Draw(rc);
+ m_modelRender.Draw(rc);

ここで気づいてほしいこと：移動のコードは1行も変えていません。 m_position を動かす処理と、それを描く処理が もともと分かれていたからです。

もし移動のコードにも手を入れる必要があったなら、 そこが「混ざっていた」場所です。覚えておいてください。

まずカメラを置いてから カメラが無いと差し替えても何も見えず、 「モデルの読み込みに失敗したのか、カメラが違う方向なのか」 が分からなくなります。
順番は、カメラ → 地面 → プレイヤーです。

演習2（向かせる）

プレイヤーが進行方向を向くようにする。

解答例を見る（まず自分でやってから） 
void Player::Update()
{
    Move();                                   // m_moveSpeed が決まる

    // 動いているときだけ向きを更新する
    if (m_moveSpeed.LengthSq() > 0.001f) {
        // Z+ を正面とするモデルの場合
        m_targetAngle = atan2f(m_moveSpeed.x, m_moveSpeed.z);
    }

    m_rotation.SetRotation(Vector3::AxisY, m_targetAngle);
    m_modelRender.SetRotation(m_rotation);
    m_modelRender.SetPosition(m_position);
    m_modelRender.Update();
}

atan2f の引数の順番に注意

モデルの正面書き方
+Z 向き（よくある）atan2f(x, z)
+X 向きatan2f(-z, x)

どちらか分からなければ、両方試してください。 90度ずれていたら、もう一方です。

なめらかに向かせる（おすすめ）

// いきなり向くと硬いので、少しずつ回す
float diff = m_targetAngle - m_currentAngle;

// -π 〜 π の範囲に収める（でないと遠回りする）
while (diff >  Math::PI) { diff -= Math::PI2; }
while (diff < -Math::PI) { diff += Math::PI2; }

m_currentAngle += diff * 0.2f;
m_rotation.SetRotation(Vector3::AxisY, m_currentAngle);
角度を丸める処理を忘れると、反対回りします 350度から 10度へ向かうとき、そのまま差を取ると -340度。 ぐるっと逆向きに一周します。

「-180度〜180度に収める」処理は必ず入れてください。 角度を扱うときの定番のバグです。

解答例を見る（まず自分でやってから）
