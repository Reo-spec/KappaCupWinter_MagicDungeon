02ゲームはずっと同じことを繰り返している

アニメが1秒間に何十枚もの絵をパラパラめくって動いて見せるように、 ゲームも1秒間に60回、画面を描き直しています。 この1回分をフレームと呼びます。

つまりゲームのプログラムは、こういう形をしています。 

初期化する

ずっと繰り返す {
    入力を調べる
    ものを動かす      ← Update()
    画面に描く        ← Render()
}

この「ずっと繰り返す」部分を ゲームループ と呼びます。 k2Engine では、それが Game/main.cpp に書いてあります。

03main.cpp を読む

int WINAPI wWinMain(HINSTANCE hInstance, ...)
{
    //ゲームの初期化。
    InitGame(hInstance, hPrevInstance, lpCmdLine, nCmdShow, TEXT("Game"));

    //////////////////////////////////////
    // ここから初期化を行うコードを記述する。
    //////////////////////////////////////

    //Gameクラスのオブジェクトを作成。
    NewGO<Game>(0, "game");

    //////////////////////////////////////
    // 初期化を行うコードを書くのはここまで！！！
    //////////////////////////////////////

    // ここからゲームループ。
    while (DispatchWindowMessage())
    {
        K2Engine::GetInstance()->Execute();     // ← 1フレーム分の処理
    }

    K2Engine::DeleteInstance();
    return 0;
}

読むべきところは2つだけです。

コード意味
NewGO<Game>(0, "game") 最初のゲームオブジェクトを1個だけ作る。ここがゲームの入口
while (DispatchWindowMessage()) ウィンドウが閉じられるまでずっと回る。1周＝1フレーム
main.cpp はほとんど触りません ゲームの中身は、すべて Game クラスと、 そこから NewGO で作るオブジェクトの中に書きます。 main.cpp に処理を足していくのは間違いです。

041フレームの中で何が起きているか

053つの関数の役割

関数いつ呼ばれる何を書く
bool Start() 最初の1回だけ 画像の読み込み、初期位置の設定など
void Update() 毎フレーム 入力を調べる、動かす、当たり判定
void Render(RenderContext& rc) 毎フレーム、Update のあと 描画。ここで計算をしてはいけません
Start() が bool を返すのはなぜ？ true を返すと「初期化が終わった」という意味になり、 次のフレームから Update() が呼ばれ始めます。 false を返すと、次のフレームでもう一度 Start() が呼ばれます。 読み込みに何フレームもかかる場合に使いますが、いまは常に true で構いません。

06動かして確かめる

Game.cpp に出力を入れて、呼ばれる回数を見てみましょう。 

bool Game::Start()
{
    OutputDebugStringA("Start が呼ばれた\n");
    return true;
}

void Game::Update()
{
    m_count++;
    char text[256];
    sprintf_s(text, "Update %d回目\n", m_count);
    OutputDebugStringA(text);
}
  • Start は1回しか出ない
  • Update は1秒間におよそ60回出る
  • ウィンドウを閉じるまで止まらない

07演習

演習1（まねる）

上のコードを入れて、出力ウィンドウで回数を確認する。

演習2（数える）

Update が60回呼ばれたら「1秒たった」と表示するコードを書く。 ストップウォッチと比べて、だいたい合っているか確かめる。

解答例を見る（まず自分でやってから） 
// Game.h
private:
    int m_count = 0;

// Game.cpp
void Game::Update()
{
    m_count++;
    if (m_count % 60 == 0) {
        char text[256];
        sprintf_s(text, "%d秒たった\n", m_count / 60);
        OutputDebugStringA(text);
    }
}

ストップウォッチと比べると、だいたい合っているはずです。 ただしぴったりではありません。 フレームは正確に60回とは限らないからです。 正確に時間を測りたいときは、次の章のデルタタイムを使います。

演習3（考える）

Render() の中に重い計算を書くと、なぜよくないのでしょうか。 「描画と計算を分ける」と何が良いのかを、自分の言葉で説明してみる。

解答例を見る（まず自分でやってから）

Render() は「描く」ための関数です。ここに計算を書くと、次の問題が起きます。

  • どこで何をしているのか分からなくなる。 バグを探すとき、計算は Update、描画は Render と 決まっていれば、見る場所がすぐ決まります
  • 「絵を出さない」ことができなくなる。 画面外のものは描画を省きたいのに、そこに計算があると省けません
  • 描画だけ別のスレッドに回す、といった改善ができなくなる （LV5 でやります）

これを「関心の分離」と呼びます。 「計算する係」と「描く係」を分けておくと、あとからどちらも直しやすくなります。 LV4 で本格的に扱う考え方です。

08確認

  1. 1フレームとは何か？ 1秒に何回くらい？
  2. Start() と Update() の違いは？
  3. ゲームの処理は main.cpp に書くべき？
答え
  1. 画面を1回描き直す単位。1秒におよそ60回。
  2. Start() は最初の1回だけ、Update() は毎フレーム。
  3. 書かない。Game クラスと、そこから NewGO したオブジェクトに書く。
