LV5 最適化 ／ 5-06

AoS と SoA — データの並べ方

難易度 ／ 前提 5-05

01この章でできるようになること

  • データの持ち方を変えて、数倍速くできる
  • AoS と SoA の使い分けが分かる
  • LV4 の設計と、LV5 の速さが対立することを実感する

022つの持ち方

// AoS（Array of Structures）― 構造体の配列
struct Bullet {
    Vector3 position;
    Vector3 velocity;
    float   life;
    bool    isActive;
};
std::vector<Bullet> bullets;        // ★ ふつうの書き方


// SoA（Structure of Arrays）― 配列の構造体
struct BulletArray {
    std::vector<Vector3> positions;
    std::vector<Vector3> velocities;
    std::vector<float>   lives;
    std::vector<bool>    actives;
};
BulletArray bullets;                // ★ メンバごとに別の配列

03どちらが速いかは、処理による

処理速いほう理由
全員の位置だけ更新 SoA 位置だけが連続。無駄なく運べる
当たり判定（位置と半径だけ） SoA同上
1個の弾の全情報を見る AoS 1か所にまとまっている
弾を1個消すAoS SoA は全部の配列を触る必要がある
コードの読みやすさAoS SoA は明らかに読みにくい
LV4 と LV5 が、ここで正面から対立します LV4 では「Bullet クラスにまとめなさい」と教えました。 カプセル化です。
LV5 は「ばらしなさい」と言っています。

どちらも正しい。場面が違うだけです。
SoA にするのは、「測って、そこが遅いと分かったとき」だけです。

04現実的な折衷案

全部を SoA にする必要はありません。 ホットな部分だけ切り出すのが現実的です。 

// 当たり判定に使うものだけ、別に持つ
class BulletPool {
public:
    void UpdateAll(float dt)
    {
        // ★ ここは SoA。位置と速度だけ
        for (size_t i = 0; i < m_count; i++) {
            m_positions[i] += m_velocities[i] * dt;
        }
    }

    int FindHit(const Vector3& center, float radius) const
    {
        // ★ ここも SoA。位置だけを読む
        const float r2 = radius * radius;
        for (size_t i = 0; i < m_count; i++) {
            Vector3 d = m_positions[i] - center;
            if (d.LengthSq() < r2) { return (int)i; }
        }
        return -1;
    }

private:
    // 毎フレーム全部なめるもの → SoA
    std::vector<Vector3> m_positions;
    std::vector<Vector3> m_velocities;

    // たまにしか使わないもの → まとめて AoS
    struct BulletInfo {
        int   damage;
        int   ownerId;
        float lifeTime;
        EnBulletVisual visual;
    };
    std::vector<BulletInfo> m_infos;

    size_t m_count = 0;
};
これが、実際のゲームエンジンでよくある形です 「毎フレーム全部なめるもの」だけ SoA、 残りは AoS のまま。
読みやすさをあまり犠牲にせず、効果の大部分を得られます。

05削除をどうするか

SoA でいちばん面倒なのは、途中の1個を消すことです。 

// ★ 遅い：後ろを全部ずらす
m_positions.erase(m_positions.begin() + i);
m_velocities.erase(m_velocities.begin() + i);
m_infos.erase(m_infos.begin() + i);
// ○ 速い：最後の要素を持ってきて、size を減らす
void BulletPool::Remove(size_t i)
{
    const size_t last = m_count - 1;
    if (i != last) {
        m_positions[i]  = m_positions[last];
        m_velocities[i] = m_velocities[last];
        m_infos[i]      = m_infos[last];
    }
    m_count--;
}

「swap and pop」と呼ばれるやり方です。O(1) です。

順番が変わります 弾の並び順が入れ替わるので、 「何番目の弾」という参照は無効になります。
弾の描画順が変わる、といった影響もあります。 順番が意味を持つものには使えません。
ループの中で消すときは、要注意 
// ★ バグ：消した位置に、最後の要素が来る。それを飛ばしてしまう
for (size_t i = 0; i < m_count; i++) {
    if (ShouldRemove(i)) { Remove(i); }
}

// ○ 消したときは、i を進めない
for (size_t i = 0; i < m_count; ) {
    if (ShouldRemove(i)) { Remove(i); }
    else                 { i++; }
}

06測ってから決める

SoA にする前に、必ず AoS で測ってください。

条件SoA にする価値
要素が数千個以上ある
毎フレーム全部なめるある
使うメンバが、全体の一部ある
要素が数十個ない。全部L1に乗る
たまにしか触らないない
敵50体を SoA にしても、まず速くなりません 50体 × 数百バイト ＝ 数十KB。L1〜L2 に収まります。
もともとキャッシュに乗っているものを並べ替えても、意味はありません。

07演習

演習1（測る）

AoS と SoA を両方書いて、「10万個の位置を更新する」時間を比べる。

解答例を見る（まず自分でやってから） 
#include <vector>
#include "Bench.h"

namespace {

const int N = 100000;

struct BulletAoS {
    Vector3 position;
    Vector3 velocity;
    float   life;
    int     damage;
    int     ownerId;
    bool    isActive;
};

struct BulletSoA {
    std::vector<Vector3> positions;
    std::vector<Vector3> velocities;
    std::vector<float>   lives;
    std::vector<int>     damages;
    std::vector<int>     ownerIds;
    std::vector<char>    actives;     // vector<bool> は特殊なので char
};

}  // namespace

void CompareAosSoa()
{
    const float dt = 1.0f / 60.0f;

    //----- AoS -----
    std::vector<BulletAoS> aos(N);
    for (int i = 0; i < N; i++) {
        aos[i].position = { (float)i, 0.0f, 0.0f };
        aos[i].velocity = { 1.0f, 2.0f, 3.0f };
        aos[i].isActive = true;
    }

    //----- SoA -----
    BulletSoA soa;
    soa.positions.resize(N);
    soa.velocities.resize(N);
    soa.lives.resize(N);
    soa.damages.resize(N);
    soa.ownerIds.resize(N);
    soa.actives.resize(N, 1);
    for (int i = 0; i < N; i++) {
        soa.positions[i]  = { (float)i, 0.0f, 0.0f };
        soa.velocities[i] = { 1.0f, 2.0f, 3.0f };
    }

    // 100回ずつ回して測る
    {
        BENCH("AoS  位置更新 x100");
        for (int k = 0; k < 100; k++) {
            for (int i = 0; i < N; i++) {
                aos[i].position += aos[i].velocity * dt;
            }
        }
    }

    {
        BENCH("SoA  位置更新 x100");
        for (int k = 0; k < 100; k++) {
            for (int i = 0; i < N; i++) {
                soa.positions[i] += soa.velocities[i] * dt;
            }
        }
    }

    // 消されないように結果を使う
    char buf[128];
    sprintf_s(buf, "aos[0].x=%f soa[0].x=%f\n",
              aos[0].position.x, soa.positions[0].x);
    OutputDebugStringA(buf);
}

典型的な結果（Release）

AoS  位置更新 x100           :   52.310 ms
SoA  位置更新 x100           :   28.774 ms     ← 1.8倍速い

なぜ 1.8倍か

BulletAoS の sizeof = 40 バイト
  うち、この処理で使うのは position(12) + velocity(24までの差分) = 24バイト
  → 40バイト運んで、24バイトしか使わない（60%）

SoA
  positions(12) と velocities(12) を別々に連続で読む
  → 運んだぶんを 100% 使う
1.8倍。「10倍」ではありません AoS でも、vector なので連続して並んでいます。 キャッシュには乗るのです。 無駄が 40% あるぶんだけ遅い、という差です。

10倍の差が出るのは、ポインタの配列 （vector<Bullet*>）の場合です。 そちらも試してみてください。

おまけ ― ポインタの配列も測る

std::vector<BulletAoS*> ptrs;
for (int i = 0; i < N; i++) {
    ptrs.push_back(new BulletAoS(aos[i]));   // ★ バラバラに確保される
}

{
    BENCH("ポインタ配列 x100");
    for (int k = 0; k < 100; k++) {
        for (int i = 0; i < N; i++) {
            ptrs[i]->position += ptrs[i]->velocity * dt;
        }
    }
}
AoS  位置更新 x100           :   52.310 ms
SoA  位置更新 x100           :   28.774 ms
ポインタ配列 x100            :  198.442 ms     ← SoA の 6.9倍遅い
これが、あなたのゲームで実際に起きていることです NewGO で作った弾を std::vector<Bullet*> や std::list で持つのは、 このいちばん遅い形です。

ただし、弾が200発なら差は測れません。 問題になるのは、数千個からです。

演習2（書き直す）

自分の弾の更新と当たり判定を SoA にする。削除は swap and pop で。ゲームが前と同じように動くか確認する。

解答例を見る（まず自分でやってから）

設計方針

  • 毎フレーム全部なめるもの（位置・速度）→ SoA
  • 当たったときだけ使うもの（ダメージ・所有者）→ AoS でまとめる
  • IGameObject はプール1個だけにする（弾ごとには作らない）
// BulletSystem.h
#pragma once

class BulletSystem : public IGameObject {
public:
    bool Start()  override;
    void Update() override;
    void Render(RenderContext& rc) override;

    /// <summary>弾を1発撃つ。</summary>
    bool Fire(const Vector3& pos, const Vector3& vel, int damage);

    /// <summary>円と当たっている弾を探す。</summary>
    /// <returns>見つかった添字。無ければ -1</returns>
    int  FindHit(const Vector3& center, float radius) const;

    int  GetDamage(int index) const { return m_infos[index].damage; }
    void Remove(int index);

    int  GetCount() const { return m_count; }

private:
    static const int MAX = 4096;

    // ---- 毎フレーム全部なめる（SoA）----
    std::vector<Vector3> m_positions;
    std::vector<Vector3> m_velocities;

    // ---- 当たったときだけ使う（AoS）----
    struct Info {
        int   damage  = 0;
        int   ownerId = 0;
        float life    = 0.0f;
    };
    std::vector<Info> m_infos;

    int m_count = 0;

    // 描画はインスタンシングで1回（5-08）
    ModelRender m_modelRender;
};
// BulletSystem.cpp
namespace {
    const float BULLET_RADIUS = 8.0f;
    const float MAX_LIFE      = 5.0f;
}

bool BulletSystem::Start()
{
    m_positions.resize(MAX);
    m_velocities.resize(MAX);
    m_infos.resize(MAX);

    m_modelRender.Init("Assets/modelData/bullet.tkm",
                       nullptr, 0, enModelUpAxisZ, true, MAX);
    return true;
}

bool BulletSystem::Fire(const Vector3& pos, const Vector3& vel, int damage)
{
    if (m_count >= MAX) {
        return false;
    }
    m_positions[m_count]  = pos;
    m_velocities[m_count] = vel;
    m_infos[m_count]      = { damage, 0, 0.0f };
    m_count++;
    return true;
}

void BulletSystem::Remove(int i)
{
    const int last = m_count - 1;
    if (i != last) {
        m_positions[i]  = m_positions[last];
        m_velocities[i] = m_velocities[last];
        m_infos[i]      = m_infos[last];
    }
    m_count--;
}

void BulletSystem::Update()
{
    K2_PROFILE_SCOPE("BulletSystem");
    const float dt = g_gameTime->GetFrameDeltaTime();

    // ★ ここが SoA の効くところ。位置と速度しか触らない
    for (int i = 0; i < m_count; i++) {
        m_positions[i] += m_velocities[i] * dt;
    }

    // 寿命と画面外の判定（消すので、後ろから見る）
    for (int i = m_count - 1; i >= 0; i--) {
        m_infos[i].life += dt;
        if (m_infos[i].life > MAX_LIFE || IsOutOfScreen(m_positions[i])) {
            Remove(i);
        }
    }
}

int BulletSystem::FindHit(const Vector3& center, float radius) const
{
    const float r2 = (radius + BULLET_RADIUS) * (radius + BULLET_RADIUS);

    // ★ 位置だけを連続で読む
    for (int i = 0; i < m_count; i++) {
        Vector3 d = m_positions[i] - center;
        if (d.LengthSq() < r2) {
            return i;
        }
    }
    return -1;
}
消すループを「後ろから」にすると、swap and pop の罠を避けられます 後ろから見ていれば、 最後の要素を持ってきても、すでに見終わった位置です。 

for (int i = m_count - 1; i >= 0; i--) {
    if (...) { Remove(i); }
}
前から見るときの「i を進めない」より、こちらのほうが素直です。
弾が IGameObject ではなくなります これは大きな変更です。
  • FindGO<Bullet> が使えなくなる
  • 弾ごとの Update() / Render() が呼ばれない
  • 優先度による描画順の制御ができなくなる

そのぶん、4096発でも更新が 0.1ms 程度で終わります。

「どちらを取るか」が、この章の問いです。 弾が200発で足りるゲームなら、この変更は割に合いません。

確認のしかた

  1. 書き直す前に、K2_PROFILE_SCOPE で数字を記録
  2. 書き直したあと、同じ場面で測る
  3. 遊んでみて、弾の挙動が変わっていないか確認
  4. 4-14 のテストパネルがあれば、それも走らせる

演習3（判断する）

自分のゲームで、SoA にする価値があるものと、ないものを分類する。理由も書く。

解答例を見る（まず自分でやってから）

分類の例

対象個数SoA？理由
弾〜2000する 毎フレーム全部なめる。位置しか使わない
パーティクル〜10000する いちばん数が多い。処理も単純
敵〜50しない 全部L1に乗る。個体ごとの処理が複雑
プレイヤー1しない—
ボス1しない—
UI要素〜20しない—
アイテム〜30しない—
背景のオブジェクト〜500たぶんしない 動かないので、そもそも更新しない

判断の手順

  1. 個数は数千以上か — 違えばここで終わり
  2. 毎フレーム全部なめているか
  3. 使うメンバは、全体の一部か
  4. 測って、実際にボトルネックか

4つ全部に「はい」でなければ、AoS のままにしてください。

この判断ができることが、この章のゴールです SoA を書けることではありません。

「ここは SoA にする価値がない」と言えるほうが、 実務では価値があります。

面接でも、「弾とパーティクルだけ SoA にして、 敵はそのままにしました。敵は50体しかいないので、 測っても差が出なかったからです」 と言えれば、非常に強いです。
LV4 とのバランス 4-16 で整理したコードを、 ここで崩すことになります。

崩してよいのは、測って効果が確認できた場所だけです。 そして崩した理由をコメントに残してください。 
// 【SoA化】弾は最大4096発なので、位置と速度だけ別配列にしている。
// AoS だと更新に 1.8ms かかっていたが、0.6ms になった。

08確認

  1. SoA が速くなるのは、どんな処理？
  2. AoS のほうがよいのは、どんなとき？
  3. swap and pop の欠点は？
  4. 要素が50個しかないとき、SoA にする価値は？
答え
  1. 大量の要素の、一部のメンバだけを毎フレームなめる処理。
  2. 1個の全情報を見るとき、削除が多いとき、 読みやすさを優先したいとき。
  3. 順番が変わる。「何番目」という参照が無効になる。
  4. ない。もともとキャッシュに乗っているので変わらない。
