02同じゲームを3回作り直す

この教材には背骨があります。 LV2で作ったシューティングを、そのままLV3・LV4・LV5で作り直していきます。 毎回ゼロから作るより、自分が書いて痛い目を見たコードを直すほうが、はるかに身につきます。

だから、自分のコードを必ず残してください LV1の最初（1-03）で自分のGitリポジトリを作り、毎章コミットしてください。 ここを飛ばすと、LV3以降の制作課題が成立しません。

LV5

最適化 — 測って速くする

中心の問い： なぜ遅い？どう測る？

ゴール：「速くなった気がする」ではなく、数字で示せるようになる。

このレベルの課題はすべて 「計測 → 仮説 → 修正 → 再計測」の形式で提出します。 たとえば「3.2ms → 0.8ms。原因はキャッシュミス。Profilerパネルで確認」のように。 「速くなりました」だけは不合格です。

5-10 は必ず「壊す」ところから

2つのスレッドで同じ変数を100万回足しても100万になりません。 しかも10回に1回しか再現せず、デバッガで止めると再現しなくなります。 この気持ち悪さを体験してから、正しい書き方に進んでください。

5-09 で「LV2の設計は間違いだったのか？」と思うはずです。 違います。要件によって選ぶものです。 小規模なら継承ベースのほうが速く作れます。大量のオブジェクトを捌くならデータ指向が勝ちます。 この判断ができることが、LV5の到達点です。
