LV1 入門 ／ 1-03

Gitで自分のリポジトリを作る

難易度 ／ 前提 1-01

01この章でできるようになること

  • 自分のコードを Git で保存できる
  • コミットとプッシュができる

02なぜ最初にこれをやるのか

理由は3つあります。

  1. 壊したときに戻せる。 初心者のうちは、直そうとしてもっと壊すことがよくあります。 Gitがあれば「昨日の状態」に一瞬で戻せます
  2. この教材の後半で使う。 LV2で作ったゲームを、LV3で3D化し、LV4で設計し直します。 コードが残っていないと、そこに進めません
  3. 就職活動で見せられる。 「1年でここまで書けるようになった」という履歴そのものが、 作品と同じくらい強い材料になります
ここを飛ばさないでください あとから「やっぱりGitを入れよう」としても、 それまでの履歴は二度と作れません。 10分で終わります。いまやってください。

03手順

  1. Git をインストールする（Git for Windows）
  2. GitHub のアカウントを作る（無料）
  3. リポジトリを作る。 かならず Private（非公開）にしてください。 学校の課題や、配布されたエンジンのコードが含まれるためです
  4. Visual Studio の Git メニューから、 またはコマンドで、自分のプロジェクトをそこに紐づける

コマンドでやる場合は、これだけです。

cd C:\dev\k2Engine
git init
git add .
git commit -m "最初のコミット"
git remote add origin https://github.com/あなたの名前/リポジトリ名.git
git push -u origin main

04.gitignore を必ず設定する

ビルドでできたファイルは、Gitに入れてはいけません。 毎回何百MBも変わるので、リポジトリが使い物にならなくなります。

k2Engine のリポジトリには、すでに .gitignore が入っています。 自分で新しく作る場合は、最低限これを入れてください。 

# ビルドの中間ファイル
x64/
Debug/
Release/
*.obj
*.pdb
*.ilk
*.exe

# Visual Studio の作業ファイル
.vs/
*.user

# デバッグGUIのウィンドウ配置
imgui.ini
入れてしまったあとで消すのは大変です 最初のコミットの前に .gitignore を置いてください。 一度コミットしてしまうと、あとから .gitignore に書いても消えません。

05いつコミットするか

この教材では「1章終わるごとに1コミット」を目安にしてください。 

git add .
git commit -m "1-07 完了：キャラクターが動くようになった"
git push

コミットメッセージは「何をしたか」を書きます。 日本語で構いません。

だめな例よい例
update自機の移動を実装
あああ弾が画面外で消えないバグを修正
いろいろ2-14完了：弾を撃てるようにした

半年後の自分は、他人です。 「あああ」と書いたコミットは、何も教えてくれません。

06困ったときに使うもの

やりたいことコマンド
いま何が変わっているか見るgit status
どこを変えたか見るgit diff
これまでの履歴を見るgit log --oneline
1つのファイルを、直前のコミットの状態に戻す git restore ファイル名
「戻す」系のコマンドは慎重に git restore や git reset --hard は、 コミットしていない変更を消してしまいます。 今日1日の作業が消えることもあります。
ネットで調べたコマンドを、意味を分からずに打たないでください。 まずは git status で、いまの状態を確認する癖をつけましょう。

07演習

演習1（まねる）

GitHubにPrivateのリポジトリを作り、最初のコミットをプッシュする。

演習2（確かめる）

GitHubのページを開いて、x64 フォルダが入っていないことを確認する。入っていたら .gitignore が効いていません。

解答例を見る（まず自分でやってから）

入ってしまっていたら、こうします。 

# .gitignore を先に直してから
git rm -r --cached x64
git commit -m ".gitignore を修正してビルド成果物を除外"
git push

--cached を付けると、Gitの管理からだけ外れて、 ローカルのファイルは消えません。 これを付け忘れると、本当にファイルが消えます。

リポジトリの大きさも見てみてください。 ソースコードだけなら数MBです。 数百MBになっていたら、何か余計なものが入っています。

演習3（戻してみる）

Game.cpp をわざと壊して（適当な文字を書いて）保存し、git restore Game/Game.cpp で元に戻す。

解答例を見る（まず自分でやってから） 
# いま何が変わっているか見る
git status

# どこが変わったか見る
git diff Game/Game.cpp

# 元に戻す
git restore Game/Game.cpp

この「戻せる」という感覚が、Gitを使ういちばんの理由です。

これができると、思い切って試せるようになります。 「壊したらどうしよう」と思わずに、いろいろ書き換えてみてください。 戻せるのですから。

Visual Studio からでもできます 「Git 変更」ウィンドウで、ファイルを右クリック → 「変更の取り消し」でも同じことができます。 コマンドが苦手なら、そちらでも構いません。

08確認

  1. リポジトリを Private にする理由は？
  2. .gitignore に何を書く？ なぜ？
  3. コミットはどのくらいの頻度で？
答え
  1. 学校の課題や、配布されたエンジンのコードが含まれるため。
  2. x64/ などのビルド成果物。毎回変わるうえ巨大で、 Gitで管理する意味がないから。
  3. この教材では1章に1回を目安に。多すぎて困ることはない。
