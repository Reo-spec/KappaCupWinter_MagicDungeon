LV1 入門 ／ 1-17

const と参照渡し

難易度 ／ 前提 1-14

01この章でできるようになること

  • 値渡しのコストが分かる
  • const Vector3& という書き方の意味が分かる
  • 関数の引数を、正しい形で書ける

02値渡しはコピーされる

void Move(Vector3 pos)      // ← コピーが作られる
{
    ...
}

Vector3 は float が3つで12バイト。 これくらいなら大した問題ではありません。 でも、大きなクラスだとどうでしょうか。 

void Draw(RenderContext rc)      // ★ 巨大なオブジェクトが丸ごとコピーされる

毎フレーム、大量のコピーが発生します。 しかもコピーした中身を書き換えても、元には反映されません （1-14）。

03参照渡しならコピーされない

void Draw(RenderContext& rc)     // ★ コピーされない

& を付けるだけです。 これが Render(RenderContext& rc) の & の理由です。

ただし、参照渡しには1つ問題があります。 関数の中で、元の値を勝手に書き換えられてしまいます。 

void PrintPosition(Vector3& pos)
{
    pos.x = 0.0f;      // ★ 呼んだ側の変数が変わってしまう
    ...
}

04const ― 「書き換えません」という約束

void PrintPosition(const Vector3& pos)
{
    pos.x = 0.0f;      // ★ コンパイルエラーになる
}

const を付けると、書き換えようとした瞬間にエラーになります。

const 型& が基本形です 「コピーはしない。でも書き換えもしない」 — これがいちばんよく使う形です。
エンジンのコードを見ると、const Vector3& が 大量に出てくるのが分かります。

05使い分けの表

書き方コピー書き換えいつ使う
int hpするしない 小さい型（int, float, bool）
const Vector3& posしないしない 大きい型を、読むだけ（基本形）
Vector3& posしないする 結果を書き込んで返したいとき
Vector3* posしないする 「渡さない」こともあるとき
小さい型に const& を付けるのは逆効果 const int& hp は、かえって遅くなることがあります。 int や float は、そのまま渡してください。 目安は「ポインタより大きいものは参照で」です。

06関数のうしろの const

class Enemy {
public:
    int GetHp() const { return m_hp; }      // ★ うしろに const
private:
    int m_hp = 100;
};

これは「この関数は、メンバ変数を書き換えません」という宣言です。 

int GetHp() const
{
    m_hp = 0;        // ★ コンパイルエラー
    return m_hp;
}

Get〜 のような「読むだけの関数」には、必ず付けてください。 付けておくと、const なオブジェクトからも呼べるようになります。

07演習

演習1（まねる）

void Print(const Vector3& pos) という関数を作って、中で pos.x = 0.0f; と書いてみる。エラーになることを確認する。

演習2（直す）

自分が書いたクラスの Get〜 関数に、すべて const を付ける。

解答例を見る（まず自分でやってから） 
class Enemy {
public:
    int            GetHp() const       { return m_hp; }
    const Vector3& GetPosition() const { return m_position; }
    bool           IsAlive() const     { return m_hp > 0; }
private:
    int     m_hp = 100;
    Vector3 m_position = Vector3::Zero;
};

GetPosition() の戻り値も const Vector3& にしています。 コピーを作らず、書き換えもさせないためです。

これは k2Engine の書き方とまったく同じです。 SpriteRender などを見てみてください。 

const Vector3& GetPosition() const
{
    return m_position;
}

演習3（測る）

大きな構造体（float を100個持つもの）を作り、値渡しと参照渡しで、どのくらい速さが違うかを調べる。

解答例を見る（まず自分でやってから） 
struct BigData {
    float values[100];
};

void ByValue(BigData d)        { d.values[0] = 1.0f; }
void ByRef(const BigData& d)   { (void)d; }

void Game::Update()
{
    BigData data = {};

    {
        K2_PROFILE_SCOPE("ByValue");
        for (int i = 0; i < 100000; i++) { ByValue(data); }
    }
    {
        K2_PROFILE_SCOPE("ByRef");
        for (int i = 0; i < 100000; i++) { ByRef(data); }
    }
}

F1 → Profiler で比べてください。 Debug ビルドなら、値渡しのほうがはっきり遅いはずです。 400バイトを10万回コピーしているのですから。

Release ビルドだと差が消えるかもしれません コンパイラの最適化が、無駄なコピーを消してしまうことがあります。
「だから気にしなくていい」という意味ではありません。 最適化が効かない場面は普通にあります。 const& はタダなので、付けておくのが正解です。

そして「測ってから判断する」という姿勢が、 LV5 のテーマそのものです。

08確認

  1. void Draw(RenderContext& rc) の & は何のため？
  2. const Vector3& の const は何を約束している？
  3. int GetHp() const のうしろの const は？
  4. int を const int& で渡すのはよい？
答え
  1. コピーを避けるため。巨大なオブジェクトを毎回コピーしないように。
  2. 「この関数は、渡されたものを書き換えません」。
  3. 「この関数は、メンバ変数を書き換えません」。
  4. よくない。小さい型はそのまま渡すほうが速い。
