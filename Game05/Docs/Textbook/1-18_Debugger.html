LV1 入門 ／ 1-18

デバッガを使う

難易度 ／ 前提 1-12

この章は、この先ずっと効きます デバッガを使えるかどうかで、今後の進み方がまったく変わります。 使えない人は、当てずっぽうでコードを書き換えて何時間も溶かします。 使える人は、数分で原因にたどり着きます。
ここは飛ばさないでください。

01この章でできるようになること

  • プログラムを好きなところで止めて、中身を見られる
  • 1行ずつ実行して、動きを追える
  • クラッシュしたとき、原因の場所を特定できる

02ブレークポイント ― 止める

行番号の左の灰色の帯をクリックすると、赤い丸が付きます。 （F9 でも付けられます）

F5 で実行すると、その行に来た瞬間に止まります。

止まっているあいだ、ゲームも止まっています 固まったように見えますが、正常です。 Visual Studio の画面に戻って、続きの操作をしてください。

034つのキーを覚える

キー名前動作
F10ステップオーバー 次の1行へ進む（関数の中には入らない）
F11ステップイン 関数の中へ入る
Shift+F11ステップアウト いまの関数を抜けるまで進む
F5続行 次のブレークポイントまで走る

まず F10 だけ覚えてください。 1行ずつ進めるだけで、たいていのことは分かります。

04中身を見る ― ローカルとウォッチ

ウィンドウ何が見える
ローカル いまの関数の変数が自動で全部出る
ウォッチ 自分で指定したものだけを見る
自動変数 いまの行の前後で使われているものだけ

いちばん簡単なのは、変数にマウスカーソルを乗せることです。 止まっているあいだ、値がポップアップで出ます。

ウォッチに入れたいときは、変数を選択して右クリック → 「ウォッチ式の追加」です。 m_hp * 2 のような式も入れられます。

値を書き換えることもできます ローカルウィンドウの値をダブルクリックすると、 その場で書き換えられます。
「HPを1にしたらどうなるか」を、コードを直さずに試せます。 これは非常に便利です。

05コールスタック ― どこから来たか

Ctrl+Alt+C で呼び出し履歴が開きます。 

> Game.exe!Enemy::Update()  行 42            ← いまここ
  Game.exe!IGameObject::UpdateWrapper()      ← ここから呼ばれた
  Game.exe!GameObjectManager::ExecuteUpdate()
  Game.exe!K2EngineLow::ExecuteUpdate()
  Game.exe!K2Engine::Execute()
  Game.exe!wWinMain()                        ← 大もと

上から下へ「誰が呼んだか」がさかのぼれます。 行をダブルクリックすると、その場所に飛べます。

クラッシュしたら、まずこれを見る いちばん上が、落ちた場所です。
もし自分のコードではなくエンジンの中で落ちていたら、 下にたどって、自分のコードが出てくる最初の行を見てください。 たいてい、そこが原因です。

06条件付きブレークポイント

毎フレーム止まると、進めません。 「特定のときだけ止めたい」ときに使います。

  1. ブレークポイント（赤い丸）を右クリック
  2. 「条件」を選ぶ
  3. m_hp <= 0 のような式を書く

これで、HPが0以下になった瞬間だけ止まります。

これを知っているかどうかで、大差がつきます 「100体目の敵だけおかしい」「10秒後だけ変」といったバグを、 一発で捕まえられます。
i == 99 や m_frameCount > 600 のような条件が使えます。

07出力ウィンドウとの使い分け

デバッガ（止める）OutputDebugStringA（ログ）
向いていること 1か所をじっくり調べる 時間の流れを追う
向いていないこと 毎フレーム変わるものを追う 複雑な構造の中身を見る
例 「この変数の中身は？」 「この関数、何回呼ばれてる？」

両方使ってください。どちらかだけでは足りません。

08デバッグの手順

当てずっぽうでコードを書き換えないこと 「とりあえず直してみる」はいちばん時間がかかります。 運よく直っても、なぜ直ったか分からないので、また同じバグを踏みます。
  1. 症状をはっきりさせる。 「動かない」ではなく「Aボタンを押しても弾が出ない」
  2. どこまで正しいか確かめる。 ブレークポイントを置いて、そこまで来ているか見る
  3. 変数の中身を見る。 期待した値が入っているか
  4. おかしくなった場所を絞る。 正しい場所と、おかしい場所の間に原因がある
  5. 原因が分かってから直す

2番がいちばん大事です。 「弾が出ない」とき、Shoot() にブレークポイントを置いて そもそも呼ばれているのかを確かめてください。 呼ばれていないなら、原因は Shoot() の中ではありません。

09演習

演習1（まねる）

Game::Update() にブレークポイントを置いて止め、F10 で1行ずつ進めながら、ローカルウィンドウで変数の変化を見る。

演習2（条件を付ける）

m_frameCount を数えるコードを書き、300フレーム目だけ止まる条件付きブレークポイントを設定する。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    m_frameCount++;          // ★ この行にブレークポイント
    ...
}

手順

  1. ブレークポイントを置く
  2. 赤い丸を右クリック → 「条件」
  3. m_frameCount == 300 と入力
  4. F5 で実行

約5秒後（300 ÷ 60）に止まります。 それまではふつうに動き続けます。

「ヒット カウント」も便利です 右クリック → 「条件」→「ヒット カウント」を選ぶと、 「300回目に通ったときだけ止まる」という指定もできます。
変数を用意しなくてよいので、こちらのほうが手軽なことも多いです。

演習3（クラッシュを追う）

わざとクラッシュさせて、コールスタックから原因の行を特定する。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    int* p = nullptr;
    *p = 100;              // ★ ここで落ちる
}

実行すると、こう出ます。

例外がスローされました: 書き込みアクセス違反
p は nullptr でした。

やること

  1. 「中断」を押す（「続行」や「閉じる」ではない）
  2. 止まった行を見る → *p = 100;
  3. Ctrl+Alt+C でコールスタックを開く
  4. いちばん上が Game::Update() になっている
  5. p にマウスを乗せる → 0x0000000000000000（つまり nullptr）
Visual Studio は、かなり親切に教えてくれます 「p は nullptr でした」とまで書いてくれます。 読めば、たいてい書いてあります。
英語だからと閉じてしまう人が多いのですが、 そこに答えがあります。

次に、エンジンの中で落ちる例も試してみてください。

void Game::Update()
{
    std::vector<int> v;
    int a = v[10];         // 空の vector の10番目
    (void)a;
}

今度はエンジンや標準ライブラリの中で止まります。 コールスタックを下にたどって、 自分のコードが出てくる最初の行を探してください。 そこが原因です。

10確認

  1. ブレークポイントを置くキーは？
  2. F10 と F11 の違いは？
  3. クラッシュしたとき、まず何を見る？
  4. 「毎フレーム止まって進めない」ときは？
答え
  1. F9（行番号の左をクリックでも可）。
  2. F10 は関数の中に入らず次の行へ。 F11 は関数の中に入る。
  3. コールスタック（Ctrl+Alt+C）。 いちばん上が落ちた場所。
  4. 条件付きブレークポイント、またはヒットカウントを使う。
