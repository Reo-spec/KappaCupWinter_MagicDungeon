LV3 表現 ／ 3-13

アニメーション

難易度 ／ 前提 3-09

01この章でできるようになること

  • モデルを歩かせたり、攻撃させたりできる
  • アニメーションをなめらかに切り替えられる
  • 状態とアニメーションを対応させる書き方が身につく

02使い方

// Player.h
enum EnAnimClip {
    enAnimClip_Idle,
    enAnimClip_Walk,
    enAnimClip_Attack,
    enAnimClip_Num,          // ★ 個数。最後に置く
};

private:
    AnimationClip m_animClips[enAnimClip_Num];
    ModelRender   m_modelRender;

// Player.cpp
bool Player::Start()
{
    m_animClips[enAnimClip_Idle  ].Load("Assets/animData/idle.tka");
    m_animClips[enAnimClip_Idle  ].SetLoopFlag(true);      // ループする

    m_animClips[enAnimClip_Walk  ].Load("Assets/animData/walk.tka");
    m_animClips[enAnimClip_Walk  ].SetLoopFlag(true);

    m_animClips[enAnimClip_Attack].Load("Assets/animData/attack.tka");
    m_animClips[enAnimClip_Attack].SetLoopFlag(false);     // 1回だけ

    m_modelRender.Init("Assets/modelData/player.tkm",
                       m_animClips,        // ★ 渡す
                       enAnimClip_Num);
    return true;
}

再生は1行です。 

m_modelRender.PlayAnimation(enAnimClip_Walk, 0.2f);
//                          ↑クリップ番号     ↑切り替えにかける秒数
第2引数が「なめらかさ」です 0.2 くらいを指定すると、前のポーズから0.2秒かけて混ざります。 （補間、ブレンドといいます）
0 にするとカクッと切り替わります。 忘れるとロボットみたいな動きになるので、必ず指定してください。

03PlayAnimation は毎フレーム呼んでよい

同じクリップを指定したときは、何も起きません。 だから、毎フレーム呼んでも問題ありません。 

void Player::Update()
{
    // 動いているなら歩き、止まっているなら待機
    if (m_moveSpeed.LengthSq() > 0.001f) {
        m_modelRender.PlayAnimation(enAnimClip_Walk, 0.2f);
    }
    else {
        m_modelRender.PlayAnimation(enAnimClip_Idle, 0.2f);
    }

    m_modelRender.Update();
}

「いまの状態から、あるべきアニメーションを毎フレーム決める」 — この書き方がいちばん壊れにくいです。

逆に「攻撃ボタンが押された瞬間に1回だけ呼ぶ」という書き方をすると、 どこかで呼び忘れて、ずっと攻撃モーションのまま といったバグが起きます。

04状態と対応させる

2-16 でやった状態の考え方が、そのまま使えます。 

enum EnState {
    enState_Idle,
    enState_Walk,
    enState_Attack,
};

void Player::Update()
{
    switch (m_state) {
    case enState_Idle:
        m_modelRender.PlayAnimation(enAnimClip_Idle, 0.2f);
        if (入力がある)      { m_state = enState_Walk; }
        if (攻撃ボタン)      { m_state = enState_Attack; }
        break;

    case enState_Walk:
        m_modelRender.PlayAnimation(enAnimClip_Walk, 0.2f);
        Move();
        if (入力がない)      { m_state = enState_Idle; }
        if (攻撃ボタン)      { m_state = enState_Attack; }
        break;

    case enState_Attack:
        m_modelRender.PlayAnimation(enAnimClip_Attack, 0.1f);
        // 攻撃が終わったら待機へ
        if (m_modelRender.IsPlayingAnimation() == false) {
            m_state = enState_Idle;
        }
        break;
    }

    m_modelRender.Update();
}
攻撃中に歩けないのは、これで表現できます enState_Attack の中に Move() を書かなければ、 攻撃中は動けません。
状態ごとに「何ができるか」を書き分けるだけで、 ゲームらしい手触りになります。

05再生速度

m_modelRender.SetAnimationSpeed(2.0f);    // 2倍速

走りのアニメーションを、移動速度に合わせて速くする といった使い方をします。 

float speed = m_moveSpeed.Length();
m_modelRender.SetAnimationSpeed(speed / 200.0f);

これだけで「足が滑っている」感じがかなり減ります。

06演習

演習1（まねる）

待機と歩きのアニメーションを、移動入力で切り替える。

演習2（状態にする）

攻撃モーションを足して、攻撃中は動けないようにする。

解答例を見る（まず自分でやってから） 
// Player.h
enum EnState { enState_Idle, enState_Walk, enState_Attack };

private:
    EnState m_state = enState_Idle;

// Player.cpp
void Player::Update()
{
    switch (m_state) {
    case enState_Idle:   UpdateIdle();   break;
    case enState_Walk:   UpdateWalk();   break;
    case enState_Attack: UpdateAttack(); break;
    }

    m_modelRender.SetPosition(m_position);
    m_modelRender.Update();
}

void Player::UpdateIdle()
{
    m_modelRender.PlayAnimation(enAnimClip_Idle, 0.2f);

    if (g_pad[0]->IsTrigger(enButtonA)) {
        m_state = enState_Attack;
        return;
    }
    if (HasMoveInput()) {
        m_state = enState_Walk;
    }
}

void Player::UpdateWalk()
{
    m_modelRender.PlayAnimation(enAnimClip_Walk, 0.2f);
    Move();                                   // ★ 歩きにだけ Move がある

    if (g_pad[0]->IsTrigger(enButtonA)) {
        m_state = enState_Attack;
        return;
    }
    if (HasMoveInput() == false) {
        m_state = enState_Idle;
    }
}

void Player::UpdateAttack()
{
    m_modelRender.PlayAnimation(enAnimClip_Attack, 0.1f);
    // Move() を呼ばない → 動けない

    if (m_modelRender.IsPlayingAnimation() == false) {
        m_state = enState_Idle;
    }
}
攻撃アニメは、必ず SetLoopFlag(false) に ループのままだと IsPlayingAnimation() が 永遠に true を返し、攻撃状態から抜けられません。

「攻撃したら動けなくなった」というバグの、いちばんの原因です。

状態ごとに関数を分けておくと、後で読みやすくなります。 switch の中身が10行を超えたら、関数に切り出してください。

演習3（合わせる）

移動速度に応じてアニメーションの再生速度を変える。足が滑らなくなるか確認する。

解答例を見る（まず自分でやってから） 
void Player::UpdateWalk()
{
    m_modelRender.PlayAnimation(enAnimClip_Walk, 0.2f);
    Move();

    // 移動の速さに合わせる
    float speed = m_moveSpeed.Length();
    float rate  = speed / WALK_SPEED;          // WALK_SPEED のときちょうど 1.0

    // 極端な値にならないよう、上下を押さえる
    rate = min(max(rate, 0.5f), 2.0f);
    m_modelRender.SetAnimationSpeed(rate);
    ...
}

合わせ方の手順

  1. まず SetAnimationSpeed(1.0f) のまま歩かせる
  2. 足が滑るなら、移動速度が速すぎる（またはアニメが遅い）
  3. 速度を 1.0 のままでぴったり合う移動速度を探す
  4. その値を WALK_SPEED にする
  5. あとは上の式で、走りも歩きも自動的に合う
状態を抜けるとき、速度を戻すのを忘れずに SetAnimationSpeed は設定しっぱなしです。 歩きで 2.0 にしたまま待機に戻ると、 待機モーションも2倍速になります。 
void Player::UpdateIdle()
{
    m_modelRender.SetAnimationSpeed(1.0f);    // ★ 戻す
    m_modelRender.PlayAnimation(enAnimClip_Idle, 0.2f);
    ...
}
これは「フットスライド」と呼ばれる問題です きちんと直そうとすると、アニメーションの足の動きから 移動速度を決める（ルートモーション）というやり方になります。
市販ゲームではそちらが主流ですが、 速度に合わせて再生速度を変えるだけでも、かなり良くなります。

07確認

  1. PlayAnimation の第2引数は何？
  2. 毎フレーム PlayAnimation を呼んでよいのはなぜ？
  3. 攻撃モーションに SetLoopFlag(true) を付けるとどうなる？
答え
  1. 前のアニメーションから混ざりきるまでの秒数。
  2. 同じクリップを指定したときは何も起きないから。
  3. IsPlayingAnimation() が false にならず、攻撃状態から抜けられなくなる。
