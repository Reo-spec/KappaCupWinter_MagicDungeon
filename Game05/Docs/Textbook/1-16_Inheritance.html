LV1 入門 ／ 1-16

継承と仮想関数

難易度 ／ 前提 1-15

01この章でできるようになること

  • 共通の部分をまとめて、違う部分だけを書ける
  • なぜ Update() が勝手に呼ばれるのかが分かる
  • IGameObject のソースが読める

02同じコードを何度も書きたくない

敵も弾もアイテムも、「位置を持つ」「毎フレーム動く」「画面に描かれる」 のは同じです。 全部のクラスに同じコードを書くのは無駄です。

共通部分を「親」にまとめて、違うところだけ「子」で書く。 これが継承です。 

// 親
class Character
{
public:
    void SetPosition(const Vector3& pos) { m_position = pos; }
protected:
    Vector3 m_position = Vector3::Zero;
};

// 子
class Enemy : public Character      // ★ Character を継承する
{
public:
    void Attack();                  // Enemy だけが持つもの
};
Enemy e;
e.SetPosition({ 100.0f, 0.0f, 0.0f });   // 親の関数が使える
e.Attack();                               // 自分の関数も使える
protected という3つめの指定 private だと、子からも触れません。 子には触らせたいが外には見せたくない、というときに protected を使います。

03仮想関数 ― 子ごとに中身を変える

親に Update() があるとして、 敵と弾では動き方が違います。 そこで、親では「こういう関数があるよ」とだけ決めて、 中身は子に書かせます。 

class Character
{
public:
    virtual void Update() {}        // ★ virtual を付ける
};

class Enemy : public Character
{
public:
    void Update() override          // ★ override を付ける
    {
        m_position.y -= 1.0f;
    }
};

class Bullet : public Character
{
public:
    void Update() override
    {
        m_position.y += 10.0f;
    }
};

04ここが継承の本番

親のポインタで、子をまとめて扱えます。 

std::vector<Character*> characters;
characters.push_back(new Enemy());
characters.push_back(new Bullet());
characters.push_back(new Enemy());

for (Character* c : characters) {
    c->Update();      // ★ Enemy なら Enemy::Update、Bullet なら Bullet::Update
}
これが「ポリモーフィズム（多態性）」です 呼ぶ側は「Characterだ」としか知らないのに、 実際には正しい子の関数が呼ばれます。
敵の種類が100個に増えても、この for 文は1行も変わりません。 これが継承のいちばんの価値です。
virtual を付け忘れると、親のほうが呼ばれます virtual が無いと、ポインタの型で決まってしまいます。 Character* なので Character::Update() が呼ばれ、 何も起きません。エラーも出ません。
「子の Update が呼ばれない」ときは、まず virtual を疑ってください。

05override は必ず書く

class Enemy : public Character
{
public:
    void Updata() override     // ★ タイプミス → コンパイルエラーになる
    {
    }
};

override は「親の関数を上書きしています」という宣言です。 親に同じ名前の仮想関数が無ければ、コンパイルエラーになります。

書かないと、タイプミスしても「新しい関数」として黙って作られます。 結果、「なぜか Update が呼ばれない」という原因不明のバグになります。

これは実際によく起きます Updata、Uptade、Rander。 override を書いておけば、全部その場で気づけます。 必ず書いてください。

06IGameObject の正体

では、エンジンのソースを読んでみましょう。 k2EngineLow/gameObject/IGameobject.h です。 

class IGameObject : public Noncopyable {
public:
    virtual ~IGameObject() {}

    virtual bool Start() { return true; }
    virtual void Update() {}
    virtual void Render(RenderContext& renderContext) {}

public:
    void UpdateWrapper()
    {
        if (m_isActive && m_isStart && !m_isDead) {
            Update();                    // ★ ここで子の Update が呼ばれる
        }
    }
    ...
protected:
    bool m_isStart = false;
    bool m_isDead = false;
    bool m_isActive = true;
};

謎が解けました。

  1. GameObjectManager は std::list<IGameObject*> を持っている
  2. 毎フレーム、全部に対して UpdateWrapper() を呼ぶ
  3. UpdateWrapper() が Update() を呼ぶ
  4. Update() は virtual なので、 あなたが書いた Game::Update() が呼ばれる
なぜ Update() をそのまま呼ばないのか UpdateWrapper() をはさむことで、 「死んでいたら呼ばない」「非アクティブなら呼ばない」という判定を、 全オブジェクト共通で1か所に書けます。
これを各自の Update() の先頭に書かせたら、 書き忘れる人が必ず出ます。

07デストラクタは virtual に

virtual ~IGameObject() {}      // ★ virtual が付いている

親のポインタで delete するとき、 virtual が無いと子のデストラクタが呼ばれません。 

Character* c = new Enemy();
delete c;      // virtual が無いと、~Enemy() が呼ばれない！

Enemy が何かを確保していたら、それが漏れます。 継承される可能性のあるクラスのデストラクタは、 必ず virtual にする。これは鉄則です。

08演習

演習1（まねる）

Character（親）と Enemy・Bullet（子）を作り、std::vector<Character*> に入れてまとめて Update() する。

演習2（壊して確かめる）

親の Update() から virtual を消すと、何が起きるか。予想してから試す。

解答例を見る（まず自分でやってから） 
class Character
{
public:
    void Update() {}          // virtual を消した
};

親の Update()（中身が空）が呼ばれます。 子の Update() は呼ばれません。何も動かなくなります。

しかも override を付けていると、 子のほうでコンパイルエラーになります。 

error C3668: 'Enemy::Update': オーバーライド指定子 'override' を含むメソッドが
             基底クラス メソッドをオーバーライドしていません
これが override の価値です override を書いていなければ、エラーも警告も出ずに、 ただ静かに動かなくなります。
書いていれば、その場で止めてくれます。 「めんどうだから書かない」は、何時間も損をします。

演習3（読む）

k2EngineLow/gameObject/IGameobject.h を実際に開いて、全部読んでみる。分からないところがあってもよい。UpdateWrapper() と StartWrapper() の違いを説明してみる。

解答例を見る（まず自分でやってから） 
void UpdateWrapper()
{
    if (m_isActive && m_isStart && !m_isDead) {
        Update();
    }
}

void StartWrapper()
{
    if (m_isActive && !m_isStart && !m_isDead) {
        if (Start()) {
            m_isStart = true;       // ★ true を返したら、もう呼ばない
        }
    }
}
条件意味
UpdateWrapperm_isStart が true 初期化が終わってから呼ぶ
StartWrapperm_isStart が false 初期化がまだのときだけ呼ぶ

ここから分かること

  • Start() が false を返すと、 m_isStart が true にならず、 次のフレームでもう一度 Start() が呼ばれます
  • そのあいだ Update() は呼ばれません
  • だから「読み込みに何フレームもかかる処理」を Start() で分割して書けるのです
エンジンのソースは読んでよいものです 「ブラックボックス」だと思わないでください。 困ったとき、答えはたいていソースに書いてあります。
IGameObject は150行ほどしかありません。 このくらいなら、全部読めます。 読める、と分かったことがこの演習の成果です。

09確認

  1. virtual を付けないと何が起きる？
  2. override を書く理由は？
  3. あなたの書いた Game::Update() は、誰が呼んでいる？
  4. デストラクタを virtual にするのはなぜ？
答え
  1. 親のほうの関数が呼ばれる。子の関数は呼ばれず、エラーも出ない。
  2. 関数名を打ち間違えたときに、コンパイルエラーで気づけるから。
  3. GameObjectManager。 IGameObject::UpdateWrapper() を経由して呼ばれる。
  4. 親のポインタで delete したとき、 子のデストラクタも呼ばれるようにするため。
