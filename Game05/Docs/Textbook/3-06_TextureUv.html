LV3 表現 ／ 3-06

テクスチャとUV

難易度 ／ 前提 3-04

01この章でできるようになること

  • UVが何なのか説明できる
  • 背景を無限にスクロールさせられる
  • 1枚の画像から、コマを切り出して使える

02UVとは「画像のどこを使うか」

頂点は、位置のほかに UV という値を持っています。 「この頂点は、画像のどこに対応するか」を表す2つの数です。

UV画像の場所
(0, 0)左上
(1, 0)右上
(0, 1)左下
(1, 1)右下
(0.5, 0.5)真ん中

画像の大きさに関係なく、いつも 0〜1 です。 512×512 でも 1920×1080 でも、右端は 1.0 です。

3-03 の演習2でやった return float4(In.uv.x, In.uv.y, 0, 1); を、 もう一度動かしてみてください。UVの並びが目で見えます。

03UVをずらすとスクロールする

cbuffer myCb : register(b1){
    float4 param0;      // x, y = UVのずらし量
};

float4 PSMain( PSInput In ) : SV_Target0
{
    float2 uv = In.uv;
    uv.y += param0.y;                 // ★ UVをずらす

    return colorTexture.Sample(Sampler, uv) * mulColor;
}
void BackgroundRender::Update()
{
    // 1秒で画像1枚ぶん流れる
    m_cb.param0.y += 1.0f * g_gameTime->GetFrameDeltaTime();
    m_sprite.Update(m_position, m_rotation, m_scale);
}
これだけだと、端で止まります UVが 1.0 を超えると、既定では端の色が引き伸ばされます （クランプ）。スクロールになりません。

04繰り返すように設定する

SpriteInitData に、 テクスチャアドレッシングモードという設定があります。 

SpriteInitData initData;
...
// UVが1.0を超えたら、繰り返す
initData.textureAddressMode = D3D12_TEXTURE_ADDRESS_MODE_WRAP;

m_sprite.Init(initData);
モードUVが範囲外のとき
CLAMP（既定）端の色を引き伸ばす
WRAP 繰り返す。スクロールにはこれ
MIRROR鏡のように折り返して繰り返す
画像が「つながる」ように作られている必要があります タイリング（シームレス）テクスチャといって、 上端と下端、左端と右端がぴったり繋がる画像でないと、 繰り返したときに継ぎ目が見えます。
星空や雲のような模様が一様なものなら、作るのは難しくありません。

05値が大きくなりすぎないように

param0.y をずっと足し続けると、 何時間も遊んだときに値が大きくなりすぎて、 小数の精度が足りなくなります。 スクロールがカクつき始めます。 

m_cb.param0.y += 1.0f * dt;

// 1.0 を超えたら 0 に戻す。見た目は同じ（1周したところ）。
if (m_cb.param0.y > 1.0f) {
    m_cb.param0.y -= 1.0f;
}

fmodf(m_cb.param0.y, 1.0f) でも同じです。 どちらでも構いません。

061枚の画像からコマを切り出す

キャラクターのアニメーションを、1枚の画像に並べておくやり方があります。 スプライトシートと呼びます。 

cbuffer myCb : register(b1){
    float4 param0;      // x = コマ番号, y = 横のコマ数
};

float4 PSMain( PSInput In ) : SV_Target0
{
    float cellCount = param0.y;                  // 例：4コマ
    float index     = param0.x;                  // 何コマ目か

    float2 uv = In.uv;
    uv.x = uv.x / cellCount + index / cellCount; // ★ 横方向に切り出す

    return colorTexture.Sample(Sampler, uv) * mulColor;
}

uv.x を 1/4 に縮めてから、 コマ番号のぶんだけずらしています。 

void CharacterRender::Update()
{
    m_animTimer += g_gameTime->GetFrameDeltaTime();

    // 0.1秒ごとに次のコマへ
    int index = ((int)(m_animTimer / 0.1f)) % 4;

    m_cb.param0.x = (float)index;
    m_cb.param0.y = 4.0f;
    m_sprite.Update(m_position, m_rotation, m_scale);
}
2Dのアニメーションは、これで作れます 歩き、攻撃、爆発。コマを並べた画像1枚と、この数行だけです。

07演習

演習1（まねる）

背景をスクロールさせる。WRAP を設定しないとどうなるかも確認する。

演習2（重ねる）

速さの違う背景を2枚重ねて、奥行きを出す。（遠くのものほどゆっくり動かす）

解答例を見る（まず自分でやってから）

これを多重スクロール（パララックス）と呼びます。 2Dゲームで奥行きを出す、いちばん手軽な方法です。 

// GameScene.cpp
bool GameScene::Start()
{
    // 奥（星空）― ゆっくり
    m_farBg.Init("Assets/sprite/stars.dds",  "Assets/shader/scroll.fx", 1920, 1080);
    m_farBg.SetScrollSpeed(0.05f);

    // 手前（雲）― 速い
    m_nearBg.Init("Assets/sprite/clouds.dds", "Assets/shader/scroll.fx", 1920, 1080);
    m_nearBg.SetScrollSpeed(0.30f);
    return true;
}

優先度に注意してください。

enPriority_BackgroundFar  = 0,      // 奥
enPriority_BackgroundNear = 1,      // 手前
enPriority_Enemy          = 3,
...

手前の雲は半透明（AlphaBlendMode_Trans）にして、 SetMulColor でαを 0.5 くらいに落とすと自然になります。

速さの比は「3倍くらい」を目安に 奥 0.05 に対して手前 0.15〜0.30。 差が小さいと効果が分からず、大きすぎると不自然です。 3枚重ねると、さらに深みが出ます。

演習3（自分で書く）

画面が波打つシェーダを書く。（ヒント：UVを sin でずらす）本文には答えがありません。

解答例を見る（まず自分でやってから） 
cbuffer myCb : register(b1){
    float4 param0;      // x = 時間, y = 波の強さ
};

float4 PSMain( PSInput In ) : SV_Target0
{
    float2 uv = In.uv;

    // 縦の位置と時間で、横方向にずらす
    uv.x += sin(uv.y * 20.0f + param0.x * 3.0f) * param0.y;

    return colorTexture.Sample(Sampler, uv) * mulColor;
}
数字意味目安
20.0f波の細かさ5〜50
3.0f波が動く速さ1〜10
param0.y波の大きさ0.005〜0.03

波の大きさは、思っているよりずっと小さい値です。 UVは 0〜1 なので、0.1 もずらすと画像の10%分動いてしまいます。

使いどころ

  • 水中ステージ
  • ダメージを受けたときの画面のゆがみ
  • 回想シーンへの切り替え
  • 炎の向こう側の陽炎
WRAP にしていないと端が伸びます UVをずらすシェーダは、必ず範囲外を参照します。 CLAMP のままだと、画面の端の色が引き伸ばされて見えます。 WRAP にするか、ずらす量をごく小さくしてください。

08確認

  1. UV (1, 0) は画像のどこ？
  2. スクロールさせるのに必要な設定は？
  3. スクロール値を足し続けると、何が起きる？ 対策は？
答え
  1. 右上。
  2. initData.textureAddressMode = D3D12_TEXTURE_ADDRESS_MODE_WRAP;
  3. 値が大きくなりすぎて小数の精度が落ち、カクつく。 1.0 を超えたら 1.0 引いて戻す。
