FindGO でオブジェクトを探す

難易度 ／ 前提 2-03

00入場チェック

  • NewGO の第3引数（名前）は何のためにある？ → 答えられないなら 2-03 へ戻る

01この章でできるようになること

  • ほかのゲームオブジェクトを名前で探せる
  • 1個・複数・全部に処理、の3つを使い分けられる
  • 名前で探すのは重いということを知っている

023つの探し方

関数使うとき返ってくるもの
FindGO<T>(名前)1個だけ探す 最初に見つかった1個。無ければ nullptr
FindGOs<T>(名前)同じ名前を全部集める const std::vector<T*>&
QueryGOs<T>(名前, 関数)全部に処理をする なし（関数が順に呼ばれる）
 
// 1個だけ
Player* player = FindGO<Player>("player");
if (player != nullptr) {
    Vector3 pos = player->GetPosition();
}

// 全部集める
const auto& enemies = FindGOs<Enemy>("enemy");
for (auto enemy : enemies) {
    enemy->TakeDamage(1);
}

// 全部に処理をする（途中でやめられる）
QueryGOs<Enemy>("enemy", [&](Enemy* enemy) {
    if (IsHit(enemy)) {
        enemy->TakeDamage(1);
        return false;      // false を返すと、そこで打ち切り
    }
    return true;           // true なら次へ
});
かならず nullptr を確認する FindGO は見つからなければ nullptr を返します。 名前を打ち間違えただけでも nullptr です。 確認せずに使うとクラッシュします。

03名前で探すのは重い

エンジンのソースを見ると、FindGO はこうなっています。 

template<class T>
T* FindGameObject(const char* objectName)
{
    for (auto goList : m_gameObjectListArray) {     // 優先度255個ぶん
        for (auto go : goList) {                    // その中の全オブジェクト
            if (go->IsMatchName(objectName)) {      // 文字列の比較
                T* p = dynamic_cast<T*>(go);        // 型の確認
                return p;
            }
        }
    }
    return nullptr;
}

全部のオブジェクトを順に見て、文字列を1つずつ比較しています。 オブジェクトが1000個あれば、最大1000回の文字列比較です。 エンジンのコメントにも「重いよ！」と書いてあります。

毎フレーム呼んではいけません 弾が100発あって、それぞれが Update() で FindGO していたら、1フレームに100回の全探索です。 Start() で1回だけ探して、結果を覚えておいてください。

04では、どう覚えておくのか

探した結果を Player* m_player; のように生ポインタで持つと、 相手が死んだときに事故ります。 それが 2-08 と 2-09 のテーマです。

正解を先に書いておくと、こうなります。 

class Bullet : public IGameObject {
    GOHandle<Player> m_player;      // ハンドルで持つ
};

bool Bullet::Start()
{
    m_player.Reset(FindGO<Player>("player"));   // 探すのは1回だけ
    return true;
}

void Bullet::Update()
{
    Player* player = m_player.Get();    // 毎フレーム取り直す（速い）
    if (player == nullptr) {
        return;
    }
    ...
}

GOHandle::Get() は、番号で表を引くだけなので速いです。 毎フレーム呼んでも問題ありません。 重いのは「名前で全部を探す」ほうです。

05名前の付け方

方針例
1個しかないものは、そのままの名前"player", "gameCamera"
たくさんあるものは、種類の名前で統一敵は全部 "enemy"（FindGOs で集められる）
探す予定がないものは nullptr でよいNewGO<Effect>(7)

名前は文字列なので、打ち間違えてもコンパイルエラーになりません。 "player" と "Player" は別物です。 心配なら、定数にまとめておくと安全です。 

// GameObjectName.h
const char* const OBJECT_NAME_PLAYER = "player";
const char* const OBJECT_NAME_ENEMY  = "enemy";

06よくあるエラー

FindGO が nullptr を返す

原因1：名前の打ち間違い。GameObject List パネルで正しい名前を確認する。
原因2：相手がまだ NewGO されていない。 優先度の順番を確認する（2-04）。
原因3：型が違う。FindGO<Enemy>("player") のように、 名前は合っていても型が違うと dynamic_cast が失敗して nullptr になります。

だんだん重くなる

原因：毎フレーム FindGO している。 オブジェクトが増えるほど遅くなります。
直し方：Start() で1回だけ探して、GOHandle に覚えさせる。

07演習

演習1（まねる）

敵から FindGO<Player>("player") で自機を探して、 自機のほうへ向かって動かす。

解答例を見る（まず自分でやってから） 
// Enemy.h
private:
    GOHandle<Player> m_player;

// Enemy.cpp
bool Enemy::Start()
{
    m_spriteRender.Init("Assets/sprite/enemy.dds", 64.0f, 64.0f);
    m_player.Reset(FindGO<Player>("player"));   // 探すのは1回だけ
    return true;
}

void Enemy::Update()
{
    Player* player = m_player.Get();
    if (player == nullptr) {
        return;                     // 自機がいない
    }

    const float dt = g_gameTime->GetFrameDeltaTime();
    Vector3 toPlayer = player->GetPosition() - m_position;
    toPlayer.Normalize();
    m_position += toPlayer * 150.0f * dt;

    m_spriteRender.SetPosition(m_position);
    m_spriteRender.Update();
}

Normalize() を忘れないでください。 忘れると、自機が遠いほど速く、近いほど遅くなります。 （向きだけ欲しいので、長さを1にそろえます）

演習2（数える）

FindGOs<Enemy>("enemy") で敵の数を数えて、画面に表示する。

解答例を見る（まず自分でやってから） 
void GameUi::Update()
{
    const auto& enemies = FindGOs<Enemy>("enemy");

    wchar_t text[256];
    swprintf_s(text, 256, L"ENEMY %d", (int)enemies.size());
    m_fontRender.SetText(text);
}

ただし、これは毎フレーム全探索しています。 UIは1個しかないので実用上は問題ありませんが、 数を数えるだけなら、敵が生まれたとき／死んだときにカウンタを増減するほうが速いです。

どちらが良いかは、測ってから決めてください。 （LV5 のテーマです）

演習3（測る）

敵を500個出して、毎フレーム FindGO するコードと Start() で1回だけ探すコードの両方を書き、 Profilerパネル（F1 → Profiler）で処理時間を比べる。 本文には答えがありません。

解答例を見る（まず自分でやってから） 
// A案：毎フレーム FindGO
void Enemy::Update()
{
    K2_PROFILE_SCOPE("Enemy Update (FindGO)");
    Player* player = FindGO<Player>("player");
    ...
}

// B案：Start で1回だけ
void Enemy::Update()
{
    K2_PROFILE_SCOPE("Enemy Update (GOHandle)");
    Player* player = m_player.Get();
    ...
}

F1 → Profiler で処理時間を比べます。

結果の見かた

  • 敵が数十体なら、差はほとんど出ません。それが正常です
  • 敵が500体になると、A案がはっきり遅くなります。 500体 × 500個の全探索 ＝ 1フレームに25万回の文字列比較だからです

「差が出なかった」も立派な結果です。 そのときは「この規模では問題にならない」ことが分かったということ。 測らずに「遅そうだから」で複雑にするのが、いちばん良くありません。

08確認

  1. FindGO が nullptr を返すのはどんなとき？（3つ）
  2. なぜ毎フレーム FindGO してはいけない？
  3. GOHandle::Get() は毎フレーム呼んでもいい？ なぜ？
答え
  1. 名前の打ち間違い／まだ作られていない／型が違う。
  2. 全オブジェクトを順に見て文字列比較するので、数が増えるほど遅くなるから。
  3. いい。番号で表を引くだけなので、オブジェクトが何個あっても速さが変わらないから。
