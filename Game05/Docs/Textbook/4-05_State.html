State ― 状態を持つものを書く

難易度 ／ 前提 4-03 , 2-16

01この章でできるようになること

  • 巨大な if の塊を、状態ごとに分けられる
  • enum + switch と、Stateクラスの使い分けが分かる
  • ボスの行動パターンを、あとから足せるようになる

02困っている形

void Boss::Update()
{
    m_timer += g_gameTime->GetFrameDeltaTime();

    if (m_phase == 0) {
        // 登場演出
        m_position.y -= 100.0f * g_gameTime->GetFrameDeltaTime();
        if (m_position.y < 300.0f) {
            m_phase = 1;
            m_timer = 0.0f;
        }
    }
    else if (m_phase == 1) {
        // 左右移動しながら弾を撃つ
        ...30行...
        if (m_hp < 500) {
            m_phase = 2;
            m_timer = 0.0f;
            m_shotCount = 0;        // ★ 入るときにリセットするものが増えていく
        }
    }
    else if (m_phase == 2) {
        ...50行...
    }
    else if (m_phase == 3) {
        ...40行...
    }
}

困ること

  • 1つの関数が200行を超える
  • 状態を切り替えるとき、リセットし忘れる変数が出る
  • メンバ変数が、どの状態で使うものか分からない
  • 第2形態だけテストしたいのに、最初から戦うしかない

03段階1 ― まず関数に分ける

いきなりクラスにしなくて構いません。 関数に分けるだけで、半分は解決します。 

enum EnPhase {
    enPhase_Appear,     // 登場
    enPhase_Move,       // 移動して撃つ
    enPhase_Rush,       // 突進
    enPhase_Dead,
};

void Boss::Update()
{
    switch (m_phase) {
    case enPhase_Appear: UpdateAppear(); break;
    case enPhase_Move:   UpdateMove();   break;
    case enPhase_Rush:   UpdateRush();   break;
    case enPhase_Dead:   UpdateDead();   break;
    }
}

void Boss::ChangePhase(EnPhase next)
{
    m_phase = next;
    m_timer = 0.0f;          // ★ 共通のリセットを1か所に
    m_shotCount = 0;
}
ChangePhase() が効きます 「状態を変えるときのリセット」を1か所にまとめると、 忘れようがなくなります。
m_phase = enPhase_Rush; と直接書かないのがコツです。

3-13 でやったのは、この形です。 状態が5個くらいまでなら、これで充分です。

04段階2 ― State クラスにする

状態が増え、状態ごとに持つ変数が違ってくると、 クラスに分けたくなります。 

// BossState.h
class Boss;

class IBossState {
public:
    virtual ~IBossState() {}

    /// <summary>この状態に入ったとき、1回だけ呼ばれる。</summary>
    virtual void OnEnter(Boss& boss) {}
    /// <summary>毎フレーム呼ばれる。次の状態を返す（変えないなら nullptr）。</summary>
    virtual std::unique_ptr<IBossState> Update(Boss& boss, float dt) = 0;
    /// <summary>この状態を抜けるとき、1回だけ呼ばれる。</summary>
    virtual void OnExit(Boss& boss) {}
};
// 突進する状態
class BossRushState : public IBossState {
public:
    void OnEnter(Boss& boss) override
    {
        boss.PlayAnimation(enAnimClip_Rush);
        m_targetPos = boss.GetPlayerPosition();     // ★ この状態だけの変数
        m_timer = 0.0f;
    }

    std::unique_ptr<IBossState> Update(Boss& boss, float dt) override
    {
        m_timer += dt;

        Vector3 dir = m_targetPos - boss.GetPosition();
        dir.Normalize();
        boss.MoveBy(dir * RUSH_SPEED * dt);

        if (m_timer > RUSH_TIME) {
            return std::make_unique<BossMoveState>();   // ★ 次の状態
        }
        return nullptr;                                 // ★ このまま
    }

private:
    Vector3 m_targetPos = Vector3::Zero;
    float   m_timer = 0.0f;
};
// Boss 側は、こうなる
void Boss::Update()
{
    if (m_state == nullptr) {
        return;
    }
    auto next = m_state->Update(*this, g_gameTime->GetFrameDeltaTime());
    if (next) {
        m_state->OnExit(*this);
        m_state = std::move(next);
        m_state->OnEnter(*this);
    }
}

Boss::Update() が10行になりました。 そして m_targetPos は、 突進状態のクラスの中にしか存在しません。

05OnEnter / OnExit の価値

enum + switchState クラス
入るときの処理 ChangePhase() に全部書く 状態ごとに OnEnter
状態専用の変数 Boss のメンバに全部並ぶ その状態クラスの中だけ
状態を足す enum と switch を書き換える クラスを1つ足すだけ
ファイル数1つ増える
向いている規模〜5状態5状態〜
小さいものに State クラスを使わないでください プレイヤーの「待機／歩き／攻撃」に State クラスを使うと、 3ファイル増えて読みにくくなるだけです。
3-13 の switch で充分です。

06ボスの第2形態からテストする

State に分けたことの、いちばん実利のある効果です。 

bool Boss::Start()
{
#ifdef _DEBUG
    // デバッグ中は、好きな状態から始められる
    m_state = std::make_unique<BossRushState>();
#else
    m_state = std::make_unique<BossAppearState>();
#endif
    m_state->OnEnter(*this);
    return true;
}

さらに、F1 のデバッグパネル （2-23）にボタンを足せば、 実行中に状態を切り替えられます。 

if (ImGui::Button("突進フェーズへ")) {
    boss->ForceChangeState(std::make_unique<BossRushState>());
}
ボス戦の調整が、何倍も速くなります 第3形態を調整するのに、毎回最初から戦う必要がなくなります。 これだけのために State に分ける価値があります。

07演習

演習1（分ける）

自分のボス（または敵）の Update() を、enum + 状態ごとの関数に分ける。ChangePhase() も作る。

演習2（クラスにする）

状態を IState のクラスに分ける。OnEnter / OnExit も実装する。

解答例を見る（まず自分でやってから）

BossState.h

#pragma once
#include <memory>

class Boss;

class IBossState {
public:
    virtual ~IBossState() {}
    virtual const char* GetName() const = 0;     // デバッグ表示用
    virtual void OnEnter(Boss& boss) {}
    virtual std::unique_ptr<IBossState> Update(Boss& boss, float dt) = 0;
    virtual void OnExit(Boss& boss) {}
};

class BossAppearState : public IBossState {
public:
    const char* GetName() const override { return "Appear"; }
    void OnEnter(Boss& boss) override;
    std::unique_ptr<IBossState> Update(Boss& boss, float dt) override;
};

class BossMoveState : public IBossState {
public:
    const char* GetName() const override { return "Move"; }
    void OnEnter(Boss& boss) override;
    std::unique_ptr<IBossState> Update(Boss& boss, float dt) override;
private:
    float m_timer     = 0.0f;
    float m_shotTimer = 0.0f;
    int   m_dir       = 1;
};

class BossRushState : public IBossState {
public:
    const char* GetName() const override { return "Rush"; }
    void OnEnter(Boss& boss) override;
    std::unique_ptr<IBossState> Update(Boss& boss, float dt) override;
    void OnExit(Boss& boss) override;
private:
    Vector3 m_targetPos = Vector3::Zero;
    float   m_timer     = 0.0f;
};

BossState.cpp（1つだけ抜粋）

void BossMoveState::OnEnter(Boss& boss)
{
    boss.PlayAnimation(enAnimClip_Idle);
    m_timer     = 0.0f;
    m_shotTimer = 0.0f;
}

std::unique_ptr<IBossState> BossMoveState::Update(Boss& boss, float dt)
{
    m_timer     += dt;
    m_shotTimer += dt;

    // 左右に往復
    boss.MoveBy({ MOVE_SPEED * m_dir * dt, 0.0f, 0.0f });
    if (fabsf(boss.GetPosition().x) > MOVE_LIMIT) {
        m_dir = -m_dir;
    }

    // 撃つ
    if (m_shotTimer > SHOT_INTERVAL) {
        m_shotTimer = 0.0f;
        boss.ShotWay(3);
    }

    // HPが減ったら突進へ
    if (boss.GetHp() < RUSH_HP) {
        return std::make_unique<BossRushState>();
    }
    // 一定時間たっても突進へ
    if (m_timer > MOVE_TIME) {
        return std::make_unique<BossRushState>();
    }
    return nullptr;
}

Boss 側

// Boss.h
public:
    void ChangeState(std::unique_ptr<IBossState> next);
    const char* GetStateName() const
    {
        return m_state ? m_state->GetName() : "(none)";
    }
    // State から使われるので public
    void MoveBy(const Vector3& v) { m_position += v; }
    void ShotWay(int num);
    int  GetHp() const { return m_hp; }
    const Vector3& GetPosition() const { return m_position; }

private:
    std::unique_ptr<IBossState> m_state;

// Boss.cpp
void Boss::ChangeState(std::unique_ptr<IBossState> next)
{
    if (m_state) { m_state->OnExit(*this); }
    m_state = std::move(next);
    if (m_state) { m_state->OnEnter(*this); }
}

void Boss::Update()
{
    if (m_state == nullptr) { return; }

    auto next = m_state->Update(*this, g_gameTime->GetFrameDeltaTime());
    if (next) {
        ChangeState(std::move(next));
    }
    m_modelRender.SetPosition(m_position);
    m_modelRender.Update();
}
Update の中で自分を差し替えることになります m_state->Update() の戻り値で次の状態を返しているのは、 このためです。

もし Update() の中から直接 boss.ChangeState(...) を呼ぶと、 m_state が差し替わった直後に、自分自身（解放済み）の続きを実行する ことになります。 これは実際に起きる、追いにくいクラッシュです。

「次の状態を返す」形にしておけば、この事故は起こりません。

GetName() を付けておく理由

// デバッグパネルに1行足すだけで、いまの状態が見える
ImGui::Text("Boss State : %s", boss->GetStateName());

ボスのデバッグが、ここから一気に楽になります。

演習3（デバッグする）

F1 のデバッグパネルに、いまの状態の表示と、状態を強制的に切り替えるボタンを足す。（2-23）

解答例を見る（まず自分でやってから） 
// BossDebugPanel.cpp
#include "stdafx.h"
#include "Boss.h"
#include "BossState.h"

namespace {
    void DrawBossPanel()
    {
        Boss* boss = FindGO<Boss>("boss");
        if (boss == nullptr) {
            ImGui::TextDisabled(U8("ボスがいません"));
            return;
        }

        ImGui::Text("State : %s", boss->GetStateName());
        ImGui::Text("HP    : %d", boss->GetHp());
        ImGui::Separator();

        ImGui::TextUnformatted(U8("強制的に切り替える"));
        if (ImGui::Button("Appear")) {
            boss->ChangeState(std::make_unique<BossAppearState>());
        }
        ImGui::SameLine();
        if (ImGui::Button("Move")) {
            boss->ChangeState(std::make_unique<BossMoveState>());
        }
        ImGui::SameLine();
        if (ImGui::Button("Rush")) {
            boss->ChangeState(std::make_unique<BossRushState>());
        }

        ImGui::Separator();
        if (ImGui::Button(U8("HPを10に"))) {
            boss->SetHpForDebug(10);
        }
    }
}

void RegisterBossPanel()
{
    nsDbg::DebugGui::RegisterPanel(U8("ボス"), DrawBossPanel);
}
ボタンから ChangeState を呼ぶのは安全です 演習2の注意（Update の中から呼ぶと危ない）は、 IBossState::Update() の内側から呼んだ場合の話です。

デバッグパネルの描画は IBossState::Update() の外なので、 ここから呼ぶぶんには問題ありません。

「気づいたら変な状態になっていた」を調べるときに効きます。 どの順で遷移したかが残るので、 意図しない遷移がどこで起きたかが一目で分かります。

08確認

  1. m_phase = ... と直接書かず ChangePhase() を作るのはなぜ？
  2. State クラスにしたとき、状態専用の変数はどこに置く？
  3. State の Update() が「次の状態」を返す形にする理由は？
  4. enum + switch で充分なのは、だいたい何状態まで？
答え
  1. 切り替え時のリセット処理を1か所にまとめ、 忘れないようにするため。
  2. その状態クラスのメンバ。Boss には置かない。
  3. Update() の中で自分自身を解放してしまうのを防ぐため。
  4. 5状態くらいまで。
