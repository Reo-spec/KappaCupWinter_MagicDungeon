LV4 設計 ／ 4-10

Factory ― 生成を1か所に集める

難易度 ／ 前提 2-16

01この章でできるようになること

  • 散らばった switch を1か所にまとめられる
  • 敵の設定を、コードではなくデータで書ける
  • ステージ構成を、ビルドせずに調整できる

02困っている形

// Spawner.cpp
switch (type) {
case 0: { auto* e = NewGO<Enemy>(...); e->SetHp(10); e->SetMover(...); } break;
case 1: { auto* e = NewGO<Enemy>(...); e->SetHp(30); e->SetMover(...); } break;
case 2: ...
}

// BossStage.cpp ― ★ また switch
switch (type) {
case 0: ...
}

// DebugPanel.cpp ― ★ ここにも
switch (m_selectedType) {
case 0: ...
}

敵を1種類足すと、3か所に1行ずつ足すことになります。 そして、どれか1つを忘れます。

03まず ― 生成関数を1つにする

これだけで、8割は解決します。 

// EnemyFactory.h
enum EnEnemyType {
    enEnemyType_Zako,
    enEnemyType_Shooter,
    enEnemyType_Tank,
    enEnemyType_Num,
};

/// <summary>敵を1体作る。</summary>
/// <returns>作れなければ nullptr</returns>
Enemy* CreateEnemy(EnEnemyType type, const Vector3& position);
// EnemyFactory.cpp
Enemy* CreateEnemy(EnEnemyType type, const Vector3& position)
{
    Enemy* e = NewGO<Enemy>(enPriority_Enemy, "enemy");
    e->SetPosition(position);

    switch (type) {
    case enEnemyType_Zako:
        e->SetHp(10);
        e->SetMover(std::make_unique<StraightMover>(200.0f));
        e->SetScore(100);
        break;
    case enEnemyType_Shooter:
        e->SetHp(30);
        e->SetMover(std::make_unique<ZigzagMover>(150.0f, 200.0f, 3.0f));
        e->SetShotPattern(std::make_unique<AimShot>());
        e->SetScore(300);
        break;
    case enEnemyType_Tank:
        e->SetHp(200);
        e->SetMover(std::make_unique<StraightMover>(60.0f));
        e->SetScore(1000);
        break;
    default:
        DeleteGO(e);
        return nullptr;
    }
    return e;
}
switch は消えていません。1か所に集めただけです それで充分です。 敵を足すとき、触るのは EnemyFactory.cpp だけになりました。
「完全に switch をなくす」より、こちらのほうが読みやすいことが多いです。

04次 ― データにする

上の switch をよく見ると、 やっていることは「値を設定する」だけです。 ならば、表にできます。 

// EnemyFactory.cpp
namespace {

struct EnemyDef {
    const char* name;
    int         hp;
    int         score;
    float       moveSpeed;
    EnMoverType moverType;
    EnShotType  shotType;
};

// ★ 敵の定義を、1か所の表にする
const EnemyDef ENEMY_TABLE[enEnemyType_Num] = {
    // name        hp   score  speed  mover            shot
    { "Zako",      10,   100,  200.0f, enMover_Straight, enShot_None },
    { "Shooter",   30,   300,  150.0f, enMover_Zigzag,   enShot_Aim  },
    { "Tank",     200,  1000,   60.0f, enMover_Straight, enShot_None },
};

}  // namespace

Enemy* CreateEnemy(EnEnemyType type, const Vector3& position)
{
    if (type < 0 || type >= enEnemyType_Num) {
        return nullptr;
    }
    const EnemyDef& def = ENEMY_TABLE[type];

    Enemy* e = NewGO<Enemy>(enPriority_Enemy, "enemy");
    e->SetPosition(position);
    e->SetHp(def.hp);
    e->SetScore(def.score);
    e->SetMover(CreateMover(def.moverType, def.moveSpeed));
    e->SetShotPattern(CreateShotPattern(def.shotType));
    return e;
}

敵を1種類足すのが、表に1行足すだけになりました。

これを「テーブル駆動」といいます 分岐を、データの参照に置き換えるやり方です。
ゲーム開発では非常によく使われます。 行が並んでいるので、バランス調整のとき見比べやすいのも利点です。

05最後 ― ファイルから読む

表をテキストファイルにすれば、ビルドせずに調整できます。 

# Assets/data/enemy.txt
# name      hp   score  speed  mover     shot
Zako        10    100   200    straight  none
Shooter     30    300   150    zigzag    aim
Tank       200   1000    60    straight  none
Bomber      50    500   180    zigzag    circle

エンジンのデバッグ設定と同じ形式です。 k2EngineLow/dbg/DebugSettings.cpp が参考になります。

コードに書くファイルから読む
調整の速さビルドが要る 再起動だけ。うまく作れば実行中でも
間違いの検出コンパイル時 実行するまで分からない
プログラマ以外が触れるか無理 触れる
手間少ない読み込みを書く必要がある
ファイル化は、調整の回数が多いものだけに 敵のHPやスコアは、何十回も調整します。→ ファイル向き
敵の種類そのもの（クラス構成）は、めったに変わりません。→ コードでよい
「何回調整したか」で決めてください。

06ステージ構成もデータにする

# Assets/data/stage1.txt
# time  type      x
1.0     Zako      -200
1.5     Zako         0
2.0     Zako       200
5.0     Shooter   -300
5.0     Shooter    300
12.0    Tank         0
20.0    BOSS
void Spawner::Update()
{
    m_time += g_gameTime->GetFrameDeltaTime();

    while (m_next < (int)m_schedule.size()
        && m_schedule[m_next].time <= m_time)
    {
        const auto& s = m_schedule[m_next];
        CreateEnemy(s.type, { s.x, SPAWN_Y, 0.0f });
        m_next++;
    }
}
ここまで来ると、ゲームが「作れる」ようになります ステージを1つ増やすのが、テキストファイルを1つ足すだけになります。
これはポートフォリオでも強い要素です。 「ステージを追加するのに、コードを触らなくて済む設計にしました」 と言えます（4-17）。

07演習

演習1（まとめる）

散らばった敵の生成コードを、CreateEnemy() 1つにまとめる。

演習2（表にする）

テーブル駆動に書き直す。敵を1種類足してみて、1行で済むか確かめる。

解答例を見る（まず自分でやってから） 
// EnemyFactory.cpp
namespace {

enum EnMoverType  { enMover_Straight, enMover_Zigzag, enMover_Chase };
enum EnShotType   { enShot_None, enShot_Aim, enShot_Fan, enShot_Circle };

struct EnemyDef {
    const char*  name;
    int          hp;
    int          score;
    float        moveSpeed;
    EnMoverType  mover;
    EnShotType   shot;
    float        shotInterval;
    const char*  modelPath;
};

const EnemyDef ENEMY_TABLE[] = {
  // name       hp  score  speed  mover             shot           interval  model
  { "Zako",     10,   100, 200.f, enMover_Straight, enShot_None,     0.0f, "Assets/modelData/zako.tkm"    },
  { "Shooter",  30,   300, 150.f, enMover_Zigzag,   enShot_Aim,      1.2f, "Assets/modelData/shooter.tkm" },
  { "Tank",    200,  1000,  60.f, enMover_Straight, enShot_Fan,      2.0f, "Assets/modelData/tank.tkm"    },
  { "Bomber",   50,   500, 180.f, enMover_Chase,    enShot_Circle,   3.0f, "Assets/modelData/bomber.tkm"  },
};

// ★ 表の行数と enum の数が合っているか、コンパイル時に確かめる
static_assert(
    sizeof(ENEMY_TABLE) / sizeof(ENEMY_TABLE[0]) == enEnemyType_Num,
    "ENEMY_TABLE の行数が EnEnemyType と合っていません");

std::unique_ptr<IMover> CreateMover(EnMoverType type, float speed)
{
    switch (type) {
    case enMover_Straight: return std::make_unique<StraightMover>(speed);
    case enMover_Zigzag:   return std::make_unique<ZigzagMover>(speed, 200.0f, 3.0f);
    case enMover_Chase:    return std::make_unique<ChaseMover>(speed);
    }
    return nullptr;
}

std::unique_ptr<IShotPattern> CreateShotPattern(EnShotType type)
{
    switch (type) {
    case enShot_None:   return nullptr;
    case enShot_Aim:    return std::make_unique<AimShot>();
    case enShot_Fan:    return std::make_unique<FanShot>(3, 60.0f);
    case enShot_Circle: return std::make_unique<CircleShot>(12);
    }
    return nullptr;
}

}  // namespace

Enemy* CreateEnemy(EnEnemyType type, const Vector3& position)
{
    if (type < 0 || type >= enEnemyType_Num) {
        return nullptr;
    }
    const EnemyDef& def = ENEMY_TABLE[type];

    Enemy* e = NewGO<Enemy>(enPriority_Enemy, "enemy");
    e->SetPosition(position);
    e->SetHp(def.hp);
    e->SetScore(def.score);
    e->SetModel(def.modelPath);
    e->SetMover(CreateMover(def.mover, def.moveSpeed));

    auto shot = CreateShotPattern(def.shot);
    if (shot) {
        e->SetShotPattern(std::move(shot), def.shotInterval);
    }
    return e;
}

敵を足すときにやること

  1. EnEnemyType に enEnemyType_Bomber を足す
  2. 表に1行足す

以上です。

static_assert を入れておいてください enum に足して、表に足し忘れるのが、この方式の唯一の事故です。

static_assert があればコンパイルエラーで止まります。 実行時に配列の範囲外を読んで、よく分からない値の敵が出る、 という事態を防げます。

表を眺めるだけでバランスが見える

これが副次的な、でも大きな利点です。 「Tank のスコアが Shooter の3倍だけど、HPは7倍だな」 といったことが、表を見ただけで分かります。

演習3（ファイルにする）

ステージ構成をテキストファイルから読むようにする。ビルドせずにステージを調整できるか確かめる。

解答例を見る（まず自分でやってから）

ファイル形式（なるべく単純に）

# Assets/data/stage1.txt
# 「#」で始まる行と空行は無視する
# time  type      x
1.0     Zako      -200
1.5     Zako         0
2.0     Zako       200
5.0     Shooter   -300
5.0     Shooter    300
12.0    Tank         0

読み込み

// StageData.h
struct SpawnEntry {
    float        time;
    EnEnemyType  type;
    float        x;
};

class StageData {
public:
    bool Load(const char* filePath);
    const std::vector<SpawnEntry>& GetEntries() const { return m_entries; }
private:
    std::vector<SpawnEntry> m_entries;
};

// StageData.cpp
namespace {
    EnEnemyType NameToType(const std::string& name)
    {
        for (int i = 0; i < enEnemyType_Num; i++) {
            if (name == ENEMY_TABLE[i].name) {
                return (EnEnemyType)i;
            }
        }
        return enEnemyType_Num;      // 見つからない
    }
}

bool StageData::Load(const char* filePath)
{
    std::ifstream ifs(filePath);
    if (!ifs) {
        // ★ 読めなかったことが分かるようにする
        char buf[256];
        sprintf_s(buf, "StageData: %s が開けません\n", filePath);
        OutputDebugStringA(buf);
        return false;
    }

    m_entries.clear();
    std::string line;
    int lineNo = 0;

    while (std::getline(ifs, line)) {
        lineNo++;
        // コメントと空行を飛ばす
        if (line.empty() || line[0] == '#') { continue; }

        std::istringstream iss(line);
        float       time = 0.0f;
        std::string name;
        float       x = 0.0f;

        if (!(iss >> time >> name >> x)) {
            char buf[256];
            sprintf_s(buf, "StageData: %d行目が読めません\n", lineNo);
            OutputDebugStringA(buf);
            continue;                 // ★ 1行おかしくても、続ける
        }

        EnEnemyType type = NameToType(name);
        if (type == enEnemyType_Num) {
            char buf[256];
            sprintf_s(buf, "StageData: %d行目 不明な敵 '%s'\n",
                      lineNo, name.c_str());
            OutputDebugStringA(buf);
            continue;
        }
        m_entries.push_back({ time, type, x });
    }

    // 時間順に並べておく（ファイルがバラバラでも動くように）
    std::sort(m_entries.begin(), m_entries.end(),
        [](const SpawnEntry& a, const SpawnEntry& b) {
            return a.time < b.time;
        });

    return true;
}

使う

bool Spawner::Start()
{
    if (m_stage.Load("Assets/data/stage1.txt") == false) {
        // ★ 読めなくてもゲームは続ける
        return true;
    }
    return true;
}

void Spawner::Update()
{
    m_time += g_gameTime->GetFrameDeltaTime();

    const auto& entries = m_stage.GetEntries();
    while (m_next < (int)entries.size() && entries[m_next].time <= m_time) {
        CreateEnemy(entries[m_next].type, { entries[m_next].x, SPAWN_Y, 0.0f });
        m_next++;
    }
}
データを外に出すと、壊れ方が変わります コードならコンパイラが間違いを教えてくれました。 ファイルはそうではありません。

必ずこの3つを入れてください。
  • ファイルが開けなかったときに気づけるログ
  • 1行おかしくても止まらず、その行だけ飛ばす
  • おかしい行の行番号をログに出す

これが無いと、「なぜか敵が出ない」という 原因不明の不具合になります。

さらに一歩：実行中に読み直す

// デバッグパネルに
if (ImGui::Button(U8("ステージを読み直す"))) {
    spawner->Reload();
}

これがあると、調整のサイクルが「数秒」になります。 ファイルを保存 → ボタンを押す → すぐ確認。 ビルドを待つ時間がゼロになります。

08確認

  1. Factory にすると、敵を足すとき触る場所はいくつになる？
  2. テーブル駆動とは？
  3. データをファイルに出す代わりに、失うものは？
  4. ファイル読み込みで、必ず入れるべき3つは？
答え
  1. 1か所（EnemyFactory.cpp）。 テーブル駆動なら、表に1行。
  2. 分岐を、データ（表）の参照に置き換えるやり方。
  3. コンパイル時の検査。間違いが実行するまで分からなくなる。
  4. 開けなかったときのログ、1行飛ばして続ける、行番号を出す。
