LV3 表現 ／ 3-07

αブレンドと描画順・深度

難易度 ／ 前提 3-03 , 2-04

01この章でできるようになること

  • 半透明が変になる理由を説明できる
  • 加算合成で「光っているもの」を作れる
  • 深度バッファが何をしているか分かる

024つの合成モード

モード計算使いどころ
AlphaBlendMode_None上書き 不透明なもの。いちばん速い
AlphaBlendMode_Trans αで混ぜる ふつうの半透明、切り抜いた絵
AlphaBlendMode_Add 足す 光、炎、爆発、レーザー
AlphaBlendMode_Multiply 掛ける 影、暗くするフィルタ
「光るもの」は加算合成です Add は後ろの色に足すので、 重なるほど明るくなり、黒い部分は何も起きません。 これが「光っている」ように見える理由です。
弾、爆発、エフェクトは、まず Add を試してください。 一気にそれらしくなります。

03深度バッファ ― 前後関係の記録

3Dでは、描く順番がバラバラでも前後関係が正しくなります。 深度バッファ（Zバッファ）のおかげです。

画面のピクセルごとに「いま描かれているものの奥行き」を 記録しておき、それより手前のものだけを描くという仕組みです。

042Dでは優先度がすべて

2D（OnRender2D）では深度を使いません。 優先度の順に、上から重ねて描いているだけです （2-04）。

つまり2Dの重なりがおかしいときは、優先度を見れば必ず直ります。 深度やαブレンドのせいではありません。

加算合成なら、順番を気にしなくてよい 足し算は順番を変えても結果が同じです（a+b = b+a）。
だから Add のエフェクトどうしは、 どんな順に描いても同じ絵になります。 エフェクトで加算合成がよく使われるのは、見た目だけが理由ではありません。

05透明なのに四角く見える

よくある症状です。原因は3つ考えられます。

原因直し方
AlphaBlendMode_None になっている Trans にする
画像にαチャンネルが無い 透過付きで作り直して .dds に変換
シェーダでαを返していない return float4(rgb, 1.0f) のように αを 1 で固定していないか確認

3つめは、3-03 で シェーダを書き換えたときにやりがちです。 

// ダメ：αを捨てている
return float4(color.rgb, 1.0f);

// よい：元のαを残す
return float4(color.rgb, color.a);

06演習

演習1（まねる）

弾を AlphaBlendMode_Add にして、Trans と見比べる。光って見えることを確認する。

演習2（重ねる）

加算合成のスプライトを何枚も重ねて、どんどん明るくなることを確認する。また、順番を入れ替えても同じ絵になるか試す。

解答例を見る（まず自分でやってから） 
// 同じ場所に3枚出す
for (int i = 0; i < 3; i++) {
    Effect* e = NewGO<Effect>(enPriority_Effect + i, "effect");
    e->SetPosition({ 0.0f, 0.0f, 0.0f });
}

結果

  • 重ねるほど白く飛んでいく（足し算なので）
  • 優先度を入れ替えても、まったく同じ絵になる

半透明（Trans）で同じことをすると、 順番を変えると結果が変わります。 αで混ぜる計算は、順番を入れ替えると答えが違うからです。

白く飛びすぎるときは SetMulColor でα（4つめ）を下げてください。 加算合成でも、αは「どれだけ足すか」の強さとして効きます。 
m_spriteRender.SetMulColor({ 1.0f, 1.0f, 1.0f, 0.4f });

演習3（調べる）

AlphaBlendMode_Multiply（乗算）を使うと、どう見えるか試す。どんな場面で使えそうか考える。

解答例を見る（まず自分でやってから）

乗算は後ろの色に掛け算します。

掛ける色結果
白 (1,1,1)何も変わらない
黒 (0,0,0)真っ黒になる
灰 (0.5,0.5,0.5)半分の明るさ（暗くなる）
赤 (1,0,0)赤以外が消える

使いどころ

  • 影 — キャラクターの足元に、灰色の丸を乗算で置く
  • 暗いエリア — 洞窟に入ったら画面全体を暗くする
  • 色調の変更 — 夕方は全体にオレンジを掛ける
  • 汚れ・傷 — テクスチャの上から汚れを掛ける
加算と乗算は「反対」の関係です 加算は明るくするだけ、乗算は暗くするだけ。
  • 光を足したい → 加算
  • 影を落としたい → 乗算
この2つを覚えておけば、たいていの演出は作れます。

07確認

  1. 光っているものを表現するには、どの合成モード？
  2. 半透明どうしの重なりがおかしくなるのはなぜ？
  3. 2Dの重なり順は何で決まる？
  4. 透明にしたいのに四角く出るときの原因を1つ。
答え
  1. 加算（AlphaBlendMode_Add）。
  2. 半透明は深度を書き込まないので深度テストが効かず、 描いた順がそのまま重なり順になるから。
  3. 優先度（NewGO の第1引数）。
  4. ブレンドモードが None／画像にαが無い／ シェーダでαを 1 に固定している。
