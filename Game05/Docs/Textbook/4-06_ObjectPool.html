LV4 設計 ／ 4-06

Object Pool ― 作らずに使い回す

難易度 ／ 前提 2-05

01この章でできるようになること

  • 弾を大量に撃っても重くならないようにできる
  • new / delete のコストを意識できる
  • エンジンの Deactivate() を使いこなせる

02何が重いのか

弾を撃つたびに NewGO、当たったら DeleteGO。 1秒に60発撃つと、1秒で60回の new と delete です。

重くなる理由説明
new / delete 自体 OSに空きメモリを探してもらう。意外と遅い
初期化のコスト Start() で Init() を呼ぶと、 毎回テクスチャの読み込みが走ることがある
メモリの断片化 細かい確保と解放を繰り返すと、 メモリが虫食いになって効率が落ちる
リストの操作 k2Engine はゲームオブジェクトを std::list で持っている
2つめが、たいていいちばん重いです Bullet::Start() で m_spriteRender.Init("Assets/sprite/bullet.dds", ...) と書いていませんか。
エンジンがキャッシュしていても、 シェーダの設定やバッファの作成は毎回走ります。

03考え方 ― 最初に作って、使い回す

  1. ゲーム開始時に、弾を200発ぶん作っておく
  2. 全部 Deactivate() しておく（動かない・描かれない）
  3. 撃つとき、使っていない1発を探して Activate()
  4. 当たったら Deactivate() して、また貸出待ちに戻す

new も delete も、ゲーム中は1回も起きません。

k2Engine には、ちょうどよい機能があります IGameObject::Deactivate() を呼ぶと、 Update() も Render() も呼ばれなくなります。 オブジェクトは残ったままです。
Activate() で元に戻ります。 Object Pool のために用意されたような機能です。

04作る

// BulletPool.h
#pragma once

class Bullet;

class BulletPool : public IGameObject {
public:
    bool Start() override;

    /// <summary>
    /// 弾を1発撃つ。空きが無ければ何もしない。
    /// </summary>
    /// <returns>撃てたら true</returns>
    bool Fire(const Vector3& position, const Vector3& velocity);

    int GetActiveCount() const;      // デバッグ表示用

private:
    static const int NUM_BULLET = 200;
    std::vector<Bullet*> m_bullets;
};
// BulletPool.cpp
bool BulletPool::Start()
{
    m_bullets.reserve(NUM_BULLET);

    for (int i = 0; i < NUM_BULLET; i++) {
        Bullet* b = NewGO<Bullet>(enPriority_Bullet, "bullet");
        b->Deactivate();                  // ★ 最初は全部お休み
        m_bullets.push_back(b);
    }
    return true;
}

bool BulletPool::Fire(const Vector3& position, const Vector3& velocity)
{
    for (Bullet* b : m_bullets) {
        if (b->IsActive()) {
            continue;                     // 使用中
        }
        b->Reset(position, velocity);     // ★ Start ではなく Reset
        b->Activate();
        return true;
    }
    return false;                         // 全部使用中だった
}
// Bullet 側
void Bullet::Reset(const Vector3& position, const Vector3& velocity)
{
    m_position = position;
    m_velocity = velocity;
    m_lifeTime = 0.0f;
    // ★ Init は呼ばない。Start で1回やってある
}

void Bullet::Update()
{
    m_position += m_velocity * g_gameTime->GetFrameDeltaTime();

    if (IsOutOfScreen()) {
        Deactivate();                     // ★ DeleteGO ではない
        return;
    }
    m_spriteRender.SetPosition(m_position);
    m_spriteRender.Update();
}
DeleteGO を書き残さないでください プールの弾を DeleteGO してしまうと、 m_bullets の中に、解放済みのポインタが残ります。
次に Fire() したときにクラッシュします。原因が非常に分かりにくいバグです。
当たり判定のところも含めて、 DeleteGO を全部 Deactivate() に置き換えてください。

05溢れたらどうするか

やり方向いている場面
撃たない（何もしない） おすすめ。プレイヤーはまず気づかない
いちばん古い弾を消して使う 弾が必ず出てほしい演出
プールを増やす その場で new が走るので、本末転倒ぎみ

ただし、溢れたことに気づける仕掛けは入れてください。 

bool BulletPool::Fire(...)
{
    ...
    // ここに来たら、全部使用中
#ifdef _DEBUG
    static int s_overflowCount = 0;
    s_overflowCount++;
    if (s_overflowCount % 60 == 1) {
        // 出しすぎないように、たまにだけ出す
        OutputDebugStringA("BulletPool: 弾が足りません\n");
    }
#endif
    return false;
}

06どれくらい速くなるのか

推測しないでください。測ってください。 

void Player::Shot()
{
    K2_PROFILE_SCOPE("Shot");       // ★ ここを測る
    ...
}

F1 → Profiler パネルで、 Shot にかかっているミリ秒が見られます。 プール化の前後で比べてください。

思ったほど速くならないことも、よくあります 弾が20発程度なら、プール化しても違いは測れません。 効くのは「毎フレーム何十個も生成・破棄する」場合です。
差が出なかったなら、それは「そこは問題ではなかった」という発見です。 計測の話は LV5 で本格的にやります。

差が出る条件を作る

通常のプレイでは差が測れません。 わざと負荷をかけてください。 

// デバッグ用：毎フレーム50発撃つ
#ifdef _DEBUG
if (g_pad[0]->IsPress(enButtonY)) {
    for (int i = 0; i < 50; i++) {
        Shot();
    }
}
#endif

記録の例

== 毎フレーム50発 ==
                     NewGO版    プール版
Player::Shot          0.42 ms   0.03 ms
フレーム全体          18.1 ms    3.9 ms
FPS                   55         60（上限）
数字が「0.00 ms」なら、測れていないだけです K2_PROFILE_SCOPE は1フレームに数十回までを想定した簡易計測です。 1回が短すぎると 0 に見えます。

その場合はループの外側にスコープを置いて、まとめて測ってください。
Debug ビルドの数字は、あてになりません Debug は最適化が切れているので、何倍も遅く出ます。

比較そのものは Debug でもできますが、 「実際に何msかかるか」を知りたいときは Release で測ってください。

演習3（広げる）

プールの仕組みをテンプレートにして、弾・敵・エフェクトで使い回せるようにする。

解答例を見る（まず自分でやってから） 
// ObjectPool.h
#pragma once
#include <vector>

/// <summary>
/// ゲームオブジェクトを使い回すためのプール。
/// </summary>
/// <remarks>
/// T は IGameObject を継承していること。
/// 生成時に Start() が1回だけ呼ばれ、以降は Activate/Deactivate だけで
/// 貸し出しと返却を行う。
/// </remarks>
template<class T>
class ObjectPool {
public:
    /// <summary>プールを作る。Start() の中から呼ぶこと。</summary>
    void Init(int num, int priority, const char* name)
    {
        m_objects.reserve(num);
        for (int i = 0; i < num; i++) {
            T* obj = NewGO<T>(priority, name);
            obj->Deactivate();
            m_objects.push_back(obj);
        }
    }

    /// <summary>使っていないものを1つ借りる。</summary>
    /// <returns>空きが無ければ nullptr</returns>
    T* Acquire()
    {
        // 前回の続きから探す（毎回先頭から探すと、混んできたとき遅い）
        const int num = (int)m_objects.size();
        for (int i = 0; i < num; i++) {
            m_searchIndex = (m_searchIndex + 1) % num;
            T* obj = m_objects[m_searchIndex];
            if (obj->IsActive() == false) {
                obj->Activate();
                return obj;
            }
        }
        return nullptr;
    }

    int GetNum() const { return (int)m_objects.size(); }

    int GetActiveNum() const
    {
        int n = 0;
        for (T* obj : m_objects) {
            if (obj->IsActive()) { n++; }
        }
        return n;
    }

private:
    std::vector<T*> m_objects;
    int m_searchIndex = 0;
};

使い方

// GameScene.h
private:
    ObjectPool<Bullet>      m_bulletPool;
    ObjectPool<EnemyBullet> m_enemyBulletPool;
    ObjectPool<Explosion>   m_explosionPool;

// GameScene.cpp
bool GameScene::Start()
{
    m_bulletPool.Init(200, enPriority_Bullet, "bullet");
    m_enemyBulletPool.Init(500, enPriority_EnemyBullet, "enemyBullet");
    m_explosionPool.Init(30, enPriority_Effect, "explosion");
    return true;
}

// 撃つとき
Bullet* b = m_bulletPool.Acquire();
if (b != nullptr) {
    b->Reset(position, velocity);
}

m_searchIndex を持っている理由

毎回先頭から探すと、プールが混んでいるときに毎回200回ループします。 前回の続きから探せば、たいてい数回で見つかります。

デバッグパネルに出しておくと便利です 
ImGui::Text("Bullet : %d / %d",
    scene->GetBulletPool().GetActiveNum(),
    scene->GetBulletPool().GetNum());
常に上限に張り付いていたら、プールが小さすぎます。 逆に、200個確保して最大12個しか使っていないなら、 減らしてメモリを節約できます。
プールは万能ではありません 使っていないオブジェクトも、メモリは占有し続けます。 500個の敵弾プールは、ゲーム中ずっと500個分のメモリを持ち続けます。

「毎フレーム大量に作って捨てるもの」にだけ使ってください。 ボスや背景をプールにする意味はありません。

08確認

  1. プールにしたとき、DeleteGO の代わりに何を呼ぶ？
  2. 弾の Init() はどこで呼ぶ？
  3. プールが溢れたとき、おすすめの対応は？
  4. プールにしないほうがよいものは？
答え
  1. Deactivate()。
  2. Start() で1回だけ。撃つたびには呼ばない。
  3. 撃たない（何もしない）。ただし気づけるログは出す。
  4. ボスや背景のように、数が少なく作り直さないもの。 メモリを無駄に占有するだけ。
