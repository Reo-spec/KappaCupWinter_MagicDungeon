GUI自分のデバッグパネルを作る

難易度 ／ 前提 2-13

00入場チェック

  • ラムダ式 [](){} を見たことがある？ → 1-10
  • GameObject List パネルを使ったことがある？ → 2-06

01この章でできるようになること

  • ゲームを動かしたまま、数値を調整できる
  • ボスの状態やHPを画面で確認できる
  • RAII（デストラクタで後片づけ）の考え方が使える
これは「あとで楽をするための投資」です 自機の速度を調整するのに、毎回コードを直してビルドしていたら、 1回の調整に何分もかかります。 スライダーにしておけば、遊びながら1秒で試せます。 調整の回数が10倍こなせれば、ゲームの出来も変わります。

02いちばん短い例

DebugGui::RegisterPanel("Game", "Score", []() {
    ImGui::Text("score = %d", g_score);
});
  • 第1引数：メニューバーでの分類名（好きな名前でよい）
  • 第2引数：パネルの名前（ウィンドウのタイトルになる）
  • 第3引数：中身を描画する関数

ImGui::Begin() / End() は書かなくて大丈夫です。エンジンがやります。 F1 → 分類名 → パネル名 で開けます。

03ゲームオブジェクトの中から作る

ここが大事です。 this をキャプチャしたラムダ式を登録したまま、 そのゲームオブジェクトが死ぬと、 削除済みのメンバ変数を触ってクラッシュします。 2-08 でやった事故と、まったく同じ形です。

DebugGuiPanel をメンバ変数として持つと、 デストラクタで自動的に登録が解除されます。 

// Player.h
class Player : public IGameObject {
public:
    bool Start() override;
    void Update() override;
private:
    float m_speed = 600.0f;
    Vector3 m_position = Vector3::Zero;
    bool  m_isInvincible = false;

    DebugGuiPanel m_debugPanel;      // ★ メンバ変数として持つ
};
// Player.cpp
bool Player::Start()
{
    m_spriteRender.Init("Assets/sprite/player.dds", 64.0f, 64.0f);

    m_debugPanel.Register("Game", "Player", [this]() {
        ImGui::Text("pos  = %.1f, %.1f", m_position.x, m_position.y);
        ImGui::SliderFloat("speed", &m_speed, 100.0f, 2000.0f);
        ImGui::Checkbox("invincible", &m_isInvincible);
        if (ImGui::Button("reset position")) {
            m_position = { 0.0f, -350.0f, 0.0f };
        }
    });
    return true;
}
RAII という考え方 「持っているものが死ぬときに、自動で後片づけをする」 — これを RAII と呼びます。C++では非常によく使われます。
あなたはすでに、GOHandle と DebugGuiPanel という 2つの例を見ています。LV5 の K2_PROFILE_SCOPE も同じ仕組みです。

04よく使う部品

ImGui::Text("hp = %d", hp);                         // 文字
ImGui::SliderFloat("speed", &speed, 0.0f, 2000.0f); // スライダー
ImGui::DragFloat3("position", &pos.x, 1.0f);        // 座標（3つまとめて）
ImGui::Checkbox("invincible", &isInvincible);       // チェックボックス
ImGui::ColorEdit3("color", &color.x);               // 色
if (ImGui::Button("respawn")) { Respawn(); }        // ボタン
ImGui::Separator();                                 // 区切り線
ImGui::SameLine();                                  // 次を同じ行に置く

どんな部品があるか全部見たいときは、メニューの Debug → ImGui Demo を開いてください。 使える部品のカタログになっています。 気になった部品の名前で imgui_demo.cpp を検索すれば、 書き方がそのまま載っています。

05日本語を出したいとき

ImGui に渡す文字列は UTF-8 でなければなりません。 Visual Studio で作ったソースはたいてい Shift-JIS なので、そのままだと文字化けします。 

ImGui::Text("敵の数 = %d", num);        // 文字化けする
ImGui::Text(U8("敵の数 = %d"), num);    // 正しく表示される

U8() で囲んでください。 英数字だけの文字列は素通しされるので、付けておいても害はありません。

06作っておくと便利なパネル

パネル中身
Player速度・連射間隔のスライダー、無敵チェック、位置リセット
Bossいまの状態（Enter/AttackA...）、HPスライダー、状態を強制的に変えるボタン
Debug当たり判定の表示ON/OFF、敵の出現を止めるチェック

とくに「ボスの状態を強制的に変えるボタン」は、作っておくと劇的に楽になります。 第2形態の調整のために毎回ボスのHPを半分まで削るのは、時間の無駄です。 

m_debugPanel.Register("Game", "Boss", [this]() {
    const char* stateNames[] = { "Enter", "AttackA", "AttackB", "Dying" };
    ImGui::Text("state = %s", stateNames[m_state]);
    ImGui::Text("timer = %.2f", m_stateTimer);
    ImGui::SliderInt("hp", &m_hp, 0, m_maxHp);

    ImGui::Separator();
    if (ImGui::Button("-> AttackB")) { ChangeState(enState_AttackB); }
    ImGui::SameLine();
    if (ImGui::Button("-> Dying"))   { ChangeState(enState_Dying); }
});

07提出のときに消す

デバッグ機能を丸ごと消したいときは、 k2EngineLow/dbg/DebugConfig.h の定義をコメントアウトします。 

//#define K2_ENABLE_DEBUG_GUI
だから ImGui:: は登録した関数の中だけに書く Update() の中などに直接 ImGui:: を書くと、 この定義を消したときにクラッシュします。 必ず Register() で登録した関数の中に書いてください。

08演習

演習1（まねる）

自機の速度をスライダーで変えられるようにする。

演習2（増やす）

無敵チェックボックスを作って、当たり判定を無効にできるようにする。 ボスの調整がとても楽になります。

解答例を見る（まず自分でやってから） 
// Player.h
private:
    bool m_isInvincible = false;
    DebugGuiPanel m_debugPanel;

public:
    bool IsInvincible() const { return m_isInvincible; }

// Player.cpp
bool Player::Start()
{
    ...
    m_debugPanel.Register("Game", "Player", [this]() {
        ImGui::SliderFloat("speed", &m_speed, 100.0f, 2000.0f);
        ImGui::Checkbox("invincible", &m_isInvincible);
        ImGui::SetItemTooltip("%s", U8("チェックを入れると被弾しなくなる"));
    });
    return true;
}

被弾する側で、このフラグを見ます。

void Player::TakeDamage(int damage)
{
    if (m_isInvincible) {
        return;              // 無敵なので何もしない
    }
    ...
}
これは本当に効きます ボスの第2形態を調整するのに、毎回やられ直すのは時間の無駄です。 無敵チェックひとつで、調整の速さが何倍にもなります。
ついでに「敵の出現を止める」チェックも作っておくと、 ボスだけを何度も試せるようになります。

演習3（自分で書く）

当たり判定の円を表示するON/OFFを、パネルから切り替えられるようにする。 本文には答えがありません。

解答例を見る（まず自分でやってから）

表示のON/OFFは、全部のオブジェクトで共通にしたいので、 グローバルな変数か static メンバにします。 

// DebugFlags.h
#pragma once

/// <summary>
/// デバッグ表示の切り替え。
/// K2_ENABLE_DEBUG_GUI を消しても、変数は残るので問題ない。
/// </summary>
struct DebugFlags {
    static bool isShowCollision;    // 当たり判定を表示する
    static bool isStopSpawner;      // 敵の出現を止める
};

// DebugFlags.cpp
bool DebugFlags::isShowCollision = false;
bool DebugFlags::isStopSpawner   = false;
// GameScene.cpp — パネルは1か所でまとめて登録する
bool GameScene::Start()
{
    ...
    m_debugPanel.Register("Game", "Debug", []() {
        ImGui::Checkbox("show collision", &DebugFlags::isShowCollision);
        ImGui::Checkbox("stop spawner",   &DebugFlags::isStopSpawner);
    });
    return true;
}
// Enemy.cpp — 使う側
void Enemy::Render(RenderContext& rc)
{
    m_spriteRender.Draw(rc);

    if (DebugFlags::isShowCollision) {
        m_debugCircle.Draw(rc);
    }
}

// EnemySpawner.cpp
void EnemySpawner::Update()
{
    if (DebugFlags::isStopSpawner) {
        return;
    }
    ...
}

ポイント

  • フラグは1か所にまとめる。あちこちに static bool を 置くと、どこにあるか分からなくなります
  • パネルの登録も1か所だけ。敵1体ごとに登録すると、 同じパネルが何十個も作られてしまいます
  • DebugFlags はデバッグGUIが無効でもコンパイルが通ります。 ImGui:: を使っているのはパネルの中だけだからです
グローバルな変数を使ってよいのか？ デバッグ用に限れば、これでよいです。 LV4-12 で「なぜグローバルが嫌われるのか」を学びますが、 そこで扱うのはゲームのロジックの話です。 デバッグ用のフラグは、製品には残らないので事情が違います。

09確認

  1. ゲームオブジェクトの中でパネルを登録するとき、何を使う？ なぜ？
  2. ImGui:: を Update() に直接書いてはいけないのはなぜ？
  3. 日本語を表示するには？
答え
  1. DebugGuiPanel。オブジェクトが死ぬときに、 デストラクタで自動的に登録を解除してくれるから。
  2. デバッグ機能を無効にしたときに、コンテキストが無い状態で呼ばれてクラッシュするから。
  3. U8("...") で囲む。
