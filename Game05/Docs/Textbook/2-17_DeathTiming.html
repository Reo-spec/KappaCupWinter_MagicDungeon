撃破処理と DeleteGO のタイミング設計

難易度 ／ 前提 2-16 , 2-09

00入場チェック

  • DeleteGO した直後、メモリはどうなっている？ → 2-05
  • GOHandle はなぜ安全？ → 2-09

01この章でできるようになること

  • 同じフレームで両方が死んでも壊れないコードが書ける
  • 二重に当たり判定が起きないようにできる
  • 「死ぬ」と「消える」を分けて考えられる

02ありがちな壊れ方

2-15 で書いたコードには、まだ穴があります。 1発の弾が、同じフレームで2体の敵に当たるケースです。 

void Bullet::CheckHitToEnemy()
{
    const auto& enemies = FindGOs<Enemy>("enemy");
    for (auto enemy : enemies) {
        if (IsHit(enemy)) {
            enemy->TakeDamage(1);
            DeleteGO(this);
            return;              // ← ここで抜けているので、実は大丈夫
        }
    }
}

return があるので1体だけです。では、これならどうでしょう。 

// 敵のほうから弾を探す版
void Enemy::CheckHitToBullet()
{
    const auto& bullets = FindGOs<Bullet>("bullet");
    for (auto bullet : bullets) {
        if (IsHit(bullet)) {
            DeleteGO(bullet);       // 弾を消す
            m_hp--;
            if (m_hp <= 0) {
                DeleteGO(this);     // 自分も消す
            }
            // return を書いていない！
        }
    }
}

HPが0になったあとも、ループが続きます。 残りの弾にも当たって、HPは -1、-2 と減り続け、 DeleteGO(this) も何度も呼ばれます。

03本当の問題は「もう死んでいる相手」

04対策1 ― IsDead() を確認する

void Bullet::CheckHitToEnemy()
{
    const auto& enemies = FindGOs<Enemy>("enemy");
    for (auto enemy : enemies) {
        if (enemy->IsDead()) {
            continue;              // ★ もう死んでいる相手は無視
        }
        if (IsHit(enemy) == false) {
            continue;
        }
        enemy->TakeDamage(1);
        DeleteGO(this);
        return;                    // ★ 自分を消したら、すぐ帰る
    }
}

IsDead() は IGameObject が持っている関数です。 「リストには入っているが、もう死んでいる」を見分けられます。

05対策2 ― 「死ぬ」と「消える」を分ける

もう少し丁寧に作るなら、やられた瞬間に消さないという手があります。 

class Enemy : public IGameObject {
public:
    void TakeDamage(int damage);
    bool IsAliveEnemy() const { return m_state == enState_Alive; }
private:
    enum EnState {
        enState_Alive,      // 生きている。当たり判定あり
        enState_Dying,      // やられた。爆発中。当たり判定なし
    };
    EnState m_state = enState_Alive;
    float   m_dyingTimer = 0.0f;
};

void Enemy::TakeDamage(int damage)
{
    if (m_state != enState_Alive) {
        return;                     // もうやられている
    }
    m_hp -= damage;
    if (m_hp <= 0) {
        m_state = enState_Dying;    // すぐには消さない
        m_dyingTimer = 0.4f;
        PlayExplosion();
        AddScore(100);              // スコアはここで1回だけ
    }
}

void Enemy::Update()
{
    if (m_state == enState_Dying) {
        m_dyingTimer -= g_gameTime->GetFrameDeltaTime();
        if (m_dyingTimer <= 0.0f) {
            DeleteGO(this);         // 爆発が終わってから消える
            return;
        }
        return;                     // 動かない
    }
    Move();
}
この書き方の良いところ
  • TakeDamage の先頭で弾くので、何回呼ばれてもスコアは1回
  • 爆発アニメを最後まで見せられる
  • 当たり判定は IsAliveEnemy() で判断できる

ここで出てきた enState_Alive / enState_Dying のような書き方を ステートマシンと呼びます。 2-22 ボスを作る で本格的に使います。

06まとめ：3つの守りかた

守り方いつ使う
DeleteGO(this) の直後に return いつでも。例外なし
相手の IsDead() を確認する FindGOs の結果を回すとき
状態（Alive / Dying）を持つ 爆発を見せたいとき、スコアの二重加算を防ぎたいとき

07動かして確かめる

二重処理はめったに起きないので、わざと起こしてみます。 弾を10発同時に、同じ場所へ撃ってください。

  • 対策する前：スコアが100ではなく、200や300入ることがある
  • 対策したあと：何度やっても100だけ入る
  • GameObject List で、爆発中の敵が Alive のまま残っている

08演習

演習1（再現する）

対策なしのコードで、スコアが二重に入るところを実際に見る。 見られたら、それがこの章の価値です。

解答例を見る（まず自分でやってから）

確実に再現させるコツは、同じ場所に弾を重ねることです。 

// デバッグ用。1回のボタンで10発まとめて、同じ場所に出す。
void Player::ShootDebugBurst()
{
    for (int i = 0; i < 10; i++) {
        Bullet* b = NewGO<Bullet>(enPriority_Bullet, "bullet");
        Vector3 pos = m_position;
        pos.y += 40.0f + i * 2.0f;    // ほんの少しずらす
        b->SetPosition(pos);
    }
}

この状態で、HPが1の敵に撃ち込んでください。 スコアが100ではなく、200や300入ることがあります。

確実に見るには

  • スコアが増えるたびに OutputDebugStringA でログを出す
  • 出力ウィンドウで、1回の撃破に対して何回ログが出るか数える
void GameScene::AddScore(int value)
{
    m_score += value;
    char text[256];
    sprintf_s(text, "AddScore %d -> %d\n", value, m_score);
    OutputDebugStringA(text);
}

1回の撃破で2行出たら、それが二重処理です。

演習2（直す）

IsDead() の確認を入れて、二重処理が起きないことを確認する。

解答例を見る（まず自分でやってから） 
void Bullet::CheckHitToEnemy()
{
    const auto& enemies = FindGOs<Enemy>("enemy");
    for (auto enemy : enemies) {
        if (enemy->IsDead()) {
            continue;              // ★ 追加
        }
        Vector3 diff = enemy->GetPosition() - m_position;
        float radiusSum = RADIUS + enemy->GetRadius();
        if (diff.LengthSq() >= radiusSum * radiusSum) {
            continue;
        }
        enemy->TakeDamage(1);
        DeleteGO(this);
        return;                    // ★ 忘れない
    }
}

これで、さっきのログが1回の撃破につき1行になるはずです。

なぜ IsDead() だけで足りるのか DeleteGO(enemy) された瞬間に m_isDead が true になります。 同じフレームの中でも、すぐに true になっています。 だから、あとから来た弾はこの continue で弾かれます。

演習3（自分で書く）

Dying 状態を入れて、やられた敵が0.4秒かけて小さくなりながら消える ようにする。その間、当たり判定は無くすこと。 本文には答えがありません。

解答例を見る（まず自分でやってから） 
// Enemy.h
private:
    enum EnState { enState_Alive, enState_Dying };
    EnState m_state = enState_Alive;
    float   m_dyingTimer = 0.0f;
    static const float DYING_TIME;

public:
    bool IsAliveEnemy() const { return m_state == enState_Alive; }

// Enemy.cpp
const float Enemy::DYING_TIME = 0.4f;

void Enemy::TakeDamage(int damage)
{
    if (m_state != enState_Alive) {
        return;                      // もうやられている。二重加算を防ぐ
    }
    m_hp -= damage;
    if (m_hp > 0) {
        return;
    }
    m_state = enState_Dying;
    m_dyingTimer = DYING_TIME;
    PlayExplosion();
    AddScore(100);                   // ここで1回だけ
}

void Enemy::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();

    if (m_state == enState_Dying) {
        m_dyingTimer -= dt;
        if (m_dyingTimer <= 0.0f) {
            DeleteGO(this);
            return;
        }
        // 残り時間の割合で、小さくしながら薄くする。
        float rate = m_dyingTimer / DYING_TIME;    // 1.0 → 0.0
        m_spriteRender.SetScale({ rate, rate, 1.0f });
        m_spriteRender.SetMulColor({ 1.0f, 1.0f, 1.0f, rate });
        m_spriteRender.SetPosition(m_position);
        m_spriteRender.Update();
        return;                      // 動かない
    }

    Move();
    ...
}

当たり判定を無くすのは、弾のほうで見ます。

// Bullet.cpp
for (auto enemy : enemies) {
    if (enemy->IsDead() || enemy->IsAliveEnemy() == false) {
        continue;                    // 死亡中は当たらない
    }
    ...
}

これで「爆発は見えるが、もう当たらない」状態が作れます。 ここで書いた enState_ の考え方が、 2-22 ボス でそのまま使えます。

09確認

  1. FindGOs は DeleteGO 済みのオブジェクトを返す？
  2. スコアが二重に入るのを防ぐには？（2つ）
  3. 「死ぬ」と「消える」を分けると、何ができるようになる？
答え
  1. 返す。DEADはリストから外れておらず、次のフレームまで残っている。
  2. 相手の IsDead() を確認する／TakeDamage の先頭で状態を見て弾く。
  3. 爆発アニメを最後まで見せられる。当たり判定だけ先に消せる。
