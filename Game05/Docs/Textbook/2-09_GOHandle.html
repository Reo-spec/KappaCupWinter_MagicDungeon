GOHandle で安全に参照する

難易度 ／ 前提 2-08

00入場チェック

  • 削除済みオブジェクトを触ると、どんな結末がありうる？ → 答えられないなら 2-08 へ戻る
  • nullptr チェックだけでは、なぜ防げない？ → 同上

2-08 で実際にクラッシュさせてから来てください。 痛い目を見ていないと、この章はただの決まりごとに見えます。

01この章でできるようになること

  • 生ポインタをメンバ変数に持たずに、他のオブジェクトを覚えておける
  • 相手が死んでいるかどうかを、毎回安全に確認できる
  • なぜ GOHandle に -> 演算子が無いのかを説明できる

02問題は「ポインタが嘘をつく」こと

前の章で分かったのは、こういうことでした。

DeleteGO は、こちらが持っているポインタ変数を書き換えてくれない。 だからポインタは、指す先が消えたあとも「まだそこにある」という顔をし続ける。

ポインタはただの数字（アドレス）です。 その数字がいま有効かどうかを、ポインタ自身は知りません。 だから「有効かどうかを知っている人」に、毎回聞きに行く必要があります。

知っている人は誰でしょうか。GameObjectManager です。 生き死にを管理しているのは、そいつだからです。

03GOHandle のしくみ

中身は k2EngineLow/gameObject/GOHandle.h にあります。 驚くほど短いです。 

T* Get() const
{
    if (m_instanceId == 0) {
        return nullptr;
    }
    auto gameObjectManager = GameObjectManager::GetInstance();
    IGameObject* gameObject =
        gameObjectManager->FindGameObjectByInstanceID(m_instanceId);
    if (gameObject == nullptr) {
        return nullptr;
    }
    return static_cast<T*>(gameObject);
}

そして FindGameObjectByInstanceID のほうは、 DeleteGO 済み（IsDead()）なら nullptr を返します。 つまり、まだメモリが残っている1フレームの間も、ちゃんと「いない」と答えてくれます。

04書き換える

Before（2-08 で落ちたコード）

class Missile : public IGameObject {
    Enemy* m_target = nullptr;      // 生ポインタで敵を覚えておく
};

void Missile::Update()
{
    // 敵がすでに DeleteGO されていたら、ここで事故る
    Vector3 toTarget = m_target->GetPosition() - m_position;
    ...
}

After

class Missile : public IGameObject {
    GOHandle<Enemy> m_target;       // ハンドルで敵を覚えておく
};

bool Missile::Start()
{
    m_spriteRender.Init("Assets/sprite/missile.dds", 32.0f, 32.0f);
    m_target.Reset(FindGO<Enemy>("enemy"));   // ハンドルに覚えさせる
    return true;
}

void Missile::Update()
{
    Enemy* target = m_target.Get();     // ★ 毎回取り直す
    if (target == nullptr) {
        // 敵はもういない。自分も消える。
        DeleteGO(this);
        return;
    }

    Vector3 toTarget = target->GetPosition() - m_position;
    toTarget.Normalize();
    m_position += toTarget * 400.0f * g_gameTime->GetFrameDeltaTime();

    m_spriteRender.SetPosition(m_position);
    m_spriteRender.Update();
}

何が変わったか

コード説明
GOHandle<Enemy> m_target; ポインタではなくインスタンスIDを覚える
m_target.Reset(...) 覚えさせる。nullptr を渡してもよい
Enemy* target = m_target.Get(); マネージャに問い合わせる。毎回呼ぶのがポイント
if (target == nullptr) 死んでいれば必ず nullptr が返るので、ここで気づける
ローカル変数に受けてから使う m_target.Get() を2回も3回も呼ぶ必要はありません。 関数の先頭で1回だけ受けて、そのあとはローカル変数を使ってください。 1フレームの途中で相手が死ぬことはないので、これで安全です。

05なぜ -> が使えないのか

GOHandle には、わざと operator-> を用意していません。 もしあったら、こう書けてしまいます。 

m_target->GetPosition();     // ← 書けてしまうと、結局チェックを忘れる

これでは、生ポインタのときと何も変わりません。 Get() でいったん受けるしかない形にしておけば、 「そのポインタ、nullかもしれないぞ」と目に入ります。

「面倒くさい」と感じる書き方が、バグを防ぐ ライブラリの設計では、わざと不便にすることがあります。 便利にすると、人は必ず近道をして、間違えるからです。 これは覚えておくと、LV4の設計の話でも効いてきます。

06API 一覧

関数説明
Reset(T* go)参照するオブジェクトを設定する
Get()生きていればアドレス、死んでいれば nullptr
IsAlive()生きているかどうかだけ知りたいとき

07配列で持つときも同じ

2-08 で出てきた「std::vector<Enemy*> に入れっぱなし」も、同じやり方で直せます。 

// Before : 死んだ敵のポインタが残り続ける
std::vector<Enemy*> m_enemies;

// After
std::vector<GOHandle<Enemy>> m_enemies;

void GameScene::Update()
{
    for (auto& handle : m_enemies) {
        Enemy* enemy = handle.Get();
        if (enemy == nullptr) {
            continue;       // もういない
        }
        enemy->DoSomething();
    }

    // 死んだものを配列から取り除く。
    m_enemies.erase(
        std::remove_if(
            m_enemies.begin(), m_enemies.end(),
            [](const GOHandle<Enemy>& h) { return h.IsAlive() == false; }
        ),
        m_enemies.end()
    );
}

08動かして確かめる

  • 敵を倒したあとも、ミサイルがクラッシュしない
  • GameObject List パネルで、敵が消えた次のフレームにミサイルも消える
  • 何度実行しても、同じ結果になる（運に左右されない）

最後のひとつが大事です。2-08 のコードは実行するたび結果が変わりました。 直したコードは、何度やっても同じ動きになります。それが「直った」ということです。

09よくあるエラー

Get() がいつも nullptr を返す

原因1：Reset() を呼び忘れている。
原因2：Start() で FindGO したとき、 相手がまだ作られていなかった。優先度（priority）の順番を確認してください。
直し方：GameObject List パネルで、 相手が本当に生きているか・IDはいくつかを確認する。

error C2664 : 引数を変換できません

原因：Reset() に IGameObject* を渡している。
直し方：FindGO<Enemy>("enemy") のように、型を指定して取得する。

毎フレーム Get() を呼ぶのは遅くないですか？

遅くありません。FindGO（名前で全部を探す）より速いです。 GOHandle はIDで表を引くだけなので、オブジェクトが何個あっても速さが変わりません。 どうしても気になるなら、LV5 で Profiler を使って実際に測ってください。 測らずに「遅そう」で判断しないこと。

10演習

演習1（まねる）

2-08 で書いたミサイルを GOHandle に書き換えて、 敵を倒しても落ちないことを確認する。

演習2（変えてみる）

敵が死んだときミサイルも消すのではなく、 そのまま真っ直ぐ飛び続けるように変える。

解答例を見る（まず自分でやってから） 
void Missile::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();

    Enemy* target = m_target.Get();
    if (target != nullptr) {
        // 相手がいる間だけ、向きを更新する。
        Vector3 toTarget = target->GetPosition() - m_position;
        toTarget.Normalize();
        m_direction = toTarget;
    }
    // 相手がいなくても、覚えた向きに飛び続ける。
    m_position += m_direction * SPEED * dt;

    if (IsOutOfScreen()) {
        DeleteGO(this);
        return;
    }
    ...
}

ポイントは「向きをメンバ変数で覚えておく」ことです。 毎フレーム相手から計算するのではなく、 最後に計算した向きを m_direction に保存しておけば、 相手が消えてもそのまま飛び続けられます。

演習3（自分で書く）

敵が死んだら、いちばん近い別の敵に狙いを切り替えるようにする。 FindGOs<Enemy>("enemy") が使えます。 本文には答えがありません。

解答例を見る（まず自分でやってから） 
void Missile::Update()
{
    Enemy* target = m_target.Get();
    if (target == nullptr) {
        RetargetToNearest();            // 狙いを付け直す
        target = m_target.Get();
    }
    if (target == nullptr) {
        DeleteGO(this);                 // 敵が1体もいない
        return;
    }
    ...
}

void Missile::RetargetToNearest()
{
    const auto& enemies = FindGOs<Enemy>("enemy");

    Enemy* nearest = nullptr;
    float nearestDistanceSq = FLT_MAX;

    for (auto enemy : enemies) {
        if (enemy->IsDead()) {
            continue;                   // 死んでいる相手は選ばない
        }
        Vector3 diff = enemy->GetPosition() - m_position;
        float distanceSq = diff.LengthSq();
        if (distanceSq < nearestDistanceSq) {
            nearestDistanceSq = distanceSq;
            nearest = enemy;
        }
    }
    m_target.Reset(nearest);            // nullptr でもよい
}

気をつけるところ

  • IsDead() の確認を入れる。FindGOs は死んだ相手も返します （2-17）
  • 距離の比較は LengthSq() でよい。平方根は不要です （2-15）
  • Reset(nullptr) は安全です。ハンドルが空になるだけ

演習4（自分のゲームに入れる）

自分のゲームのコードを見直して、 他のゲームオブジェクトを生ポインタで持っているところを全部探し、 GOHandle に置き換える。 これ以降、生ポインタをメンバ変数に持つのは禁止です。

解答例を見る（まず自分でやってから）

探し方

  1. すべての .h で、クラス名* の形のメンバ変数を探す
  2. それがゲームオブジェクト（IGameObject を継承したもの）なら、 GOHandle に置き換える

Visual Studio の「フォルダを指定して検索」（Ctrl+Shift+F）で、 こう検索すると見つけやすいです。

Player*
Enemy*
Bullet*

置き換えなくてよいもの

形理由
関数の中のローカル変数そのフレームで使い捨てるだけなので安全
関数の引数同上
SpriteRender などのメンバゲームオブジェクトではない。自分が持っているもの
SoundSource*（自分で作って自分で消すBGM） 寿命を自分で完全に管理しているなら可。ただしハンドルのほうが安全

迷ったら GOHandle にしてください。 コストはほとんどありません。

11確認

  1. GOHandle はポインタの代わりに何を覚えている？
  2. Get() は誰に問い合わせている？
  3. なぜ GOHandle には -> 演算子が用意されていない？
  4. DeleteGO された直後（まだメモリがある1フレーム）に Get() を呼ぶと、何が返ってくる？
答え
  1. インスタンスID。NewGO のときに割り振られる、使い回されない番号。
  2. GameObjectManager。生き死にを管理している唯一の場所だから。
  3. m_target->Update() と書けてしまうと、 nullptr チェックを忘れるから。 Get() で受け取るしかない形にして、確認を強制している。
  4. nullptr。FindGameObjectByInstanceID が IsDead() を見て、死んでいれば nullptr を返すから。 メモリが残っていても「いない」扱いになる。

12この4章のまとめ

これ以降、守ってほしい3つのルール
  1. 他のゲームオブジェクトは GOHandle で持つ。生ポインタをメンバ変数にしない
  2. DeleteGO(this) の直後は必ず return
  3. 「誰が消す係か」を決めてから書く。消す係はひとりだけ

この3つを守るだけで、k2Engine で起きるクラッシュの大半は消えます。
