01この章でできるようになること

  • ここからシューティングゲームの制作が始まります

これから作るもの 縦スクロールのシューティングゲームです。 2-13 から 2-23 まで、1つのゲームを少しずつ育てていきます。 毎章コミットしてください。LV3以降で、このコードを使います。

02Player クラス

// Player.h
#pragma once

class Player : public IGameObject
{
public:
    bool Start() override;
    void Update() override;
    void Render(RenderContext& rc) override;

    const Vector3& GetPosition() const { return m_position; }

private:
    void Move();
    void ClampToScreen();

private:
    SpriteRender m_spriteRender;
    Vector3      m_position = Vector3::Zero;

    static const float SPEED;           // 1秒に進む距離
};
// Player.cpp
#include "stdafx.h"
#include "Player.h"

const float Player::SPEED = 600.0f;

bool Player::Start()
{
    m_spriteRender.Init("Assets/sprite/player.dds", 64.0f, 64.0f);
    m_position = { 0.0f, -350.0f, 0.0f };    // 下のほうに置く
    return true;
}

void Player::Update()
{
    Move();
    ClampToScreen();

    m_spriteRender.SetPosition(m_position);
    m_spriteRender.Update();
}

void Player::Render(RenderContext& rc)
{
    m_spriteRender.Draw(rc);
}
Update() を短く保つ Update() の中に全部書かず、 Move() ClampToScreen() のように名前をつけて分けます。 Update() を読めば「何をしているか」が一目で分かる状態を保ってください。 これを怠ると、LV4 で出てくる「1000行の Update」になります。

03移動

void Player::Move()
{
    const float dt = g_gameTime->GetFrameDeltaTime();

    Vector3 move = Vector3::Zero;
    move.x = g_pad[0]->GetLStickXF();
    move.y = g_pad[0]->GetLStickYF();

    // 斜めが速くならないように、長さを1にそろえる。
    if (move.LengthSq() > 1.0f) {
        move.Normalize();
    }

    m_position += move * SPEED * dt;
}

LengthSq() は長さの2乗です。 Length() は平方根の計算が入るぶん少し遅いので、 「1より長いか」を調べるだけなら2乗で比べれば充分です。 （1の2乗は1なので、そのまま比べられます）

04画面の外に出さない

void Player::ClampToScreen()
{
    const float LIMIT_X = 960.0f - 32.0f;    // 画面の半分 - 自機の半分
    const float LIMIT_Y = 540.0f - 32.0f;

    m_position.x = max(-LIMIT_X, min(LIMIT_X, m_position.x));
    m_position.y = max(-LIMIT_Y, min(LIMIT_Y, m_position.y));
}

画面は 1920 × 1080、中心が (0,0) なので、 端は ±960 と ±540 です（2-11）。 自機の幅が64なら、半分の32だけ内側で止めれば、はみ出しません。

マジックナンバーを名前にする 960.0f - 32.0f をそのまま書かず、 LIMIT_X という名前をつけました。 「この数字は何か」が名前で分かるようにするのが、読みやすいコードの基本です。

05動かして確かめる

  • スティックで上下左右に動く
  • 斜めに動いても速くならない
  • 画面の端で止まり、はみ出さない
  • GameObject List に player が1個だけある

06よくあるエラー

斜めが速い

原因：Normalize() していない。
直し方：上のコードのように、長さが1を超えたら正規化する。

じわじわ勝手に動く

原因：スティックのあそび（ドリフト）。 手を離しても 0.05 くらいの値が返ってくるパッドがあります。
直し方：小さい値を切り捨てる。 

if (fabsf(move.x) < 0.15f) { move.x = 0.0f; }
if (fabsf(move.y) < 0.15f) { move.y = 0.0f; }

上に動かすと下に行く

原因：Y軸の向きを逆に考えている。
直し方：k2Engine の2Dは上が +Y です。

演習3（自分で書く）

ボタンを押している間だけ低速移動になるようにする （弾幕シューティングによくある操作です）。 本文には答えがありません。

解答例を見る（まず自分でやってから） 
// Player.h
private:
    float m_speed = 600.0f;
    static const float SLOW_RATE;    // 低速時の倍率

// Player.cpp
const float Player::SLOW_RATE = 0.35f;

void Player::Move()
{
    const float dt = g_gameTime->GetFrameDeltaTime();

    Vector3 move = Vector3::Zero;
    move.x = g_pad[0]->GetLStickXF();
    move.y = g_pad[0]->GetLStickYF();
    if (move.LengthSq() > 1.0f) {
        move.Normalize();
    }

    float speed = m_speed;
    if (g_pad[0]->IsPress(enButtonRB1)) {    // 押している間だけ低速
        speed *= SLOW_RATE;
    }
    m_position += move * speed * dt;
}

ポイント

  • IsPress を使う。IsTrigger だと1フレームしか効きません
  • 低速中は当たり判定を表示すると、本物らしくなります。 弾幕シューティングで低速移動があるのは、 細かく避けるためと、判定位置を見せるためです

08確認

  1. なぜ斜め移動で Normalize() が必要？
  2. Length() ではなく LengthSq() を使ったのはなぜ？
  3. Update() を小さい関数に分ける理由は？
答え
  1. XとYを同時に1ずつ足すと、斜めの長さが約1.41になり、速くなってしまうから。
  2. 平方根の計算を省けるから。大小を比べるだけなら2乗のままで足りる。
  3. 何をしているかが読んで分かるようになる。あとで直す場所も見つけやすい。
