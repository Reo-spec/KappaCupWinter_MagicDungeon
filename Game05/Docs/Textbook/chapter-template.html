GOHandle で安全に参照する

難易度 ／ 前提 2-08

00入場チェック

この章に入る前に、次の質問に答えられますか。

  • DeleteGO() を呼んだ直後、そのオブジェクトのメモリはどうなっている？ → 答えられないなら 2-05 へ戻る
  • クラッシュしたとき、コールスタックのどこを見る？ → 答えられないなら 1-18 へ戻る

01この章でできるようになること

  • 生ポインタをメンバ変数に持たずに、他のオブジェクトを覚えておける
  • 相手が死んでいるかどうかを、毎回安全に確認できる

（ここに完成イメージのスクリーンショットかGIFを置く）

02なぜこれが必要なのか

いきなり書き方から入らず、「こういう場面で困る」→「だからこの仕組みがある」 の順で説明します。

前の章で、DeleteGO() はその場ではメモリを解放せず、 「死亡予約」をするだけだと分かりました。 実際に delete されるのは次のフレームの頭です。 この「ズレ」が事故の正体です。

03書いてみる

コードは省略せず全文を載せます。コピペではなく、必ず打ってください。

ダメな書き方

class Missile : public IGameObject {
    Enemy* m_target = nullptr;      // 生ポインタで敵を覚えておく
};

void Missile::Update()
{
    // 敵がすでに DeleteGO されていたら、ここで事故る
    HomingTo(m_target->GetPosition());
}

良い書き方

class Missile : public IGameObject {
    GOHandle<Enemy> m_target;       // ハンドルで敵を覚えておく
};

void Missile::Update()
{
    Enemy* target = m_target.Get();     // 毎回取り直す
    if (target == nullptr) {
        // 敵はもういない。自分も消える。
        DeleteGO(this);
        return;
    }
    HomingTo(target->GetPosition());
}

何をしているのか

コード説明
GOHandle<Enemy> m_target;ポインタではなくインスタンスIDを覚える
m_target.Get()GameObjectManagerに「このIDのオブジェクトはまだ生きている？」と問い合わせる
if (target == nullptr)死んでいれば必ず nullptr が返るので、ここで気づける

04動かして確かめる

  • 敵を倒したあともミサイルがクラッシュしない
  • GameObject List パネルで、敵が消えた次のフレームにミサイルも消える

05よくあるエラー

毎年、学生が実際に出したものをここに追記していきます。

error C2664: 'GOHandle<Enemy>::Reset': 引数 1 を...

原因：Reset() に IGameObject* を渡している。
直し方：FindGO<Enemy>("enemy") のように、型を指定して取得する。

Get() がいつも nullptr を返す

原因：Reset() を呼び忘れているか、渡した相手がすでに死んでいる。
直し方：GameObject List パネルで、相手が本当に生きているか確認する。

06演習

演習1（まねる）

本文どおりにミサイルを書き換えて、敵を倒しても落ちないことを確認する。

演習2（数字を変える）

敵が死んだときミサイルも消すのではなく、まっすぐ飛び続けるように変えてみる。

演習3（自分で書く）

敵が死んだら、いちばん近い別の敵に狙いを切り替えるようにする。 本文には答えがありません。

07確認

次の質問に、声に出して説明できますか。

  1. GOHandle はポインタの代わりに何を覚えている？
  2. なぜ GOHandle には -> 演算子が用意されていない？
答え
  1. インスタンスID。NewGO のときに割り振られる、使い回されない番号。
  2. m_target->Update() と書けてしまうと、nullチェックを忘れるから。 Get() でポインタを受け取るしかない形にして、確認を強制している。
