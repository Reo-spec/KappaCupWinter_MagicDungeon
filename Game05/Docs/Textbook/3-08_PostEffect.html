ポストエフェクトを自作する

難易度 ／ 前提 3-06

01この章でできるようになること

  • 画面全体にかかる効果を自分で作れる
  • レンダーターゲットという考え方が分かる
この章は難しめです ここまでで一度 3-14 に進んでも構いません。 必要になってから戻ってきてください。

02考え方は「画面を1枚の絵として扱う」

ポストエフェクトは、特別な仕組みではありません。

  1. 3Dを画面ではなく、テクスチャに描く
  2. そのテクスチャを貼った画面いっぱいの四角形を描く
  3. そのときのピクセルシェーダで好きな加工をする

やっていることは、いままでのスプライト描画と同じです。 貼る絵が「さっきまで描いていた画面そのもの」になっただけです。

この「描く先のテクスチャ」をレンダーターゲットと呼びます。

03いちばん簡単な作り方 ― 全画面スプライト

エンジンのポストエフェクトの仕組みに手を入れるのは大変です。 まずは「画面いっぱいのスプライトを、いちばん手前に重ねる」 やり方から始めましょう。

これだけでも、画面全体を赤くする・暗くする・白くフラッシュさせる といった演出は全部作れます。 

// ScreenEffect.h
class ScreenEffect : public IGameObject {
public:
    bool Start() override;
    void Update() override;
    void Render(RenderContext& rc) override;

    void Flash(const Vector4& color, float time);

private:
    MySpriteRender m_sprite;
    Vector4 m_color = { 1.0f, 1.0f, 1.0f, 0.0f };
    float   m_timer = 0.0f;
    float   m_totalTime = 0.0f;
};

// ScreenEffect.cpp
bool ScreenEffect::Start()
{
    // 真っ白な1枚の画像を、画面いっぱいに
    m_sprite.Init("Assets/sprite/white.dds",
                  "Assets/shader/sprite.fx",
                  1920.0f, 1080.0f);
    return true;
}

void ScreenEffect::Flash(const Vector4& color, float time)
{
    m_color = color;
    m_timer = time;
    m_totalTime = time;
}

void ScreenEffect::Update()
{
    if (m_timer <= 0.0f) {
        return;
    }
    m_timer -= g_gameTime->GetFrameDeltaTime();
    float rate = max(m_timer / m_totalTime, 0.0f);

    Vector4 c = m_color;
    c.w *= rate;                          // だんだん薄くなる
    m_sprite.SetMulColor(c);
    m_sprite.Update();
}

void ScreenEffect::Render(RenderContext& rc)
{
    if (m_timer <= 0.0f) {
        return;                           // 何も出ていないときは描かない
    }
    m_sprite.Draw(rc);
}

優先度は、UIよりさらに大きくしてください。 

NewGO<ScreenEffect>(enPriority_ScreenEffect, "screenEffect");

// 使うとき
FindGO<ScreenEffect>("screenEffect")->Flash({1.0f, 0.0f, 0.0f, 0.5f}, 0.3f);

04エンジンのポストエフェクトを読む

本格的なポストエフェクトを作りたくなったら、 エンジンのものを読むのがいちばんの近道です。

読む順番ファイルなぜ
1k2Engine/graphics/postEffect/PostEffectComponentBase.h ポストエフェクト1つぶんの型。短い
2postEffect/Fxaa.h/.cpp いちばん単純な実装
3Assets/shader/postEffect/fxaa.fx そのシェーダ
4postEffect/PostEffect.cpp どんな順番でかけているか

PostEffectComponentBase を継承して、 OnInit() と OnRender() を書けば、 エンジンの仕組みに乗った自作ポストエフェクトが作れます。

1つだけ注意 PostEffect クラスに自分のものを足すには、 エンジン側のコードを編集することになります。
エンジンを更新したときに上書きされないよう、 どこを変えたか記録しておいてください。

05作れるもの

効果やり方難しさ
白フラッシュ・赤フラッシュ全画面スプライトやさしい
フェードイン・アウト全画面スプライト（黒）やさしい
白黒・セピア画面テクスチャの色を変換ふつう
周辺を暗くする（ビネット）UVの中心からの距離で暗くするふつう
ぼかし（ブラー）まわりのピクセルを何点か取って平均する難しい
ブルーム明るい部分を抜き出す → ぼかす → 足す難しい

ビネットは、費用対効果がとても高いのでおすすめです。 数行で、画面がぐっと締まります。 

float4 PSMain( PSInput In ) : SV_Target0
{
    float4 color = colorTexture.Sample(Sampler, In.uv) * mulColor;

    // 画面の中心からの距離（0が中心、0.7くらいが四隅）
    float d = length(In.uv - float2(0.5f, 0.5f));

    // 外側ほど暗くする
    float v = smoothstep(0.75f, 0.35f, d);
    color.rgb *= v;

    return color;
}

06演習

演習1（まねる）

ScreenEffect を作って、被弾したときに画面を赤くフラッシュさせる。

演習2（作る）

ビネット（画面の四隅が暗くなる効果）を、全画面スプライトで作る。

解答例を見る（まず自分でやってから）

全画面スプライトに、上のビネットのシェーダを使います。 ただし「元の画面の色」は取れないので、 乗算合成を使って後ろを暗くします。 

// vignette.fx
float4 PSMain( PSInput In ) : SV_Target0
{
    float d = length(In.uv - float2(0.5f, 0.5f));
    float v = smoothstep(0.78f, 0.35f, d);      // 中心1.0 → 四隅0.0

    // 乗算合成なので、白いところは変化なし、黒いところが暗くなる
    return float4(v, v, v, 1.0f);
}
// C++
SpriteInitData initData;
initData.m_ddsFilePath[0] = "Assets/sprite/white.dds";
initData.m_fxFilePath     = "Assets/shader/vignette.fx";
initData.m_width  = 1920;
initData.m_height = 1080;
initData.m_alphaBlendMode = AlphaBlendMode_Multiply;   // ★ 乗算
m_sprite.Init(initData);

調整のポイント

  • 0.78f … どこから暗くなり始めるか。大きくすると効果が弱まる
  • 0.35f … どこで完全に暗くなるか
  • やりすぎると画面が見づらくなります。四隅がうっすら暗いくらいで充分
これがポストエフェクトの入り口です 「画面いっぱいの四角を、合成モードを変えて重ねる」 — これだけで、かなりの表現ができます。
本格的なポストエフェクト（ブルームなど）は、 画面を一度テクスチャに描いてから加工する点が違うだけで、 考え方は同じです。

演習3（読む）

k2Engine/graphics/postEffect/Fxaa.h と Assets/shader/postEffect/fxaa.fx を読んでみる。全部分からなくてよい。「画面テクスチャを受け取って、加工して、書き出している」という流れが追えれば充分。

解答例を見る（まず自分でやってから）

見るべきポイント

見るもの何が分かるか
OnInit()レンダーターゲットとスプライトを用意している
OnRender()スプライトを1枚描いているだけ
IsCopyResultTextureToMainRenderTarget() 結果をメインの画面に戻すかどうか
fxaa.fx の cbuffer register(b1) で画面サイズを受け取っている

いちばんの発見は、「ポストエフェクトもスプライトを1枚描いているだけ」 だと分かることです。

そして PostEffect.cpp の Render() を見ると、 かける順番がそのまま書いてあります。 

m_ssr.Render(rc, mainRenderTarget);              // 映り込み
m_calsSceneLuminance.Render(rc, mainRenderTarget); // 画面の明るさを測る
m_bloom.Render(rc, mainRenderTarget);            // ブルーム
m_tonemap.Render(rc, mainRenderTarget);          // トーンマップ
...
m_dof.Render(rc, mainRenderTarget);              // 被写界深度
m_fXaa.Render(rc, mainRenderTarget);             // アンチエイリアス

順番には意味があります。 たとえばFXAA（ギザギザ取り）はいちばん最後です。 先にかけても、あとの処理でまたギザギザが生まれてしまうからです。

読めた、という事実が大事です 1年前のあなたには、このファイルは暗号だったはずです。 いまは「何をしているか」が追える。それが LV3 の成果です。

07確認

  1. ポストエフェクトは、何をしている？
  2. レンダーターゲットとは？
  3. 画面を暗くするには、どの合成モード？
答え
  1. 3Dを描いた結果のテクスチャを、画面いっぱいの四角に貼って、 そのピクセルシェーダで加工している。
  2. 「描く先のテクスチャ」。画面の代わりに、ここに描いておく。
  3. 乗算（AlphaBlendMode_Multiply）。
