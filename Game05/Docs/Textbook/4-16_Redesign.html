LV4 設計 ／ 4-16

【制作課題】自分のシューティングを設計し直す

難易度 ／ 前提 4-01 , 4-14

行き詰まったら、完成形を見てください Sample/Goal_LV4 に、 この章に到達した状態のプロジェクトが入っています。
先に見てしまっても構いません。 読んで理解してから、自分のコードに戻ってください。
読む順番は Goal_LV4/readme.txt に書いてあります。 Sample/Goal_LV2 と2つ並べて開いて、同じファイルを見比べるのがいちばん早いです。

01やること

ゲームの遊びを1ミリも変えずに、中身を作り替えます。

3-14 は「見せ方」を変えました。 今回は見た目も遊びも変えません。

これが LV4 のゴールです 「外から見て何も変わっていないのに、中身がまるで違う」 という状態を作れること。
これができる人は、現場で最初から戦力になります。

02進め方 ― 順番が大事です

手順やること章
0 ブランチを切る。いまの数字を測る 4-15、 4-01
1計算を GameRule に切り出し、テストを書く 4-14
2マジックナンバーを定数に 4-01
3早期リターン、関数の切り出し 4-13
4メンバを private に、専用の関数を作る 4-02
5敵の動きを Strategy に 4-09
6生成を Factory に、表にする 4-10
7弾をプールに 4-06
8スコアや音を Observer に 4-08
9ボスを State に 4-05
10もう一度、数字を測る 4-01
1と2を先にやる理由 テストが先にあると、以降の作業が全部安全になります。 マジックナンバーの整理も、 あとの作業で数値を見失わないための下ごしらえです。
いきなり5番から始めないでください。

03ルール

  1. 遊びを変えない。バランス調整もしない
  2. 機能を足さない。やりたくなってもメモに書くだけ
  3. 1ステップごとに、ビルド・実行・コミット
  4. テストが通らなくなったら、先に進まない
  5. 全部やらなくてよい。できたところまでで構わない
2番がいちばん守れません 整理していると、必ず「ここ、こうしたら面白いのに」と思います。 それを我慢するのが、この課題の訓練です。
思いついたことは IDEAS.txt に書いて、 この課題が終わってからやってください。

04達成の目安

  • 整理の前と後で、遊んだ感じが変わっていない
  • テストが全部通っている
  • いちばん長い関数が 50行以下
  • いちばんメンバが多いクラスが 15個以下
  • ネストが3段以下
  • 敵を1種類足すのに、既存ファイルを1つしか触らない
  • 弾を1000発出しても 60FPS
  • コミットが機能単位で分かれている
  • 整理の前後で数字を記録した

06演習

演習1（下ごしらえ）

手順0〜2をやる。ブランチを切り、数字を測り、GameRule とテストを作り、マジックナンバーを整理する。

演習2（作り替える）

手順3〜9から、自分のコードでいちばん困っているもの3つを選んでやる。全部やらなくてよい。

解答例を見る（まず自分でやってから）

選び方 ― 自分の症状から選ぶ

いちばん困っていることやるべき手順
Player.cpp が長すぎて読めない 3 → 4 → （4-07）
敵を足すのが面倒5 → 6
弾を出すと重い7

迷ったらこの3つ

  1. 手順3（関数の切り出し） — 効果が大きく、失敗しにくい
  2. 手順5〜6（Strategy + Factory） — 敵の追加が劇的に楽になる
  3. 手順8（Observer） — 依存が減り、設計の話ができるようになる

この履歴そのものが、成果物です 面接で git log を見せられると、非常に強いです。

「小さく刻んで、常に動く状態を保ちながら作り替えられる」 というのは、コードの見た目以上に評価される能力です。
詰まったら、そのステップを飛ばしてください 「Observer にしようとしたが、うまく分けられなかった」 というのも、記録に残す価値のある結果です。

なぜ難しかったのかを書いておけば、それも立派な考察です。 無理に完成させるより、正直に書いてください。

== 敵「Bomber」を追加する作業 ==

【リファクタ前】
1. Enemy を継承した BomberEnemy.h / .cpp を新規作成（180行コピペ）
2. Spawner.cpp の switch に1行
3. BossStage.cpp の switch に1行
4. DebugPanel.cpp の switch に1行
5. Game.vcxproj にファイル追加
所要: 40分。3の追加を忘れて、ボスステージに出ないバグ。

【リファクタ後】
1. EnemyFactory.cpp の enum に1行
2. ENEMY_TABLE に1行
所要: 3分。static_assert があるので、片方忘れるとビルドが止まる。
数字が改善していなくても、失敗ではありません 「ファイル数は8個に増えた」というのも、正直に書いてください。

トレードオフを認識しているということが伝わります。 「全部良くなりました」より、ずっと信用されます。

最後に ― 遊んで確かめる

数字を測ったら、必ず一度、最初から最後まで遊んでください。

  • 整理する前と、同じ感触か
  • 気づかないうちに変わったところはないか
  • テストが拾えなかった変化はないか

「外から見て何も変わっていない」を、自分の目で確認します。 これができたら、LV4 は達成です。
