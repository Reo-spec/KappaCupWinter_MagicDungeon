02なぜクラスを分けるのか

ここまでは Game.cpp の中だけに書いてきました。 でも、自機・敵・弾・背景・UI を全部そこに書いたらどうなるでしょうか。 

void Game::Update()
{
    // 自機の処理 30行
    // 敵の処理 50行
    // 弾の処理 40行
    // 背景の処理 20行
    // UIの処理 30行
    // ... 気づけば1000行
}

どこを直せばいいのか分からなくなります。 だから「もの」ごとにクラスを分けます。 自機は Player、敵は Enemy、弾は Bullet。

03作ってみる

プロジェクトに Player.h と Player.cpp を追加します。 （ソリューションエクスプローラーで Game を右クリック → 追加 → 新しい項目） 

// Player.h
#pragma once

class Player : public IGameObject
{
public:
    bool Start() override;
    void Update() override;
    void Render(RenderContext& rc) override;

private:
    SpriteRender m_spriteRender;
    Vector3      m_position = Vector3::Zero;
};
// Player.cpp
#include "stdafx.h"
#include "Player.h"

bool Player::Start()
{
    m_spriteRender.Init("Assets/sprite/player.dds", 64.0f, 64.0f);
    return true;
}

void Player::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();
    m_position.x += 200.0f * dt;

    m_spriteRender.SetPosition(m_position);
    m_spriteRender.Update();
}

void Player::Render(RenderContext& rc)
{
    m_spriteRender.Draw(rc);
}
override は必ず書く override と書いておくと、関数名を打ち間違えたときにコンパイルエラーになります。 書かないと、エンジンが呼んでくれない別の関数が黙って作られ、 「なぜか Update が呼ばれない」という原因不明のバグになります。

04動かす ― NewGO

クラスを書いただけでは動きません。NewGO で作ってはじめて動きます。 

// Game.cpp
#include "Player.h"

bool Game::Start()
{
    NewGO<Player>(1, "player");
    return true;
}
引数意味
<Player>どのクラスを作るか
1優先度。処理順・描画順が決まる（2-04）
"player"名前。あとで FindGO で探すときに使う

NewGO は作ったオブジェクトのアドレスを返しますが、 使わないなら受け取らなくて構いません。 受け取ってメンバ変数にしまうときは、2-09 の GOHandle を使ってください。

05できたことの確認

F1 → GameObject → GameObject List を開くと、 player が一覧に出ているはずです。

  • 一覧に player がある
  • State が Alive になっている
  • 画面にスプライトが出て、右に動いている

06よくあるエラー

error C2504: 'IGameObject': 基底クラスが未定義です

原因：#include "stdafx.h" を書いていない。
直し方：.cpp のいちばん上に書く。 2行目以降ではダメです。

Update() が呼ばれない

原因1：NewGO し忘れ。GameObject List に出ていないはずです。
原因2：Start() が true を返していない。 State が Starting のままになります。
原因3：関数名の打ち間違い。override を書いていれば防げます。

画面に何も出ない

原因：Render() で Draw() を呼んでいない、 または Update() で m_spriteRender.Update() を呼んでいない。
直し方：両方必要です。片方だけでは出ません。

07演習

演習1（まねる）

上の Player を作って、画面に出して動かす。

演習2（増やす）

NewGO<Player> を3回呼んで、3つ出してみる。 GameObject List で3つになっていることを確認する。 （全部同じ場所に重なるはずです。なぜでしょう？）

解答例を見る（まず自分でやってから） 
bool Game::Start()
{
    NewGO<Player>(1, "player");
    NewGO<Player>(1, "player");
    NewGO<Player>(1, "player");
    return true;
}

3つとも同じ場所に重なります。 m_position の初期値が全部 Vector3::Zero で、 同じ速さで同じ向きに動くからです。

ここが大事なところです。 クラスは「設計図」で、NewGO するたびに 別々のメンバ変数を持ったインスタンスが作られます。 位置を変えれば、ちゃんと別々に動きます。 

Player* p1 = NewGO<Player>(1, "player");
p1->SetPosition({ -300.0f, 0.0f, 0.0f });

Player* p2 = NewGO<Player>(1, "player");
p2->SetPosition({  300.0f, 0.0f, 0.0f });

GameObject List を見ると、同じ名前の player が3つ並び、 IDだけが違うことが確認できます。

演習3（自分で書く）

Enemy クラスを自分で作って、Player とは違う動きをさせる。 本文には答えがありません。

解答例を見る（まず自分でやってから） 
// Enemy.h
#pragma once

class Enemy : public IGameObject
{
public:
    bool Start() override;
    void Update() override;
    void Render(RenderContext& rc) override;
private:
    SpriteRender m_spriteRender;
    Vector3      m_position = Vector3::Zero;
    float        m_timer = 0.0f;
};

// Enemy.cpp
bool Enemy::Start()
{
    m_spriteRender.Init("Assets/sprite/enemy.dds", 64.0f, 64.0f);
    return true;
}

void Enemy::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();
    m_timer += dt;

    // 左右に揺れながら下がる
    m_position.x = sinf(m_timer * 2.0f) * 300.0f;
    m_position.y -= 100.0f * dt;

    m_spriteRender.SetPosition(m_position);
    m_spriteRender.Update();
}

void Enemy::Render(RenderContext& rc)
{
    m_spriteRender.Draw(rc);
}

大事なのは動きの内容ではなく、「Playerと同じ形で書ける」と気づくことです。 IGameObject を継承して、Start/Update/Render を書いて、 NewGO する。これがk2Engineでのものの作り方です。

08確認

  1. クラスを書いただけでは動かない。何が必要？
  2. override を書く理由は？
  3. NewGO の3つの引数はそれぞれ何？
答え
  1. NewGO でインスタンスを作ること。
  2. 関数名を打ち間違えたときに、コンパイルエラーで気づけるから。
  3. クラス名（テンプレート引数）／優先度／名前。
