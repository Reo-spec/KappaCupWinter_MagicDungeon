はじめての改造

難易度 ／ 前提 1-01

01この章でできるようになること

  • コードを書き換えて、画面の変化を確かめられる
  • 「書き換える → ビルド → 実行」のリズムを体で覚える

02いま動いているコードを見る

ソリューションエクスプローラーから Game.cpp を開いてください。 全部でこれだけです。 

#include "stdafx.h"
#include "Game.h"

bool Game::Start()
{
    m_modelRender.Init("Assets/modelData/unityChan.tkm");
    return true;
}

void Game::Update()
{
    m_modelRender.Update();
}

void Game::Render(RenderContext& rc)
{
    m_modelRender.Draw(rc);
}

いまは細かい意味が分からなくて大丈夫です。 次の3つだけ覚えてください。

ここいつ動くか
Start() の { } の中 最初に1回だけ
Update() の { } の中 1秒間に約60回、ずっと
Render() の { } の中 画面に描くとき

この先しばらく、あなたが書くコードは全部この { } の中です。

03改造1 ― 位置を変える

Game.h を見ると、m_pos という変数があります。 これを使って、キャラクターの位置を変えてみます。 

bool Game::Start()
{
    m_modelRender.Init("Assets/modelData/unityChan.tkm");

    m_pos.x = 100.0f;                    // ← 足す
    m_modelRender.SetPosition(m_pos);    // ← 足す

    return true;
}

F5 を押してください。キャラクターが右にずれたはずです。

100.0f を -100.0f や 300.0f に変えて、 何度か試してみてください。y や z でも試してみましょう。

100.0f の f は何？ 「これは小数の数字だよ」という印です。付け忘れても動くことが多いのですが、 C++では付けるのが作法です。理由は 1-06 で。

04改造2 ― 動かす

Update() は毎フレーム呼ばれます。 ここで少しずつ位置を足せば、動いて見えます。 

void Game::Update()
{
    m_pos.x += 1.0f;                     // ← 足す
    m_modelRender.SetPosition(m_pos);    // ← 足す

    m_modelRender.Update();
}

+= は「いまの値に足す」という意味です。 1秒に60回呼ばれるので、1秒でだいたい60進みます。

これがゲームの動きの正体です。 パラパラ漫画のように、少しずつ位置を変えたものを、 1秒に60枚描いているだけなのです。

05改造3 ― モデルを変える

Game/Assets/modelData/ の中を見てください。 .tkm というファイルがモデルです。別のものに変えてみましょう。 

m_modelRender.Init("Assets/modelData/別のモデル.tkm");
わざと間違えてみてください 存在しないファイル名を書いて実行すると、どうなるでしょうか。 次の章で、その「エラーの読み方」をやります。 いま一度、わざと壊してみるのはよい練習です。（Gitがあるので戻せます）

06ビルドと実行のショートカット

キー動作
F5ビルドして、デバッグ実行する（いちばん使う）
Ctrl+Shift+Bビルドだけする（実行しない）
Shift+F5実行を止める
Ctrl+S保存。保存しないとビルドに反映されません

「書き換える → F5 → 見る」を、何十回も繰り返すことになります。 手がおぼえるまで、たくさん試してください。

07演習

演習1（まねる）

改造1〜3を全部やって、それぞれ画面が変わることを確認する。

演習2（変えてみる）

キャラクターが上に向かって動くようにする。また、もっと速く動くようにする。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    m_pos.y += 3.0f;                     // y を増やすと上へ。数字を大きくすると速く
    m_modelRender.SetPosition(m_pos);
    m_modelRender.Update();
}

3Dでは、y が上下、x が左右、z が奥行きです。

数字を 10.0f にすると、1秒で600も進むので、あっという間に画面の外へ消えます。 消えてしまっても、プログラムは動き続けています。 見えないだけで、ずっと足し算をしています。

演習3（考える）

Update() ではなく Start() に m_pos.x += 1.0f; を書くと、どうなるでしょうか。予想してから試してください。

解答例を見る（まず自分でやってから）

1回しか実行されないので、少し右にずれるだけで、動きません。

呼ばれる回数結果
Start()1回だけ1.0 だけずれて止まる
Update()毎フレーム（1秒に約60回）どんどん動く

この違いが、これからずっとついて回ります。

  • 1回だけやりたいこと（画像の読み込み、初期位置）→ Start()
  • 毎回やりたいこと（動かす、入力を見る、当たり判定）→ Update()

「動かないんだけど」という相談のかなりの割合が、 Update() に書くべきものを Start() に書いている というものです。

08確認

  1. Start() と Update() は、それぞれ何回呼ばれる？
  2. += はどういう意味？
  3. ものが動いて見えるのは、なぜ？
答え
  1. Start() は最初に1回だけ。Update() は1秒に約60回ずっと。
  2. いまの値に足す。a += 1 は a = a + 1 と同じ。
  3. 毎フレーム少しずつ位置を変えたものを、1秒に60回描き直しているから。
