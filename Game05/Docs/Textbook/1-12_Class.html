02バラバラの変数はつらい

敵を3体出したいとします。変数だけで書くと、こうなります。 

float enemy1X, enemy1Y; int enemy1Hp;
float enemy2X, enemy2Y; int enemy2Hp;
float enemy3X, enemy3Y; int enemy3Hp;

10体になったら書けません。 そもそも「この3つはセットだ」ということが、コードから読み取れません。

03構造体 ― データをまとめる

struct Enemy
{
    float x  = 0.0f;
    float y  = 0.0f;
    int   hp = 100;
};      // ★ この「;」を忘れない

これで Enemy という新しい型ができました。 int や float と同じように使えます。 

Enemy e;
e.x  = 100.0f;      // 「.」でメンバにアクセス
e.hp = 50;

std::vector<Enemy> enemies;    // 何体でも持てる
enemies.push_back(e);
閉じカッコのあとのセミコロン }; の ; を忘れると、 意味の分からないエラーが大量に出ます （1-05 の C2143）。 関数の } には要らないのに、構造体とクラスには要ります。

04クラス ― データと処理をまとめる

クラスは、構造体に「処理（関数）」も入れられるようにしたものです。 

class Enemy
{
public:
    void TakeDamage(int damage)
    {
        m_hp -= damage;
        if (m_hp < 0) {
            m_hp = 0;
        }
    }
    bool IsAlive() const { return m_hp > 0; }

private:
    float m_x  = 0.0f;
    float m_y  = 0.0f;
    int   m_hp = 100;
};
Enemy e;
e.TakeDamage(30);          // 呼べる
bool alive = e.IsAlive();  // 呼べる

e.m_hp = 999;              // ★ エラー。private なので外から触れない

05public と private

指定意味
public:外から使える
private:そのクラスの中からしか使えない

基本は「データは private、操作は public」です。

なぜ隠すのか m_hp を public にすると、 世界中のどこからでも書き換えられます。
「なぜかHPがマイナスになる」とき、 public なら全部のコードを疑わなければいけません。 private なら、そのクラスの中だけ見ればよいのです。
これをカプセル化と呼びます。 LV4-02 で本格的に扱います。

ちなみに struct と class の違いは、 何も書かないときが public か private か だけです。慣習として、こう使い分けます。

使いどころ
structデータを入れるだけの、単純な入れ物
class処理を持ち、中身を隠したいもの

07コンストラクタとデストラクタ

class Enemy
{
public:
    Enemy()                     // 生まれたとき
    {
        OutputDebugStringA("敵が生まれた\n");
    }
    ~Enemy()                    // 消えるとき
    {
        OutputDebugStringA("敵が消えた\n");
    }
};

自分で呼ぶものではありません。 作られたとき・消えるときに、C++が勝手に呼びます。

デストラクタは「後片づけ」の場所です 「自分が確保したものを、自分で返す」のに使います。 この考え方は、この先とても大事になります。 （1-15、 2-19、 2-23）

08演習

演習1（まねる）

Enemy 構造体を作って、std::vector<Enemy> に3体入れる。全部のHPの合計を表示する。

演習2（守る）

Enemy をクラスにして、m_hp を private にする。TakeDamage() と GetHp() を作って、HPがマイナスにならないようにする。

解答例を見る（まず自分でやってから） 
class Enemy
{
public:
    void TakeDamage(int damage)
    {
        m_hp -= damage;
        if (m_hp < 0) {
            m_hp = 0;          // ★ ここで必ず守られる
        }
    }
    int  GetHp() const  { return m_hp; }
    bool IsAlive() const { return m_hp > 0; }

private:
    int m_hp = 100;
};
これがカプセル化の価値です m_hp が public だったら、 世界中のどこかで e.m_hp -= 50; と書かれた瞬間、 マイナスになりえます。
private にして TakeDamage() しか入口が無ければ、 「HPは絶対にマイナスにならない」と保証できます。
これを「不変条件を守る」と言います。 LV4-02 のテーマです。

演習3（確かめる）

コンストラクタとデストラクタに OutputDebugStringA を入れて、いつ呼ばれるかを出力ウィンドウで確認する。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    if (g_pad[0]->IsTrigger(enButtonA)) {
        Enemy e;                          // ここで生まれる
        OutputDebugStringA("--- 中 ---\n");
    }                                     // ← ここで消える（スコープを抜ける）
}

出力はこうなります。

敵が生まれた
--- 中 ---
敵が消えた

{ } を抜けた瞬間に、自動でデストラクタが呼ばれています。

std::vector に入れた場合も試してみてください。 push_back したときにコピーが作られ、 clear() したときにまとめて消えるのが分かります。

この「自動で後片づけされる」がC++の武器です Javaや C# では、いつ消えるか分かりません（ガベージコレクタ任せ）。 C++は「{ } を抜けたら必ず消える」と決まっています。
この性質を利用したのが RAII という考え方です。 2-23 で実際に使います。

09確認

  1. 構造体・クラスの定義のあとに必要なものは？
  2. メンバ変数を private にする理由は？
  3. デストラクタはいつ呼ばれる？
答え
  1. セミコロン（};）。
  2. 外から勝手に書き換えられないようにするため。 バグが起きたとき、そのクラスの中だけ見ればよくなる。
  3. そのオブジェクトが消えるとき。 ローカル変数なら { } を抜けたとき。
