01完成の条件

下の項目が全部できていれば合格です。 見た目の派手さや、面白さは問いません。

遊べること

  • タイトル画面から始まり、ボタンでゲームが始まる
  • 自機を操作して、弾が撃てる
  • 敵が出てきて、倒すとスコアが入る
  • 敵か敵弾に当たると、残機が減る
  • 残機が0でゲームオーバー、リザルト画面に行く
  • リザルトからタイトルに戻れる
  • ボスがいて、倒すとクリアになる

作りとして正しいこと

  • 他のゲームオブジェクトを生ポインタで持っていない（全部 GOHandle）
  • DeleteGO(this) の直後に必ず return がある
  • 優先度が enum で管理されている。数字の直書きがない
  • 時間に関わる処理に、すべてデルタタイムが掛かっている
  • 3分遊んで、GameObject List の Alive が増え続けない
  • タイトルへ5往復しても、オブジェクト数が元に戻る
  • 音とエフェクトが入っている
  • 使った素材の利用規約を確認した
  • Assets/CREDITS.txt に素材の出どころを書いた（素材の用意のしかた）
  • 調整用のデバッグパネルが1つ以上ある

残しておくこと

  • Gitにコミットされている（LV3以降でこのコードを使います）
  • ビルドが通る状態で、x64/Debug などの中間ファイルは含めない

02自分でチェックする手順

提出する前に、自分でこの順にやってください。

  1. 3分間、普通に遊ぶ。GameObject List を開いたまま。 Alive が増え続けていないか見る
  2. わざと下手に遊ぶ。わざとやられる、端にずっと張り付く、 ボタンを連打する
  3. タイトル ⇄ ゲーム を5往復する。数が元に戻るか
  4. Release ビルドでも動くか確かめる。 Debug でしか動かない作品は、提出できません
  5. 別のPCで動かす。アセットのパスを間違えていると、ここで分かります
4番と5番を飛ばさないこと 毎年いちばん多いのが「自分のPCのDebugでしか動かない」です。 提出の直前ではなく、いま確かめてください。
