LV4 設計 ／ 4-02

カプセル化

難易度 ／ 前提 4-01

01この章でできるようになること

  • なぜ public だとまずいのかを説明できる
  • ただの getter/setter を並べるのが解決でないと分かる
  • const を正しく付けられる

02問題は「書き換えた犯人が分からない」こと

class Player : public IGameObject {
public:
    Vector3 m_position;      // ★ public
    int     m_hp;            // ★ public
    bool    m_isInvincible;  // ★ public
};

ある日、HPが勝手に減るバグが出たとします。 犯人を探そうとして、こう検索します。 

m_hp

47件ヒットしました。 そのうちどれが書き換えていて、どれが読んでいるだけなのか、 1件ずつ目で見るしかありません。 

class Player : public IGameObject {
public:
    int GetHp() const { return m_hp; }
    void Damage(int amount);        // ★ 減らせるのはここだけ

private:
    int m_hp = 100;
};

こう書いてあれば、犯人は Damage() の中にしかいません。 調べる範囲が47か所から1か所になります。

カプセル化の目的は「隠すこと」ではありません 「変わりうる場所を、1か所に閉じ込めること」です。
隠すのは手段で、デバッグしやすくするのが目的です。

03ただ getter/setter を並べても、意味がありません

// これは、public とほとんど同じです
class Player {
public:
    int  GetHp() const { return m_hp; }
    void SetHp(int hp) { m_hp = hp; }   // ★ 誰でも好きな値を入れられる

private:
    int m_hp;
};

SetHp() があるなら、 結局どこからでも書き換えられます。 検索する名前が m_hp から SetHp に変わっただけです。

大事なのは、「何を」ではなく「どうしたいか」で関数を作ることです。

ダメな作り方（データが主語）よい作り方（やりたいことが主語）
SetHp(GetHp() - 10) Damage(10)
SetHp(100) FullHeal()
SetIsInvincible(true) BeginInvincible(2.0f)
SetPosition(GetPosition() + v) MoveBy(v)

Damage(10) なら、中でまとめて面倒を見られます。 

void Player::Damage(int amount)
{
    if (m_isInvincible) {
        return;                       // 無敵中は無効
    }
    m_hp -= amount;
    if (m_hp < 0) {
        m_hp = 0;                     // マイナスにしない
    }

    BeginInvincible(1.0f);            // 無敵時間
    // 演出もここで
}

SetHp() 方式だと、 この「ついでにやること」を、呼び出し側が毎回書くことになります。 そして、どこかで書き忘れます。

04setter が要る場合もあります

「設定」は setter で構いません。 生成した直後に一度だけ渡すような値です。 

Enemy* e = NewGO<Enemy>(enPriority_Enemy, "enemy");
e->SetPosition({ 100.0f, 0.0f, 0.0f });    // ★ これはよい
e->SetHp(50);                              // ★ 初期値ならよい

問題なのは、ゲーム中にずっと書き換わり続ける値に setter を付けることです。

setter でよい専用の関数にする
いつ使う生成直後の設定ゲーム中ずっと
例初期位置、初期HP、色 ダメージ、回復、移動
ついでの処理無いある

05const を付ける

1-17 でやった const を、 ここで使います。 

// 読むだけの関数には const を付ける
const Vector3& GetPosition() const { return m_position; }
int  GetHp()   const { return m_hp; }
bool IsDeadNow() const { return m_hp <= 0; }
書き方意味
int GetHp() const この関数はメンバを書き換えない
const Vector3& GetPosition() 返したものを、呼び出し側が書き換えられない
void Damage(int amount) const を付けない。書き換える関数だから
参照を返すときは、必ず const を付けてください 
// 危ない：外から書き換えられる
Vector3& GetPosition() { return m_position; }

// 呼び出し側で、これができてしまう
player->GetPosition().x = 9999.0f;    // ★ private の意味がない
const Vector3& にすれば、これはコンパイルエラーになります。

06どこまでやるか

全部を private にする必要はありません。 判断の目安はこうです。

そのメンバは…どうする
ほかのクラスから書き換えられる private ＋ 専用の関数
ほかのクラスから読まれるだけ private ＋ const getter
そのクラスの中でしか使わない private。getter も要らない
3つめがいちばん多いはずです タイマー、内部状態、演出用の変数。 これらに getter を付けている人が多いのですが、 ほとんどは誰も使っていません。
使われていない getter は消してください。 クラスの「外から見える顔」が小さいほど、扱いやすくなります。

07演習

演習1（直す）

Player のメンバ変数を全部 private にして、ビルドが通るところまで直す。

演習2（置き換える）

SetHp() を消して、Damage() と Heal() にする。無敵時間の処理を Damage() の中に入れる。

解答例を見る（まず自分でやってから） 
// Player.h
class Player : public IGameObject {
public:
    bool Start()  override;
    void Update() override;

    //----- 外から使うもの -----
    int  GetHp() const { return m_hp; }
    bool IsAlive() const { return m_hp > 0; }

    /// <summary>ダメージを与える。無敵中は何も起きない。</summary>
    void Damage(int amount);
    /// <summary>回復する。最大HPは超えない。</summary>
    void Heal(int amount);

    //----- 生成直後に一度だけ使うもの -----
    void SetPosition(const Vector3& pos) { m_position = pos; }

private:
    void BeginInvincible(float time);

    Vector3 m_position = Vector3::Zero;
    int     m_hp       = MAX_HP;
    float   m_invincibleTimer = 0.0f;
};

// Player.cpp
namespace {
    const int   MAX_HP           = 100;
    const float INVINCIBLE_TIME  = 1.0f;
}

void Player::Damage(int amount)
{
    if (m_invincibleTimer > 0.0f) {
        return;                              // 無敵中
    }
    if (m_hp <= 0) {
        return;                              // もう死んでいる
    }

    m_hp -= amount;
    if (m_hp < 0) { m_hp = 0; }

    BeginInvincible(INVINCIBLE_TIME);

    if (m_hp == 0) {
        // 死亡演出はここから
    }
}

void Player::Heal(int amount)
{
    if (m_hp <= 0) {
        return;                              // 死んでいたら回復しない
    }
    m_hp += amount;
    if (m_hp > MAX_HP) { m_hp = MAX_HP; }
}

void Player::BeginInvincible(float time)
{
    m_invincibleTimer = time;
}

void Player::Update()
{
    if (m_invincibleTimer > 0.0f) {
        m_invincibleTimer -= g_gameTime->GetFrameDeltaTime();
    }
    ...
}

まとめて面倒を見られるようになったこと

  • 無敵中は無効
  • 死んでいるときは、それ以上ダメージも回復もしない
  • HPが0未満・最大値超えにならない
  • ダメージのたびに無敵時間が始まる（書き忘れようがない）
「死んでいるのに死亡演出が2回出る」バグが消えます SetHp() 方式だと、同じフレームに複数の弾が当たったときに 死亡処理が何回も走ることがあります。

if (m_hp <= 0) return; の1行が、 その事故をまとめて防いでいます。 こういう「1か所に書けば済む守り」が、カプセル化の実利です。

演習3（消す）

自分のコードの getter を全部見て、どこからも呼ばれていないものを消す。（Shift+F12 で参照を検索できます）

解答例を見る（まず自分でやってから）

やり方

  1. getter の名前の上で Shift+F12（すべての参照を検索）
  2. 結果が「定義の1件だけ」なら、誰も使っていない
  3. 消す。ビルドが通れば、本当に使われていなかった

たいてい、こういうものが残っています

float GetShotTimer() const { return m_shotTimer; }      // 内部タイマー
int   GetAnimFrame() const { return m_animFrame; }      // 演出用
bool  GetIsFirstUpdate() const { return m_isFirst; }    // 初期化フラグ
Vector3 GetMoveSpeed() const { return m_moveSpeed; }    // 作ったけど使わなかった

「あとで使うかもしれない」は、消す理由になります。 必要になったら、そのとき1行書けばよいだけです。 使われていないコードは、読む人の時間を奪うだけの負債です。

消す前に、コミットしておいてください 消してビルドが通っても、あとで「あれ、あの関数どこ？」 となることがあります。

Git に入っていれば戻せます（1-03）。 安心して消せるようにしておくのが、Git を使う理由のひとつです。

おまけ：クラスの「顔」を見る

消し終わったら、.h の public: だけを眺めてください。 そこに並んでいるものが、そのクラスの全機能です。 

// これくらいなら、ひと目で分かる
public:
    bool Start()  override;
    void Update() override;
    void Render(RenderContext& rc) override;

    int  GetHp() const;
    bool IsAlive() const;
    void Damage(int amount);
    void Heal(int amount);
    const Vector3& GetPosition() const;
    void SetPosition(const Vector3& pos);

ここが20行を超えるなら、クラスが大きすぎます。 4-07 で分ける方法をやります。

08確認

  1. カプセル化の目的は？
  2. SetHp() が public なメンバとほぼ同じなのはなぜ？
  3. 参照を返す getter に const を付けないと、何が起きる？
答え
  1. 変わりうる場所を1か所に閉じ込めて、 デバッグしやすくすること。
  2. 結局どこからでも好きな値を入れられるから。 検索する名前が変わっただけ。
  3. 呼び出し側が中身を直接書き換えられる。 private にした意味がなくなる。
