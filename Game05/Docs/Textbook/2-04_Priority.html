難易度 ／ 前提 2-03

01この章でできるようになること

  • 優先度で処理順と描画順が決まることを説明できる
  • 背景の上にキャラ、その上にUI、という重なりを作れる
  • 数字を直接書かず、enum で管理できる

02優先度とは

GameObjectManager は、ゲームオブジェクトを優先度ごとのリストに 分けて持っています。そして優先度の小さい順に Update() と Render() を呼びます。

03数字を直接書いてはいけない

こう書くと、すぐに分からなくなります。 

NewGO<Background>(0, "background");
NewGO<Player>(3, "player");
NewGO<Bullet>(5, "bullet");
NewGO<Ui>(9, "ui");

3ヶ月後に 5 を見て「これ何だっけ」となります。 間に新しいものを入れたくなったとき、どの数字が空いているかも分かりません。 enum で名前をつけてください。 

// GameObjectPriority.h
#pragma once

/// <summary>
/// ゲームオブジェクトの優先度。
/// 小さいものから順に Update / Render される。
/// 描画も同じ順なので、大きいほど手前に描かれる。
/// </summary>
enum EnGameObjectPriority {
    enPriority_Background = 0,   // 背景
    enPriority_Enemy      = 3,   // 敵
    enPriority_Player     = 4,   // 自機
    enPriority_Bullet     = 5,   // 弾
    enPriority_Effect     = 7,   // エフェクト
    enPriority_Ui         = 9,   // UI（いちばん手前）
};
NewGO<Background>(enPriority_Background, "background");
NewGO<Player>(enPriority_Player, "player");
NewGO<Bullet>(enPriority_Bullet, "bullet");
NewGO<Ui>(enPriority_Ui, "ui");
数字を飛ばしておく 0, 1, 2, 3 と詰めずに、0, 3, 4, 5, 7, 9 のように すき間をあけておきます。 あとで「敵と自機の間に何か入れたい」となったとき、 全部の数字を振り直さずに済みます。

04優先度で気をつけること

こと説明
同じ優先度の中の順番 NewGO した順。でも、これに頼った設計にしてはいけません
上限 0 〜 254。範囲外を渡すと落ちます
Start() の順番 これも優先度順。自分より優先度が大きい相手は、まだ Start していないかもしれません
Start() での FindGO に注意 Player（優先度4）の Start() で FindGO<Ui>("ui")（優先度9）をしても、 UIがまだ作られていなければ nullptr が返ります。 順番に依存するなら、優先度を見直すか、Update() の中で取得してください。

05動かして確かめる

2つのスプライトを重ねて置き、優先度を入れ替えてみます。 

NewGO<SpriteA>(2, "a");   // 赤い四角
NewGO<SpriteB>(4, "b");   // 青い四角（同じ場所）
  • 青が手前に出る
  • 数字を入れ替えると、赤が手前になる
  • GameObject List の Group by prio で、優先度ごとに分かれて見える

06演習

演習1（まねる）

上の2つのスプライトで、重なり順が変わることを確認する。

演習2（整理する）

自分のプロジェクトに GameObjectPriority.h を作り、 いま数字で書いてあるところを全部 enum に置き換える。

解答例を見る（まず自分でやってから） 
// GameObjectPriority.h
#pragma once

enum EnGameObjectPriority {
    enPriority_Background = 0,
    enPriority_Enemy      = 3,
    enPriority_Player     = 4,
    enPriority_Bullet     = 5,
    enPriority_Effect     = 7,
    enPriority_Ui         = 9,
};

置き場所は Game/ の直下でかまいません。 使うファイルで #include "GameObjectPriority.h" します。

置き換えたあと、必ず一度実行してください。 数字を間違えると重なり順が変わります。見た目で気づけます。

演習3（考える）

弾は自機より手前に出るべきでしょうか、奥に出るべきでしょうか。 自分のゲームではどちらが正しいかを決めて、理由を書く。

解答例を見る（まず自分でやってから）

どちらにも理由があります。自分のゲームで決めてください。

選択理由
弾を手前（自機より大きい優先度） 弾がどこにあるか見失わない。弾幕系ならこちら
弾を奥（自機より小さい優先度） 自機が弾に隠れない。自機の位置が常に見える

一般には「自機がいちばん手前」が安全です。 自機が見えなくなるのは致命的だからです。 弾が自機の下に隠れても、遊ぶ人はあまり困りません。

大事なのは「なんとなく」で決めないことです。 理由を言えるようにしておけば、あとで直すときも判断できます。 これは LV4 の 「なぜその設計にしたか説明できる」につながる練習です。

07確認

  1. 優先度が小さいものと大きいもの、先に Update されるのは？
  2. 手前に描かれるのはどちら？
  3. 優先度を enum にする理由を2つ。
答え
  1. 小さいほうが先。
  2. 大きいほう（あとから描かれるので上に重なる）。
  3. 数字の意味が分かる／あとから順番を変えやすい。
