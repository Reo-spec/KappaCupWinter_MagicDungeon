ポインタと参照

難易度 ／ 前提 1-13

ここが LV1 の山場です 1回で分からなくて当たり前です。 多くの人がここでつまずきます。あなただけではありません。
分からなくても、手を動かして実際に表示させてみてください。 頭で理解する前に、目で見るほうが早いです。

01この章でできるようになること

  • 変数がメモリのどこかにある、という感覚をつかむ
  • & と * の意味が分かる
  • なぜ RenderContext& rc と書いてあるのかが分かる

02変数は、メモリのどこかにある

int hp = 100; と書くと、 メモリのどこかに4バイトの場所が確保されて、そこに 100 が書かれます。

その「どこか」を表す番号がアドレスです。 & を付けると、アドレスが取れます。

03記号の意味

書き方意味
int* p;宣言のとき：「p は int のアドレスを入れる箱」
&hphp のアドレスを取る
*p使うとき：p が指す先の中身
* は場所によって意味が違います 
int* p = &hp;     // ここの * は「ポインタ型ですよ」という印
*p = 50;          // ここの * は「指す先を見ろ」という命令
同じ記号なのに意味が違うので、最初は混乱します。 宣言のときか、使うときか、で見分けてください。

04自分の目で見る

説明を読むより、表示させたほうが早いです。 

void Game::Update()
{
    int hp = 100;
    int* p = &hp;

    wchar_t text[256];
    swprintf_s(text, 256,
        L"hp の値 = %d\n"
        L"hp のアドレス = %p\n"
        L"p の値 = %p\n"
        L"*p（p が指す先）= %d",
        hp, &hp, p, *p);
    m_fontRender.SetText(text);
}
  • hp のアドレス と p の値 が同じ
  • *p が hp の値 と同じ
  • 実行するたびにアドレスが変わる

続けて、*p = 50; を足してみてください。 hp のほうが変わります。

05nullptr ― どこも指していない

int* p = nullptr;      // どこも指していない

if (p != nullptr) {    // 使う前に必ず確認する
    *p = 50;
}
nullptr を * するとクラッシュします nullptr のまま *p すると、 「アクセス違反」で必ず落ちます。
これはよいことです。すぐ気づけるからです。 2-08 でやる 「消えたものを指しているポインタ」のほうが、はるかにやっかいです。

ポインタを受け取ったら、まず nullptr を確認する。 これは一生使う習慣です。

06参照 ― 「別名」

参照は、すでにある変数に、もう1つ名前を付けたものです。 

int hp = 100;
int& r = hp;      // r は hp の別名

r = 50;           // hp が 50 になる
ポインタ int*参照 int&
使うとき*p と書くそのまま書ける
途中で別のものを指すできるできない
「何も指さない」nullptr があるない（必ず何かを指す）
安全さ注意が必要安全
迷ったら参照を使う 参照のほうが安全です。nullptr になりえないので、 チェックが要りません。
ポインタを使うのは「無いこともある」を表したいときだけにしてください。

07なぜ RenderContext& rc なのか

1-04 から、ずっと見てきたこの行。 

void Game::Render(RenderContext& rc)

もう読めるはずです。 「RenderContext の参照を受け取る」という意味です。

もし & が無かったら（RenderContext rc）、 RenderContext という巨大なオブジェクトが、 毎フレーム丸ごとコピーされます。 & を付ければ、コピーされません。

この話は 1-17 でくわしくやります。

08演習

演習1（まねる）

上のコードで、アドレスと値を画面に表示する。実行するたびにアドレスが変わることを確認する。

演習2（書き換える）

ポインタ経由で hp を書き換える。また、参照でも同じことをして、書き方の違いを比べる。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    int hp = 100;

    // ポインタで書き換える
    int* p = &hp;
    *p = 50;              // hp が 50 になる

    // 参照で書き換える
    int& r = hp;
    r = 30;               // hp が 30 になる（* が要らない）

    wchar_t text[256];
    swprintf_s(text, 256, L"hp = %d", hp);   // 30
    m_fontRender.SetText(text);
}
ポインタ参照
作るint* p = &hp;int& r = hp;
書き換える*p = 50;r = 50;

参照のほうが、ふつうの変数と同じように書けます。 これが「別名」という意味です。

演習3（関数に渡す）

HPを10減らす関数を、3通りで書いて違いを見る。
① void Damage(int hp)　② void Damage(int* hp)　③ void Damage(int& hp)

解答例を見る（まず自分でやってから） 
// ① 値渡し ― 元の変数は変わらない
void Damage1(int hp)
{
    hp -= 10;           // コピーを減らしているだけ
}

// ② ポインタ渡し
void Damage2(int* hp)
{
    if (hp == nullptr) { return; }   // 確認が要る
    *hp -= 10;
}

// ③ 参照渡し
void Damage3(int& hp)
{
    hp -= 10;           // そのまま書ける
}
int hp = 100;

Damage1(hp);      // hp は 100 のまま！
Damage2(&hp);     // hp は 90
Damage3(hp);      // hp は 80
①は「変わらない」のが落とし穴です エラーも警告も出ません。ただ、何も起きません。
「関数を呼んだのに値が変わらない」というバグの、いちばん多い原因です。

使い分けの目安

渡し方いつ使う
値渡し int hp小さい型で、書き換えないとき
参照渡し int& hp書き換えたいとき（基本はこれ）
ポインタ渡し int* hp「渡さない（nullptr）」こともあるとき

呼ぶ側を見たとき、Damage2(&hp) は「書き換えられるな」と分かります。 Damage3(hp) は見た目では分かりません。 これがポインタ渡しの数少ない利点です。

09確認

  1. &hp は何を取り出す？
  2. int* p; の * と、*p = 50; の * の違いは？
  3. ポインタと参照、迷ったらどちらを使う？ なぜ？
  4. void Damage(int hp) で hp -= 10; しても 元の値が変わらないのはなぜ？
答え
  1. hp が置かれているメモリのアドレス。
  2. 前者は「ポインタ型である」という宣言の印。 後者は「指す先を見ろ」という命令。
  3. 参照。nullptr になりえないので安全。 ポインタは「無いこともある」を表したいときだけ。
  4. 値渡しなのでコピーが渡されており、 コピーのほうを減らしているだけだから。
