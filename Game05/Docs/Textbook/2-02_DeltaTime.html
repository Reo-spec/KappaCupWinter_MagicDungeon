デルタタイムとフレーム

難易度 ／ 前提 2-01

00入場チェック

  • Update() は1秒に何回くらい呼ばれる？ → 答えられないなら 2-01 へ戻る
  • float と int の違いは？ → 答えられないなら 1-06 へ戻る

01この章でできるようになること

  • PCの速さに左右されない動きが書ける
  • g_gameTime->GetFrameDeltaTime() が何の値か説明できる
  • 「1フレームで何ピクセル」ではなく「1秒で何ピクセル」で考えられる

02やってはいけない書き方

キャラクターを右に動かしたいとき、こう書きたくなります。 

void Player::Update()
{
    m_position.x += 5.0f;    // 毎フレーム 5 進む
}

自分のPCでは、ちょうどいい速さで動くかもしれません。 でも、これは壊れています。

03デルタタイムを掛ける

デルタタイムとは、前のフレームから今のフレームまでにかかった秒数です。 60fps なら約 0.0166 秒、30fps なら約 0.0333 秒になります。 

void Player::Update()
{
    // 1秒で 300 進む。
    m_position.x += 300.0f * g_gameTime->GetFrameDeltaTime();
}

60fps なら 300 × 0.0166 = 約5、30fps なら 300 × 0.0333 = 約10。 1フレームで進む量は変わりますが、1秒で進む距離は同じになります。

速さは「1秒あたり」で考える 300.0f という数字は「1秒で300ピクセル進む」という意味です。 「1フレームで5」ではなく「1秒で300」で考える癖をつけてください。 この考え方は、Unityでも Unreal Engine でも同じです。

04どこに掛けるのか

「時間とともに変化するもの」すべてに掛けます。

やりたいこと書き方
移動m_position += m_velocity * dt;
回転m_angle += 90.0f * dt;（1秒で90度）
時間を数えるm_timer += dt;
連射のクールタイムm_coolTime -= dt;

毎回 g_gameTime->GetFrameDeltaTime() と書くのは長いので、 関数の先頭で受けておくと読みやすくなります。 

void Player::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();

    m_position.x += 300.0f * dt;
    m_timer      += dt;
}

05掛けてはいけないもの

「時間と関係ないもの」には掛けません。 

// ダメな例
m_hp -= 10 * dt;          // ダメージは時間で変わらない

// 正しい
m_hp -= 10;

ただし「毒で1秒に5ダメージ」のようなものは、 時間とともに変化するので掛けます。 「1秒あたりの量なのか、1回あたりの量なのか」で判断してください。

06動かして確かめる

k2Engine は標準で 60fps に制限されています。 わざと重くして、違いを見てみましょう。 

void Game::Update()
{
    // わざと重い処理を入れる。
    if (g_pad[0]->IsPress(enButtonA)) {
        volatile double x = 0.0;
        for (int i = 0; i < 20000000; i++) { x += i * 0.5; }
    }
}

Aボタンを押しながら、Profilerパネル（F1 → Profiler）で フレーム時間が伸びるのを見てください。

  • デルタタイムを掛けていないものは、押した瞬間スローモーションになる
  • デルタタイムを掛けたものは、カクカクするが、進む速さは変わらない

07よくあるエラー

デルタタイムを2回掛けてしまう

原因：m_velocity にすでに掛けたのに、 m_position += m_velocity * dt; でもう一度掛けている。
直し方：「速度」は1秒あたりの量、「位置」は距離と決めて、 位置に足すときだけ掛ける。

動きが速すぎる／遅すぎる

原因：数字を「1フレームあたり」のつもりで書いている。
直し方：1秒でどれだけ動いてほしいかを考える。 画面幅1920を2秒で横切るなら 960.0f です。

08演習

演習1（まねる）

デルタタイムを使って、3秒で画面を横切るスプライトを作る。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();

    // 画面幅1920を3秒で横切る → 1秒あたり640
    m_position.x += 640.0f * dt;

    // 右端まで行ったら左端に戻す
    if (m_position.x > 960.0f) {
        m_position.x = -960.0f;
    }

    m_spriteRender.SetPosition(m_position);
    m_spriteRender.Update();
}

1920 ÷ 3 = 640 です。速さは「1秒あたり」で考えます。

演習2（比べる）

デルタタイムを掛けたものと掛けないものを両方置いて、 上の「重い処理」を入れたときの違いを見る。

解答例を見る（まず自分でやってから） 
void Game::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();

    m_goodPos.x += 300.0f * dt;     // デルタタイムあり
    m_badPos.x  += 5.0f;            // デルタタイムなし

    // 重くする
    if (g_pad[0]->IsPress(enButtonA)) {
        volatile double x = 0.0;
        for (int i = 0; i < 20000000; i++) { x += i * 0.5; }
    }
    ...
}

Aボタンを押すと、デルタタイムなしのほうだけが急に遅くなります。 デルタタイムありのほうは、カクカクはしますが、同じ時間で同じ距離を進みます。

これが「PCの速さに左右されない」ということです。 遊ぶ人のPCは、あなたのPCより遅いかもしれません。

演習3（自分で書く）

3秒たったら自分を消すオブジェクトを作る。 m_timer と dt を使うこと。 本文には答えがありません。

解答例を見る（まず自分でやってから） 
// TimedObject.h
private:
    float m_timer = 0.0f;

// TimedObject.cpp
void TimedObject::Update()
{
    m_timer += g_gameTime->GetFrameDeltaTime();

    if (m_timer >= 3.0f) {
        DeleteGO(this);
        return;              // ★ 忘れない
    }
    ...
}

m_timer を足していく書き方と、 決まった秒数から引いていく書き方があります。どちらでも構いません。 

// 引いていく書き方
m_life -= g_gameTime->GetFrameDeltaTime();
if (m_life <= 0.0f) { DeleteGO(this); return; }

なお DeleteGO がいつ効くのかは 2-05 でくわしくやります。

09確認

  1. デルタタイムとは何の値？
  2. m_position.x += 5.0f; の何がいけない？
  3. m_hp -= 10 * dt; は正しい？
答え
  1. 前のフレームから今のフレームまでにかかった秒数。60fpsなら約0.0166。
  2. PCの速さで進む距離が変わってしまう。重いPCではスローモーションになる。
  3. ふつうは間違い。ダメージは「1回あたり」の量なので掛けない。 ただし「1秒に10ダメージの毒」なら正しい。
