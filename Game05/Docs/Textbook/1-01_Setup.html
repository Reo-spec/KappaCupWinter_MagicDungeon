LV1 入門 ／ 1-01

環境構築とビルド

難易度 ／ 前提 —

01この章でできるようになること

  • Visual Studio で k2Engine のプロジェクトを開ける
  • ビルドして、実行できる
ここは急がなくていい章です 環境構築は、プログラミングを始めるときにいちばん心が折れやすいところです。 うまくいかなくても、あなたのせいではありません。 エラーが出たら、下の「よくあるエラー」を落ち着いて読んでください。

02用意するもの

もの備考
Windows 10 / 11 の PCMac では動きません（DirectXがWindows専用のため）
Visual Studio 2022 以降Community版（無料）で構いません
k2Engine 一式学校から配られたもの、またはGitでクローンしたもの
ゲームパッド無くてもキーボードで動きます。あると楽

03Visual Studio を入れる

インストーラを起動すると、「ワークロード」という一覧が出ます。 ここで選び忘れると、あとでビルドできません。

  • C++ によるデスクトップ開発 にチェックを入れる
  • 右側の「インストールの詳細」に Windows 10/11 SDK が入っているか確認

ほかのワークロード（Unity、Python など）は、今は要りません。 容量が大きいので、必要になってから足せば充分です。

あとから追加できます チェックを忘れても大丈夫です。スタートメニューから Visual Studio Installer を起動して「変更」を押せば、 あとから追加できます。

04ファイルを置く場所

パスに日本語とスペースを入れないこと フォルダの名前に日本語・スペース・記号が入っていると、 ビルドツールがファイルを見つけられず、意味のわからないエラーが出ます。
置き場所可否
C:\dev\k2Engine\よい
D:\work\game\k2Engine\よい
C:\Users\山田太郎\デスクトップ\k2Engine\だめ（日本語）
C:\My Documents\k2 Engine\だめ（スペース）
OneDrive の中やめたほうがよい（同期が邪魔をする）

また、パスが長すぎるとビルドに失敗することがあります。 C:\dev\ のように、なるべく浅い場所に置いてください。

05最初の1回だけやること

リポジトリの直下に 右クリックで管理者として実行してね.bat というファイルがあります。 その名のとおり、右クリックして「管理者として実行」してください。

これは、エンジンのフォルダへのショートカット（シンボリックリンク）を作るものです。 管理者権限がないと作れないので、ふつうにダブルクリックしても失敗します。

06ビルドして実行する

  1. GameTemplate/Game/Game.sln をダブルクリックして開く
  2. 画面の上のほうにある2つのドロップダウンを確認する
    • 左：Debug
    • 右：x64
  3. F5 を押す（または「ローカル Windows デバッガー」ボタン）
  4. 初回は数分かかります。コーヒーでも飲んで待ってください
x64 になっているか、必ず確認 x86（Win32）だとビルドが通りません。 k2Engine は64bit専用です。うまくいかないときは、まずここを見てください。

ウィンドウが開いて、キャラクターが表示されたら成功です。 おめでとうございます。ここが出発点です。

07よくあるエラー

ビルドに何分もかかる

初回はそういうものです。 エンジン全体と、物理エンジンなどのライブラリを全部コンパイルするからです。 2回目からは、変えたファイルだけが作り直されるので速くなります。

fatal error C1083: include ファイルを開けません

原因1： 右クリックで管理者として実行してね.bat を実行していない。
原因2：パスに日本語やスペースが入っている。
原因3：Windows SDK が入っていない。 Visual Studio Installer で確認する。

「このプロジェクトは移行が必要です」と出る

原因：プロジェクトが想定している Visual Studio のバージョンと違う。
直し方：そのまま「OK」で進めてかまいません。 通らない場合は、Visual Studio Installer で v143 のビルドツールを追加してください。

実行したらすぐ落ちる

原因：アセットを読み込めていないことが多いです。
直し方：出力ウィンドウ （Ctrl+Alt+O）に 何か出ていないか見てください。エラーの手がかりが出ています。

グラフィックボードが無いPCで動かない

k2Engine は DirectX 12 を使います。 古いPCや、内蔵グラフィックスだけのPCでは動かないことがあります。 学校のPCで試してみてください。

08演習

演習1（まねる）

ビルドして実行し、キャラクターが画面に出るところまで進める。

演習2（慣れる）

ウィンドウを閉じて、もう一度 F5 を押す。2回目はどのくらい速くなるかを体感する。

解答例を見る（まず自分でやってから）

1回目が数分、2回目は数秒〜十数秒になるはずです。

これは 変更のないファイルは作り直さない からです。 これを「インクリメンタルビルド」と呼びます。

逆に、ビルド → リビルド を選ぶと全部作り直すので、また数分かかります。 おかしくなったとき以外は、リビルドしないでください。時間の無駄です。

演習3（調べる）

Debug と Release の違いは何でしょうか。両方でビルドして、Game/x64/ の中にできるファイルの大きさを比べてみる。

解答例を見る（まず自分でやってから）
DebugRelease
目的開発中に使う完成品として配る
速さ遅い速い
ファイルの大きさ大きい小さい
デバッグできるしにくい

Debug には「どの行を実行しているか」といった情報が全部入っているので、 大きくて遅いかわりに、デバッガで中身を追えます （1-18）。

作るときは Debug、提出するときは Release そして、提出前に必ず Release でも動くか確かめてください。 「Debugでは動いたのに」は、毎年いちばん多い失敗です。

09確認

  1. ビルド構成は Debug / Release のどちら？ プラットフォームは？
  2. フォルダのパスに入れてはいけないものは？
  3. 最初の1回だけやることは？
答え
  1. 開発中は Debug。プラットフォームは必ず x64。
  2. 日本語・スペース。OneDriveの中も避ける。
  3. 右クリックで管理者として実行してね.bat を管理者として実行する。
