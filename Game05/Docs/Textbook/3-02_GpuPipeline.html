02画面は「三角形」でできている

GPUが描けるのは、基本的に三角形だけです。 四角形は三角形2つ、キャラクターのモデルは三角形が何千個も集まったものです。

三角形は頂点3つで決まります。 頂点は、位置のほかに「色」「UV（テクスチャのどこを使うか）」 「法線（面の向き）」などの情報を持っています。

04頂点シェーダ ― どこに表示するか

3D空間の座標を、画面のどこに来るかに変換します。 sprite.fx の頂点シェーダを見てください。 

PSInput VSMain(VSInput In)
{
    PSInput psIn;
    psIn.pos = mul( mvp, In.pos );    // 座標を変換する
    psIn.uv  = In.uv;                 // UVはそのまま渡す
    return psIn;
}

mvp は Model-View-Projection 行列です。 「モデルの置かれている場所」「カメラの位置と向き」「レンズの画角」を まとめて1つにした行列で、掛けるだけで画面上の位置が出ます。

行列の中身は、いまは分からなくて大丈夫です 「これを掛けると画面の座標になる」とだけ覚えてください。 行列の計算そのものは、エンジンがやってくれます。

05ピクセルシェーダ ― 何色か

float4 PSMain( PSInput In ) : SV_Target0
{
    return colorTexture.Sample(Sampler, In.uv) * mulColor;
}

たった1行です。

部分意味
float4戻り値は色。R, G, B, A の4つ
: SV_Target0「この値を、1番目のレンダーターゲットに書け」
colorTexture.Sample(Sampler, In.uv) テクスチャの、UVの位置の色を取ってくる
* mulColor乗算カラーを掛ける
SetMulColor の正体はこれです 2-11 で使った m_spriteRender.SetMulColor({1.0f, 0.3f, 0.3f, 1.0f}) は、 この mulColor に値を送っていたのです。
赤だけ 1.0 で緑と青を下げる → 赤以外が弱まる → 赤く見える。 ただの掛け算でした。

06色は 0〜1 の数

書き方色
float4(1, 0, 0, 1)赤（不透明）
float4(1, 1, 1, 1)白
float4(0, 0, 0, 1)黒
float4(1, 1, 1, 0.5)白・半透明

0〜255 ではなく 0.0〜1.0 です。 ペイントソフトの「255, 128, 0」は、シェーダでは「1.0, 0.5, 0.0」になります。

色の成分は .r .g .b .a でも .x .y .z .w でも 取り出せます。どちらでも同じものです。 

float4 c = colorTexture.Sample(Sampler, In.uv);
c.r = 1.0f;          // 赤を最大に
c.rgb *= 0.5f;       // 3つまとめて半分に（暗くなる）

07HLSL は C++ に似ています

HLSL意味
floatC++ と同じ
float2 / float3 / float4 floatが2個/3個/4個まとまったもの
float4x44×4の行列
if / forC++ と同じように書ける
cbufferC++から値を受け取る箱（次章）

よく使う関数もあります。 

saturate(x)          // 0〜1 に収める
lerp(a, b, t)        // a と b を t の割合で混ぜる（線形補間）
sin(x), cos(x)       // 三角関数
pow(x, y)            // xのy乗
dot(a, b)            // 内積
length(v)            // ベクトルの長さ
シェーダには printf がありません GPUの上で200万個同時に動いているので、ログを出せません。
デバッグの基本は「色に出す」です。 調べたい値を return float4(value, 0, 0, 1); として、 画面の赤さで値を見るのです。
もっと本格的な方法は 3-15 でやります。

08演習

演習1（読む）

Game/Assets/shader/sprite.fx を開いて、全部読む。30行もありません。

解答例を見る（まず自分でやってから）

全体はこれだけです。

cbuffer cb : register(b0){
    float4x4 mvp;
    float4 mulColor;
};
struct VSInput{
    float4 pos : POSITION;
    float2 uv  : TEXCOORD0;
};
struct PSInput{
    float4 pos : SV_POSITION;
    float2 uv  : TEXCOORD0;
};
Texture2D<float4> colorTexture : register(t0);
sampler Sampler : register(s0);

PSInput VSMain(VSInput In)
{
    PSInput psIn;
    psIn.pos = mul( mvp, In.pos );
    psIn.uv = In.uv;
    return psIn;
}
float4 PSMain( PSInput In ) : SV_Target0
{
    return colorTexture.Sample(Sampler, In.uv) * mulColor;
}

読み方

  • VSInput … 頂点シェーダが受け取るもの（位置とUV）
  • PSInput … 頂点シェーダが返し、ピクセルシェーダが受け取るもの
  • : POSITION や : TEXCOORD0 はセマンティクス。 「この変数は位置ですよ」とGPUに教える印
  • register(b0) … 定数バッファの0番。t0 はテクスチャの0番

「2Dのスプライトを1枚描く」というのは、これだけのことなのです。

演習2（数える）

フルHD（1920×1080）の画面全体を1枚のスプライトで覆ったとき、ピクセルシェーダは何回呼ばれるか。それが1秒に60回だと、1秒間に何回か。

解答例を見る（まず自分でやってから） 
1920 × 1080 = 2,073,600 回   （1フレーム）
2,073,600 × 60 = 124,416,000 回   （1秒間）

1秒間に1億2千万回です。

だから、ピクセルシェーダに重い処理を1行足すと、 致命的に遅くなることがあります。

頂点シェーダとピクセルシェーダの重さは違います キャラクターのモデルが1万頂点だとすると、
  • 頂点シェーダ … 1万回
  • ピクセルシェーダ … 画面に占める面積ぶん（数十万回になることも）
だから「できるだけ頂点シェーダ側でやる」のが、最適化の基本のひとつです。 この話は LV5 につながります。

09確認

  1. GPUが描ける基本の形は？
  2. 頂点シェーダとピクセルシェーダは、それぞれ何回呼ばれる？
  3. ピクセルシェーダの戻り値 float4 は何を表す？
  4. シェーダで printf が使えないとき、どうやって値を見る？
答え
  1. 三角形。
  2. 頂点シェーダは頂点の数だけ、ピクセルシェーダは塗るピクセルの数だけ。
  3. 色。R, G, B, A の4つで、それぞれ 0.0〜1.0。
  4. 調べたい値を色にして画面に出す。
