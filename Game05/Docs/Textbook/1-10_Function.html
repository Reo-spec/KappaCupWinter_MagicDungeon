LV1 入門 ／ 1-10

関数 ― 処理に名前をつける

難易度 ／ 前提 1-09

01この章でできるようになること

  • 処理をまとめて、名前をつけられる
  • 引数と戻り値を使える
  • Update() を短く保てる

02なぜ関数に分けるのか

Update() にすべてを書いていくと、こうなります。 

void Game::Update()
{
    // 移動の処理 20行
    // 画面外チェック 10行
    // 弾を撃つ処理 25行
    // 当たり判定 30行
    // アニメーション 15行
    // ... 気づけば300行
}

どこを直せばいいのか分からなくなります。 名前をつけて分けると、こうなります。 

void Game::Update()
{
    Move();
    ClampToScreen();
    Shoot();
    CheckHit();
    UpdateAnimation();
}

Update() を読むだけで「何をしているか」が分かります。 直したい場所も、名前から見当がつきます。

03書き方

クラスの関数（メンバ関数）は、.h に宣言、 .cpp に中身を書きます。 

// Game.h
class Game : public IGameObject
{
public:
    bool Start();
    void Update();
    void Render(RenderContext& rc);

private:
    void Move();                  // ★ 宣言
    void ClampToScreen();         // ★ 宣言

private:
    FontRender m_fontRender;
    float m_posX  = 0.0f;
    float m_speed = 3.0f;
};
// Game.cpp
void Game::Move()                 // ★ Game:: を忘れない
{
    m_posX += m_speed;
}

void Game::ClampToScreen()
{
    if (m_posX > 900.0f) {
        m_posX = 900.0f;
        m_speed = -m_speed;
    }
    if (m_posX < -900.0f) {
        m_posX = -900.0f;
        m_speed = -m_speed;
    }
}

void Game::Update()
{
    Move();
    ClampToScreen();
    ...
}
Game:: を忘れると LNK2019 .cpp で void Move() と書くと、 Game とは無関係の、まったく別の関数になってしまいます。 結果、Game::Move の中身が見つからずリンクエラーです （1-05）。

04引数と戻り値

// 引数：外から値を受け取る
void SetHp(int hp)
{
    m_hp = hp;
}

// 戻り値：結果を返す
int GetHp()
{
    return m_hp;
}

// 両方
int Add(int a, int b)
{
    return a + b;
}
書き方意味
void戻り値なし。return を書かなくてよい
intint を返す。return が必須
( ) の中引数。無いなら空でよい

void の関数でも、return; で途中で抜けられます。 これはよく使います。 

void Game::Shoot()
{
    if (m_coolTime > 0.0f) {
        return;              // まだ撃てないので、何もせず帰る
    }
    // ここから下は、撃てるときだけ通る
    ...
}

05よい関数の作り方

こころがけ理由
ひとつのことだけをする 名前が付けやすくなる。MoveAndShoot() は分けるべき
名前は動詞から始める Move(), CheckHit(), IsAlive()
20行を超えたら分割を考える 目安。長い関数は読めない
bool を返すなら Is / Has で始める IsAlive()、HasKey()。読んだとき自然な文になる
名前がうまく付けられない関数は、たぶん分けるべきです 「これ何をする関数？」に一言で答えられないなら、 2つ以上のことをしています。 名前を考えることが、そのまま設計の練習になります。

06演習

演習1（まねる）

Update() の中身を Move() と ClampToScreen() に分ける。

演習2（作る）

2つの数を受け取って、大きいほうを返す関数 int Max2(int a, int b) を作って使う。

解答例を見る（まず自分でやってから） 
// Game.h
private:
    int Max2(int a, int b);

// Game.cpp
int Game::Max2(int a, int b)
{
    if (a > b) {
        return a;
    }
    return b;
}

else を書かなくてよいことに注目してください。 return したら、そこで関数は終わります。

ちなみに、C++には最初から max と min があります。

int big   = max(a, b);
int small = min(a, b);
int clamped = max(0, min(100, hp));   // 0〜100 に収める（よく使う）

最後の書き方は、この先ずっと使います。覚えておいてください。

演習3（分ける）

いままで書いた Update() を見直して、3つ以上の関数に分ける。そのあと、Update() が何をしているか一目で分かるか確かめる。

解答例を見る（まず自分でやってから） 
// Game.cpp
void Game::Update()
{
    UpdateInput();
    Move();
    ClampToScreen();
    UpdateHpState();
    UpdateText();
}

これが目標の形です。 Update() を見ただけで、このゲームが毎フレーム何をしているか分かります。

分けるときのコツ

  • コメントを書きたくなったところが、分けどころです。 // 移動の処理 と書きたくなったら、 それは Move() という関数にできます
  • 関数名がコメントの代わりになるので、コメントが減ります
  • 分けすぎても害はほとんどありません。迷ったら分けてください
この感覚が LV4 につながります 「長い関数を分ける」は、設計のいちばん基本の一歩です。 LV4-04 で「1000行の Update」を扱いますが、 いまこの習慣を付けておけば、そもそもそうなりません。

07確認

  1. メンバ関数の中身を .cpp に書くとき、名前の前に何を付ける？
  2. void の関数で return; を書くのはどんなとき？
  3. 関数を分ける目安は？
答え
  1. クラス名と ::。例：void Game::Move()
  2. 条件を満たさないとき、途中で処理をやめて抜けるとき。
  3. ひとつのことだけをするように。20行を超えたら考える。 コメントを書きたくなったら分けどき。
