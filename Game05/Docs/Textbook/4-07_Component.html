03考え方

「Player とは、これらの部品を持った入れ物である」 と考え直します。 

Player
 ├ HealthComponent      // HP、無敵時間、ダメージ処理
 ├ ShooterComponent     // 射撃、連射間隔、弾のレベル
 ├ ModelComponent       // モデル表示、アニメーション
 └ ColliderComponent    // 当たり判定の半径と、当たったかの判定

すると、Enemy は同じ部品を組み替えるだけで作れます。 

Enemy
 ├ HealthComponent      // ★ Player とまったく同じもの
 ├ ModelComponent       // ★ 同じ
 ├ ColliderComponent    // ★ 同じ
 └ MoverComponent       // 敵だけ持つ

04軽い作り方 ― まず「ただのメンバ」から

いきなり Unity のような仕組みを作らないでください。 まずは、ただのメンバ変数として持つだけで充分です。 

// HealthComponent.h
class HealthComponent {
public:
    void Init(int maxHp) { m_maxHp = maxHp; m_hp = maxHp; }

    void Update(float dt)
    {
        if (m_invincibleTimer > 0.0f) {
            m_invincibleTimer -= dt;
        }
    }

    /// <returns>実際にダメージが入ったら true</returns>
    bool Damage(int amount)
    {
        if (m_invincibleTimer > 0.0f || m_hp <= 0) {
            return false;
        }
        m_hp -= amount;
        if (m_hp < 0) { m_hp = 0; }
        m_invincibleTimer = INVINCIBLE_TIME;
        return true;
    }

    void Heal(int amount);
    int  GetHp() const     { return m_hp; }
    int  GetMaxHp() const  { return m_maxHp; }
    bool IsAlive() const   { return m_hp > 0; }
    bool IsInvincible() const { return m_invincibleTimer > 0.0f; }

private:
    int   m_hp = 0;
    int   m_maxHp = 0;
    float m_invincibleTimer = 0.0f;
};
// Player.h
class Player : public IGameObject {
private:
    HealthComponent  m_health;       // ★ ただのメンバ
    ShooterComponent m_shooter;
    ...
};

// Player.cpp
bool Player::Start()
{
    m_health.Init(100);
    m_shooter.Init(0.15f);
    return true;
}

void Player::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();
    m_health.Update(dt);
    m_shooter.Update(dt);
    ...
}
これで充分に効果があります IGameObject を継承していません。 仮想関数もありません。リストも登録も要りません。
それでも、Player のメンバは23個から5個になり、 HP まわりのコードは1ファイルにまとまりました。

05重い作り方 ― 汎用のコンポーネントシステム

Unity のように「実行中に部品を付け外しできる」形も作れます。 

class IComponent {
public:
    virtual ~IComponent() {}
    virtual void Start(IGameObject& owner) {}
    virtual void Update(IGameObject& owner, float dt) {}
};

class ComponentHolder {
public:
    template<class T, class... Args>
    T* AddComponent(Args&&... args)
    {
        auto c = std::make_unique<T>(std::forward<Args>(args)...);
        T* raw = c.get();
        m_components.push_back(std::move(c));
        return raw;
    }

    template<class T>
    T* GetComponent()
    {
        for (auto& c : m_components) {
            if (T* t = dynamic_cast<T*>(c.get())) {
                return t;
            }
        }
        return nullptr;
    }

    void UpdateAll(IGameObject& owner, float dt)
    {
        for (auto& c : m_components) { c->Update(owner, dt); }
    }

private:
    std::vector<std::unique_ptr<IComponent>> m_components;
};
こちらを選ぶ前に、よく考えてください
ただのメンバ汎用システム
速度速い dynamic_cast と仮想関数のぶん遅い
コンパイル時の検査効く 実行するまで nullptr か分からない
実行中の付け外しできないできる
コード量少ない多い
実行中に付け外しする必要が本当にあるか、先に確かめてください。 たいていの学生作品には要りません。

06Unity がなぜああなっているか

Unity の GameObject は、ほとんど空の入れ物です。 機能は全部 Component として付けます。

Unityこの章の言葉で
GameObject入れ物
Transform位置のコンポーネント
Rigidbody物理のコンポーネント
MonoBehaviour を継承した自作スクリプト 自作コンポーネント
GetComponent<T>() 上の GetComponent<T>() そのもの

Unreal も Godot も、同じ考え方です。 現代のゲームエンジンが揃ってこの形なのは、 4-03 の 「継承の掛け算問題」を避けるためです。

k2Engine は、あえてそうなっていません IGameObject を継承して Update() を書く、 という素朴な作りです。
はじめて触るときに分かりやすいからです。 そのぶん、規模が大きくなると自分で分ける必要があります。 それがこの章です。

07演習

演習1（切り出す）

HealthComponent を作って、Player と Enemy の両方で使う。

演習2（もう1つ）

ShooterComponent を作る。プレイヤーと敵で、撃つ弾の種類だけ違うようにする。

解答例を見る（まず自分でやってから） 
// ShooterComponent.h
#pragma once

/// <summary>
/// 一定間隔で弾を撃つ部品。
/// </summary>
/// <remarks>
/// 「いつ撃つか」だけを持ち、「何を撃つか」は持ち主が決める。
/// </remarks>
class ShooterComponent {
public:
    void Init(float interval) { m_interval = interval; m_timer = interval; }

    void Update(float dt) { m_timer += dt; }

    /// <summary>撃てるタイミングなら true を返し、タイマーを戻す。</summary>
    bool TryShot()
    {
        if (m_timer < m_interval) {
            return false;
        }
        m_timer = 0.0f;
        return true;
    }

    void SetInterval(float interval) { m_interval = interval; }
    float GetInterval() const        { return m_interval; }

private:
    float m_interval = 0.2f;
    float m_timer    = 0.0f;
};

使い方 ― 撃つものは、持ち主が決める

// Player.cpp
void Player::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();
    m_shooter.Update(dt);

    if (g_pad[0]->IsPress(enButtonA) && m_shooter.TryShot()) {
        m_bulletPool->Fire(m_position, { 0.0f, BULLET_SPEED, 0.0f });
    }
}

// Enemy.cpp
void Enemy::Update()
{
    const float dt = g_gameTime->GetFrameDeltaTime();
    m_shooter.Update(dt);

    if (m_shooter.TryShot()) {
        Vector3 toPlayer = GetPlayerDirection();
        m_enemyBulletPool->Fire(m_position, toPlayer * ENEMY_BULLET_SPEED);
    }
}
この分け方が、この章でいちばん大事なところです ShooterComponent は「弾」を知りません。 Bullet も EnemyBullet も BulletPool も、 インクルードすらしていません。

知っているのは「間隔」と「いま撃てるか」だけです。 だからプレイヤーでも敵でもボスでも、そのまま使えます。

やってはいけない作り方

// ★ こうすると、使い回せなくなる
class ShooterComponent {
public:
    void Update(float dt)
    {
        m_timer += dt;
        if (m_timer > m_interval) {
            m_timer = 0.0f;
            NewGO<Bullet>(enPriority_Bullet, "bullet");   // ★ Bullet を知っている
        }
    }
};

部品に「相手」を知らせないこと。 これは 4-04 の D（依存性逆転）と同じ話です。

発展：レベルアップに対応する

// パワーアップで連射が速くなる
void Player::PowerUp()
{
    m_shotLevel++;
    m_shooter.SetInterval(BASE_INTERVAL / (1.0f + m_shotLevel * 0.3f));
}

演習3（数える）

コンポーネントに分けたあと、Player のメンバ変数が何個になったか数える。4-01 の数字と比べる。

解答例を見る（まず自分でやってから）

分けたあとの Player.h は、こうなるはずです

class Player : public IGameObject {
public:
    bool Start()  override;
    void Update() override;
    void Render(RenderContext& rc) override;

    void Damage(int amount);
    const Vector3& GetPosition() const { return m_position; }
    int  GetHp() const { return m_health.GetHp(); }
    bool IsAlive() const { return m_health.IsAlive(); }

private:
    void Move(float dt);
    void UpdateShot(float dt);

    Vector3 m_position = Vector3::Zero;

    HealthComponent  m_health;
    ShooterComponent m_shooter;
    ModelComponent   m_model;

    GOHandle<BulletPool> m_bulletPool;
};

メンバ：23個 → 5個

測ったもの4-01のときいま
Player のメンバ変数235
Player.cpp の行数420150
いちばん長い関数182行32行
ファイル数28（増えた）
ファイル数は増えます。これは代償です 「HPの処理を直したい」ときは、HealthComponent.h を 開けばよいので速くなりました。

一方「プレイヤーの動き全体を把握したい」ときは、 複数のファイルを開くことになります。

どちらが多いかで、分けるべきかが決まります。 100行のクラスを5個に割る必要はありません。

分けすぎの目安

  • コンポーネントのメンバが1〜2個しかない
  • そのコンポーネントを使っているクラスが1つしかない
  • Update() の中身が1行

3つとも当てはまるなら、分けずに元のクラスに戻したほうが読みやすいです。 戻すのも、立派なリファクタリングです（4-13）。

08確認

  1. コンポーネントに分ける、いちばんの利点は？
  2. まず「ただのメンバ」から始めるのを勧めるのはなぜ？
  3. ShooterComponent が Bullet を知らないほうがよいのはなぜ？
  4. 分けすぎたときのサインは？
答え
  1. 同じ機能を複数のクラスで使い回せること。 そして、直す場所が1か所になること。
  2. 速く、コンパイル時に検査が効き、コード量も少ないから。 実行中の付け外しが要らないなら、これで足りる。
  3. 知ってしまうと、その弾を使うクラスでしか使えなくなるから。
  4. メンバが1〜2個、使っているクラスが1つ、 Update() が1行。
