はじめてのシェーダ改造

難易度 ／ 前提 3-02

01この章でできるようになること

  • 自分専用のシェーダファイルを持てる
  • ピクセルシェーダを書き換えて、見た目を変えられる
  • シェーダのエラーの直し方が分かる

02sprite.fx を直接いじってはいけません

共有ファイルです Assets/shader/sprite.fx は、 SpriteRender を使っているものすべてが使っています。 エンジンのポストエフェクトの一部も使っています。
直接書き換えると、ゲーム中のあらゆる2D表示が変わってしまいます。

だから、コピーして自分のファイルを作ります。

  1. Assets/shader/sprite.fx をコピー
  2. Assets/shader/myBullet.fx という名前で保存

03でも SpriteRender ではシェーダを指定できません

SpriteRender::Init の中を見ると、 シェーダのパスが決め打ちになっています。 

void SpriteRender::Init(const char* filePath, const float w, const float h,
                        AlphaBlendMode alphaBlendMode)
{
    SpriteInitData initData;
    initData.m_ddsFilePath[0] = filePath;
    initData.m_fxFilePath = "Assets/shader/sprite.fx";   // ★ 固定
    ...
}

ここが、いままで「かゆいところに手が届かない」と感じていた場所です。 SpriteRender は便利にするために選択肢を減らしたクラスなのです。

では、どうするか。SpriteRender を使わず、 自分で同じものを作ります。 中身は Sprite クラスなので、それを直接使えばよいのです。

04自分の描画クラスを作る

// MySpriteRender.h
#pragma once

class MySpriteRender : public IRenderer
{
public:
    void Init(const char* ddsFilePath, const char* fxFilePath,
              float w, float h);
    void Update();
    void Draw(RenderContext& rc);

    void SetPosition(const Vector3& pos) { m_position = pos; }
    void SetScale(const Vector3& scale)  { m_scale = scale; }

private:
    // レンダリングエンジンから、2D描画のタイミングで呼ばれる。
    void OnRender2D(RenderContext& rc) override
    {
        m_sprite.Draw(rc);
    }

private:
    Sprite     m_sprite;
    Vector3    m_position = Vector3::Zero;
    Quaternion m_rotation = Quaternion::Identity;
    Vector3    m_scale    = Vector3::One;
};
// MySpriteRender.cpp
#include "stdafx.h"
#include "MySpriteRender.h"

void MySpriteRender::Init(const char* ddsFilePath, const char* fxFilePath,
                          float w, float h)
{
    SpriteInitData initData;
    initData.m_ddsFilePath[0] = ddsFilePath;
    initData.m_fxFilePath     = fxFilePath;      // ★ 自分のシェーダを指定
    initData.m_width          = (UINT)w;
    initData.m_height         = (UINT)h;
    initData.m_alphaBlendMode = AlphaBlendMode_Trans;

    m_sprite.Init(initData);
}

void MySpriteRender::Update()
{
    m_sprite.Update(m_position, m_rotation, m_scale);
}

void MySpriteRender::Draw(RenderContext& rc)
{
    // ここでは描かず、レンダリングエンジンに「描いてほしい」と登録する。
    g_renderingEngine->AddRenderObject(this);
}
ここ意味
: public IRenderer 「描画される側」の仲間だと名乗る
SpriteInitData Sprite の全部の設定ができる構造体
m_fxFilePath 自分のシェーダを指定できる
Draw() の中の AddRenderObject ここでは描かず、あとで呼んでと登録する
OnRender2D() 2D描画のタイミングで、エンジンから呼ばれる
なぜ Draw() で描かないのか IGameObject::Render() が呼ばれる時点では、 まだ3Dも描かれていません。 そこで2Dを描いたら、あとから3Dに上書きされてしまいます。
だから「描いてほしい人リスト」に登録だけして、 正しい順番が来たら呼んでもらう形になっています。 これは SpriteRender とまったく同じやり方です。

05使う

// Bullet.h
private:
    MySpriteRender m_spriteRender;

// Bullet.cpp
bool Bullet::Start()
{
    m_spriteRender.Init(
        "Assets/sprite/bullet.dds",
        "Assets/shader/myBullet.fx",     // ★ 自分のシェーダ
        16.0f, 32.0f);
    return true;
}

void Bullet::Update()
{
    ...
    m_spriteRender.SetPosition(m_position);
    m_spriteRender.Update();
}

void Bullet::Render(RenderContext& rc)
{
    m_spriteRender.Draw(rc);
}

使い方は SpriteRender とほとんど同じです。 まずこの状態で、いままでどおり描けることを確認してください。

06いよいよ書き換える

myBullet.fx の PSMain を書き換えます。

その1 ― 真っ赤にする

float4 PSMain( PSInput In ) : SV_Target0
{
    return float4(1.0f, 0.0f, 0.0f, 1.0f);      // 問答無用で赤
}

テクスチャを完全に無視して、赤い四角になります。 まずこれで「自分のシェーダが使われている」ことを確認してください。

その2 ― 元の色を残しつつ赤くする

float4 PSMain( PSInput In ) : SV_Target0
{
    float4 color = colorTexture.Sample(Sampler, In.uv) * mulColor;
    color.g *= 0.3f;        // 緑を弱める
    color.b *= 0.3f;        // 青を弱める
    return color;           // → 赤が目立つ
}

その3 ― 白黒にする

float4 PSMain( PSInput In ) : SV_Target0
{
    float4 color = colorTexture.Sample(Sampler, In.uv) * mulColor;

    // 人間の目は緑を明るく感じるので、重みをつけて足す。
    float gray = dot(color.rgb, float3(0.299f, 0.587f, 0.114f));

    return float4(gray, gray, gray, color.a);
}

その4 ― 色を反転する

float4 PSMain( PSInput In ) : SV_Target0
{
    float4 color = colorTexture.Sample(Sampler, In.uv) * mulColor;
    color.rgb = 1.0f - color.rgb;      // 1から引くと反転
    return color;
}
シェーダを直したら、ビルドは要りません .fx は実行時に読み込まれます。 C++ のビルドは不要で、ゲームを再起動するだけで反映されます。
これは大きな利点です。試行錯誤のサイクルがとても速くなります。

07シェーダのエラー

シェーダの間違いは実行したときに分かります。 C++のようにビルドで止まってくれません。

症状原因
起動した瞬間に落ちる／固まる シェーダのコンパイルエラー
真っ黒／真っ白になる 計算は通っているが、値がおかしい
何も変わらない ファイルパスが違う（元の sprite.fx を見ている）

エラーの内容は、出力ウィンドウ （Ctrl+Alt+O）に出ます。 行番号とメッセージが書いてあります。 

myBullet.fx(31,12-17): error X3004: undeclared identifier 'colour'
1文字ずつ直して、こまめに実行する シェーダはデバッガでステップ実行できません。 10行まとめて書いて動かないと、原因が分かりません。
1〜2行書いたら実行、を繰り返してください。 ビルドが要らないので、これができます。

08演習

演習1（まねる）

MySpriteRender を作り、myBullet.fx をコピーして、上の「その1〜その4」を全部試す。

演習2（作る）

UVの位置によって色が変わるシェーダを書く。（In.uv は 0.0〜1.0 の2つの値です）

解答例を見る（まず自分でやってから） 
float4 PSMain( PSInput In ) : SV_Target0
{
    // UV をそのまま色にする
    return float4(In.uv.x, In.uv.y, 0.0f, 1.0f);
}

左下が黒、右に行くほど赤、上に行くほど緑のグラデーションになります。

これで UVがどう並んでいるかが目で見えます。 uv.x は左→右で 0→1、uv.y は上→下で 0→1 です。 （画像の座標系なので、上がYの0です）

元の色と混ぜることもできます。

float4 color = colorTexture.Sample(Sampler, In.uv) * mulColor;
// 下に行くほど暗くする
color.rgb *= (1.0f - In.uv.y);
return color;
この「UVを色にして見る」はデバッグの定番です シェーダで値がおかしいとき、その値を色にして画面に出すのが いちばん手っ取り早い確認方法です（3-02）。

演習3（自分で書く）

画像の外側だけを白く縁取りするシェーダを書いてみる。（ヒント：UVが端に近いかどうかで判定する）本文には答えがありません。

解答例を見る（まず自分でやってから） 
float4 PSMain( PSInput In ) : SV_Target0
{
    float4 color = colorTexture.Sample(Sampler, In.uv) * mulColor;

    // 画面端からの距離（0が端、0.5が中心）
    float2 d = min(In.uv, 1.0f - In.uv);
    float edge = min(d.x, d.y);

    const float WIDTH = 0.06f;
    if (edge < WIDTH) {
        color.rgb = float3(1.0f, 1.0f, 1.0f);   // 白
    }
    return color;
}

min(In.uv, 1.0f - In.uv) で、 左端からの距離と右端からの距離のうち、近いほうが出ます。 XとYの小さいほうを取れば「いちばん近い端までの距離」です。

if を使わない書き方もあります。

float isEdge = step(edge, WIDTH);        // edge < WIDTH なら 1、でなければ 0
color.rgb = lerp(color.rgb, float3(1,1,1), isEdge);
return color;
シェーダでは if を避けることがあります GPUは何百個ものピクセルを同時に処理しています。 if で処理が分かれると、両方の道を実行してから片方を捨てる ことがあり、遅くなる場合があります。
step() や lerp() で分岐せずに書くのは、 シェーダでよく使うテクニックです。
ただし、まずは読みやすさを優先してください。 速さが問題になってから直せば充分です。

09確認

  1. sprite.fx を直接編集してはいけない理由は？
  2. SpriteRender で自分のシェーダが使えないのはなぜ？ どうする？
  3. シェーダを直したあと、C++のビルドは必要？
  4. Draw() の中で直接描かないのはなぜ？
答え
  1. エンジン全体で共有しているので、他の2D表示も全部変わってしまうから。
  2. Init の中でパスが決め打ちだから。 Sprite と SpriteInitData を直接使って、自分で作る。
  3. 不要。.fx は実行時に読まれるので、再起動するだけでよい。
  4. その時点ではまだ3Dが描かれておらず、あとから上書きされてしまうから。 正しい順番で呼んでもらうために登録する。
