Observer ― 知らせる側と受け取る側を切る

難易度 ／ 前提 2-07

01この章でできるようになること

  • FindGO だらけのコードを整理できる
  • 敵を倒したとき、スコア・音・UI が勝手に反応する形にできる
  • 登録したまま消えるオブジェクトの事故を防げる

困りごと説明

03考え方 ― 「起きたこと」だけを放送する

04いちばん簡単な実装

std::function を並べておくだけです。 

// EventBus.h
#pragma once
#include <functional>
#include <vector>

/// <summary>敵が倒されたときの情報。</summary>
struct EnemyDeadEvent {
    Vector3 position;
    int     score;
};

/// <summary>
/// ゲーム中の出来事を、知りたい人に配る。
/// </summary>
class EventBus : public IGameObject {
public:
    using Handle = int;

    /// <summary>購読する。戻り値は解除に使う。</summary>
    Handle SubscribeEnemyDead(std::function<void(const EnemyDeadEvent&)> fn)
    {
        Handle h = m_nextHandle++;
        m_enemyDead.push_back({ h, std::move(fn) });
        return h;
    }

    /// <summary>購読をやめる。</summary>
    void Unsubscribe(Handle h)
    {
        m_enemyDead.erase(
            std::remove_if(m_enemyDead.begin(), m_enemyDead.end(),
                [h](const Entry& e) { return e.handle == h; }),
            m_enemyDead.end());
    }

    /// <summary>発行する。</summary>
    void PublishEnemyDead(const EnemyDeadEvent& ev)
    {
        // コピーしてから回す（購読側が解除しても安全にするため）
        auto copy = m_enemyDead;
        for (const auto& e : copy) {
            e.fn(ev);
        }
    }

private:
    struct Entry {
        Handle handle;
        std::function<void(const EnemyDeadEvent&)> fn;
    };
    std::vector<Entry> m_enemyDead;
    Handle m_nextHandle = 1;
};

05使う

// Enemy.cpp ― 放送するだけ
void Enemy::OnDead()
{
    EventBus* bus = FindGO<EventBus>("eventBus");
    if (bus != nullptr) {
        bus->PublishEnemyDead({ m_position, m_score });
    }
    Deactivate();
}
// ScoreManager.cpp ― 聞きに行く
bool ScoreManager::Start()
{
    EventBus* bus = FindGO<EventBus>("eventBus");
    m_handle = bus->SubscribeEnemyDead(
        [this](const EnemyDeadEvent& ev) {
            m_score += ev.score;
        });
    return true;
}

ScoreManager::~ScoreManager()
{
    // ★ ここが命綱
    EventBus* bus = FindGO<EventBus>("eventBus");
    if (bus != nullptr) {
        bus->Unsubscribe(m_handle);
    }
}
デストラクタでの解除を、絶対に忘れないでください 購読したまま DeleteGO されると、 ラムダが捕まえた this が解放済みのポインタになります。
次にイベントが発行されたとき、解放済みのメモリに書き込みます。
これは 2-08 でやった問題が、 もっと見つけにくい形で出てくるものです。

IGameObject に OnDestroy() はありませんが、 デストラクタは DeleteGO のときに必ず呼ばれます （2-05）。ここに書けば確実です。

06どこまで使うか

場面どちら
1つの出来事に、複数が反応する Observer
反応する相手が、あとから増えそうObserver
相手が1つで、これからも1つ FindGO で充分
毎フレーム呼ぶもの Observer にしない。直接呼ぶ
Observer の弱点：追いにくくなります 「誰がこのイベントに反応しているか」が、 コードを見ただけでは分かりません。 デバッガで追っても、いきなりラムダに飛びます。
イベントの種類は、増やしすぎないでください。 5〜10種類くらいが扱える上限です。

起きること

  • 運が良ければ、その場でクラッシュする
  • 運が悪いと、しばらく動いてから別の場所で落ちる
  • Release ビルドでだけ落ちる、ということもある
2つめがいちばん厄介です 解放されたメモリは、すぐには他人に使われません。 しばらくは中身が残っているので、 m_combo++ が「成功してしまう」ことがあります。

そして数秒後、そのメモリが別のオブジェクトに再利用されたとき、 まったく関係ない場所で不可解な値が出ます。

2-08 でやった話と同じですが、 今回は Enemy 側のコードを見ても、 ComboUi の名前がどこにも出てきません。 これが Observer のいちばんの怖さです。

直し方1 ― デストラクタで解除する（基本）

直し方2 ― 忘れられないようにする（おすすめ）

LV3 までに3回出てきた RAII を、ここでも使います。 

// Subscription.h
/// <summary>
/// 購読を持っておき、壊れるときに自動で解除するもの。
/// </summary>
class Subscription {
public:
    Subscription() = default;
    Subscription(EventBus* bus, EventBus::Handle h)
        : m_bus(bus), m_handle(h) {}

    ~Subscription() { Reset(); }

    // コピーは禁止。ムーブだけ許す
    Subscription(const Subscription&) = delete;
    Subscription& operator=(const Subscription&) = delete;

    Subscription(Subscription&& other) noexcept { *this = std::move(other); }
    Subscription& operator=(Subscription&& other) noexcept
    {
        Reset();
        m_bus = other.m_bus;
        m_handle = other.m_handle;
        other.m_bus = nullptr;
        return *this;
    }

    void Reset()
    {
        if (m_bus != nullptr) {
            m_bus->Unsubscribe(m_handle);
            m_bus = nullptr;
        }
    }

private:
    EventBus*         m_bus = nullptr;
    EventBus::Handle  m_handle = 0;
};
// ComboUi.h
private:
    Subscription m_deadSub;      // ★ これを持つだけ

// ComboUi.cpp
bool ComboUi::Start()
{
    EventBus* bus = FindGO<EventBus>("eventBus");
    m_deadSub = Subscription(bus,
        bus->SubscribeEnemyDead([this](const EnemyDeadEvent& ev) {
            m_combo++;
        }));
    return true;
}

// ★ デストラクタを書かなくてよい。Subscription が勝手に解除する
RAII は、これで4回目です
もの壊れるときに何をするか
GOHandle（持つだけ。生死を安全に確認できる）
DebugGuiPanelパネルの登録を解除する
K2_PROFILE_SCOPE計測を終了する
Subscription購読を解除する
std::unique_ptrdelete する
「後始末を、忘れようがない場所に置く」 ―― C++ でいちばん価値のある考え方です。

解除し忘れの事故は、この型を一度作れば、二度と起きません。

08確認

  1. Observer にすると、依存の矢印はどうなる？
  2. 購読したまま削除されると、何が起きる？
  3. 解除を忘れないようにする、いちばん確実な方法は？
  4. Observer にしないほうがよいのは、どんなとき？
答え
  1. 逆になる。知らせる側が相手を知らず、 受け取る側が自分から購読しに行く。
  2. ラムダが捕まえた this が解放済みになり、 次の発行で解放済みメモリに触る。
  3. 購読を RAII の型（Subscription）に持たせ、 デストラクタで自動的に解除する。
  4. 相手が1つで増えないとき。毎フレーム呼ぶとき。
