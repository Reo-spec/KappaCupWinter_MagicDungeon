LV1 入門 ／ 1-13

ヘッダと cpp の分け方

難易度 ／ 前提 1-12

01この章でできるようになること

  • .h と .cpp の役割を説明できる
  • #pragma once が何のためにあるか分かる
  • 自分で新しいクラスのファイルを作れる

02#include は「貼り付け」

まず、これを知ってください。 #include "Enemy.h" は、 そのファイルの中身をその場に丸ごと貼り付ける、という意味です。

03何をどちらに書くか

.h（ヘッダ）.cpp（ソース）
役割説明書（何があるか）中身（どう動くか）
クラスの形書く—
メンバ変数書く—
関数宣言だけ（void Move();） 中身（void Enemy::Move() { ... }）

ただし、1〜2行の短い関数は .h に書いてしまってもよい 決まりになっています。 

// Enemy.h
class Enemy {
public:
    int  GetHp() const { return m_hp; }    // 短いので .h に書いてよい
    void Move();                            // 長いので .cpp に
private:
    int m_hp = 100;
};

04#pragma once

.h のいちばん上には、必ずこれを書きます。 

#pragma once

意味は「このファイルは、1回だけ貼り付けてください」です。

無いとどうなるか。 Game.cpp が Enemy.h と Player.h を読み込み、 Player.h も Enemy.h を読み込んでいたら、 Enemy クラスの定義が2回貼り付けられます。 「同じ名前のクラスが2つある」とエラーになります。

忘れてもすぐ気づけます error C2011: 'Enemy': 'class' 型の再定義 というエラーが出ます。 #pragma once を書き忘れたな、と思ってください。

05.cpp の書き出し

// Enemy.cpp
#include "stdafx.h"      // ★ 必ず、いちばん最初の行
#include "Enemy.h"

void Enemy::Move()
{
    ...
}
#include "stdafx.h" は必ず1行目 2行目以降に書くと、 fatal error C1010: プリコンパイル済みヘッダーを検索中に 予期しない EOF が見つかりました という、意味の分からないエラーが出ます。
新しく .cpp を作ったら、まずこの1行。

stdafx.h はプリコンパイル済みヘッダといって、 よく使うものをまとめて先に用意しておく仕組みです。 これのおかげでビルドが速くなっています。

06新しいクラスを作る手順

  1. ソリューションエクスプローラーの Game を右クリック
  2. 追加 → 新しい項目 → ヘッダー ファイル (.h) → Enemy.h
  3. 同じく C++ ファイル (.cpp) → Enemy.cpp
  4. Enemy.h に #pragma once とクラス定義
  5. Enemy.cpp に #include "stdafx.h" と #include "Enemy.h"
  6. 使う側で #include "Enemy.h"

07よくあるエラー

C1010 予期しない EOF

原因：#include "stdafx.h" が無い、または1行目ではない。

C2011 型の再定義

原因：#pragma once の書き忘れ。

LNK2005 シンボルが既に定義されています

原因：.h に関数の中身を書いてしまった （クラスの外に）。
直し方：.cpp に移す。

C2065 定義されていない識別子（クラス名）

原因：#include を忘れている。

08演習

演習1（まねる）

Enemy.h と Enemy.cpp を新しく作って、Game.cpp から使う。

演習2（壊して確かめる）

Enemy.h から #pragma once を消して、Game.cpp で2回 #include "Enemy.h" する。どんなエラーが出るか見る。

解答例を見る（まず自分でやってから） 
// Game.cpp
#include "stdafx.h"
#include "Enemy.h"
#include "Enemy.h"      // わざと2回
error C2011: 'Enemy': 'class' 型の再定義です

「同じクラスが2つある」と怒られます。

#pragma once を戻すと、2回書いても何も起きません。 2回目以降は無視されるからです。

実際には、こんな直接的な形では起きません A.h が C.h を、B.h も C.h を読み込んでいて、 Game.cpp が A.h と B.h を読み込む。 こういう形で、知らないうちに2回読み込まれます。
だから #pragma once は例外なく全部の .h に書きます。

演習3（調べる）

Enemy.h を1文字だけ書き換えて、ビルドにかかる時間を測る。次に Enemy.cpp を1文字書き換えて、同じように測る。どちらが速いか、なぜか。

解答例を見る（まず自分でやってから）

.cpp を変えたほうが、圧倒的に速いはずです。

変えたもの作り直されるファイル
Enemy.cppEnemy.cpp だけ
Enemy.h Enemy.h を #include している すべての .cpp

.h は「貼り付けられる」ものなので、 貼り付け先を全部作り直す必要があります。

だから「.h には最小限しか書かない」 大規模なゲーム開発では、ヘッダを1つ直すとビルドに30分 ということが実際に起こります。
だから現場では、
  • .h に #include を書きすぎない
  • 代わりに前方宣言（class Enemy; とだけ書く）を使う
といった工夫をします。この話は LV5-15 ビルド時間を短くする で扱います。

09確認

  1. #include は何をしている？
  2. #pragma once は何のため？
  3. .cpp の1行目に必ず書くものは？
答え
  1. そのファイルの中身を、その場に丸ごと貼り付ける。
  2. 同じヘッダが2回以上貼り付けられるのを防ぐため。
  3. #include "stdafx.h"。
