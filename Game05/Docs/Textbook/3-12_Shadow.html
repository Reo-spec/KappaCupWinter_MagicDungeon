LV3 表現 ／ 3-12

影（シャドウマップ）

難易度 ／ 前提 3-11

01この章でできるようになること

  • 影を落とせる・受けられる
  • 影が出ないときに、どこを見ればいいか分かる
  • シャドウマップの仕組みが説明できる

02使い方は2行

// 影を落とす側（キャラクターなど）
m_modelRender.SetShadowCasterFlag(true);

// 影を受ける側（地面など）
m_modelRender.Init("Assets/modelData/ground.tkm",
    nullptr, 0, enModelUpAxisZ,
    true);                        // ★ isShadowReciever

isShadowReciever の既定値は true なので、 受ける側はふつう何もしなくてよいです。 落とす側の SetShadowCasterFlag(true) を忘れがちです。

影を出すには、ディレクションライトの SetCastShadow(true) も必要です。 F1 の Lighting パネルから確認できます。

03仕組み ― 「光から見えるか」を調べている

04影が出ないときのチェックリスト

見るところ確認
キャスター指定 SetShadowCasterFlag(true) を呼んだか
ライトの影フラグ F1 → Lighting → Cast Shadow が ON か
レシーバ 地面の isShadowReciever が true か
ライトの向き 真横 {1,0,0} だと影が地面に落ちない
位置関係 キャラが地面にめり込んでいないか
範囲 シャドウマップの描画範囲の外に出ていないか

上の2つがほとんどです。 順に確認してください。

05影がおかしいときの用語

症状名前原因
縞模様の影が全体に出る シャドウアクネ 距離の比較で、自分自身を影と判定してしまっている
影が本体から離れて浮く ピーターパン現象 アクネ対策のずらし量が大きすぎる
影のふちがガタガタ エイリアシング シャドウマップの解像度が足りない
名前を知っていることに意味があります 「影が縞々になる」で検索しても何も出ませんが、 「shadow acne」なら山ほど情報が出ます。
現象に名前が付いている＝みんなが通った道ということです。

06軽い影で済ませる手もある

シャドウマップは重い処理です。 すべてのオブジェクトに本物の影が要るとは限りません。

やり方コスト見た目
シャドウマップ重い正確
丸影（足元に黒い円を置く） ほぼゼロ 充分なことが多い

丸影は、乗算合成のスプライトを地面に置くだけです （3-07）。 小さな敵が大量に出るゲームでは、こちらのほうが現実的です。

07演習

演習1（まねる）

キャラクターに影を落とさせる。SetShadowCasterFlag を外すと消えることも確認する。

演習2（動かす）

3-11 の時間帯切り替えと組み合わせて、影の向きと長さが変わることを確認する。

解答例を見る（まず自分でやってから）

やることは 3-11 の演習2そのままです。 ライトの向きを変えるだけで、影も一緒に動きます。

ライトの向き影
{0, -1, 0}（真上から）足元に小さく
{1, -1, 0}（斜め45度）斜め後ろに、身長ぶん
{1, -0.2f, 0}（ほぼ真横） とても長く伸びる（夕方の感じ）

Y成分（下向きの強さ）が、影の長さを決めます。 0 に近づけるほど長くなります。

真横に近づけすぎると、影が消えます {1, 0, 0} のように完全に水平にすると、 影が地面に落ちる場所が無限遠になり、 シャドウマップの範囲外に出てしまいます。

Y は最小でも -0.15 くらいまでにしてください。

演習3（作る）

丸影を自作する。地面に置いた乗算合成のスプライトを、キャラクターの真下に追従させる。

解答例を見る（まず自分でやってから）

3Dで地面に貼るので、板ポリゴンのモデルを使うか、 ModelRender で薄い円盤のモデルを出すのが素直です。 ここではモデルを使う版を示します。 

// Player.h
private:
    ModelRender m_shadowRender;

// Player.cpp
bool Player::Start()
{
    m_modelRender.Init("Assets/modelData/player.tkm");
    m_modelRender.SetShadowCasterFlag(false);      // 本物の影は使わない

    // 丸影用の、薄い円盤モデル
    m_shadowRender.Init("Assets/modelData/roundShadow.tkm");
    m_shadowRender.SetShadowCasterFlag(false);
    return true;
}

void Player::Update()
{
    m_modelRender.SetPosition(m_position);
    m_modelRender.Update();

    // 足元より、ほんの少し上に置く
    Vector3 shadowPos = m_position;
    shadowPos.y += 1.0f;                            // ★ Zファイティング対策

    // 高いところにいるほど、薄く小さく
    float h    = max(m_position.y, 0.0f);
    float rate = max(1.0f - h / 500.0f, 0.0f);

    m_shadowRender.SetPosition({ shadowPos.x, 1.0f, shadowPos.z });
    m_shadowRender.SetScale({ rate, rate, rate });
    m_shadowRender.Update();
}

大事な3点

やること理由
地面より少しだけ上に置く 同じ高さだとZファイティングでちらつく
Y は地面に固定する ジャンプしても影は地面に残る
高さで小さく・薄くする ジャンプの高さが分かるようになる
丸影には、影以上の役目があります 3Dアクションで「いま自分がどこの真上にいるか」を プレイヤーに伝えるのは、丸影の仕事です。
本物の影よりゲームとして大事なことすらあります。 だから、シャドウマップが使える時代でも丸影は使われ続けています。

08確認

  1. シャドウマップには何が記録されている？
  2. 描画は何回行われる？
  3. 影が出ないとき、最初に疑う2つは？
  4. 縞模様の影が出る現象の名前は？
答え
  1. ライトから各ピクセルまでの距離。
  2. 2回（ライトから見た距離の描画＋通常の描画）。
  3. SetShadowCasterFlag(true) と、 ライトの Cast Shadow。
  4. シャドウアクネ（shadow acne）。
