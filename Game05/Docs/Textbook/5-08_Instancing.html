ドローコールとインスタンシング

難易度 ／ 前提 5-01 , 3-09

01この章でできるようになること

  • 同じモデルを1000個出しても重くならない
  • ドローコールがなぜコストなのか説明できる
  • k2Engine のインスタンシング機能を使える

02ドローコール1回のコスト

3-16 で見たとおり、 1回の描画は「準備 → 描け」の繰り返しでした。 

rc.SetPipelineState(...)        // ★ 状態を切り替える
rc.SetVertexBuffer(...)
rc.SetIndexBuffer(...)
rc.SetDescriptorHeap(...)
rc.DrawIndexed(...)             // ★ 描け
コストの中身説明
CPU側：コマンドを積む これが本体。1回あたり数マイクロ秒
GPU側：状態を切り替える パイプラインの流れが途切れる
定数バッファの更新 オブジェクトごとに行列を送る
ドローコールは、CPU のコストです 「GPUが重い」と思いがちですが、 多くの場合ボトルネックは「CPUがコマンドを積む時間」です。
三角形が少なくても、ドローコールが多ければ遅くなります。

目安：1フレームに 1000〜3000 回を超えたら、対策どき。 F1 → Profiler の Draw Call で見られます。

03インスタンシング ― 1回で何個も描く

同じモデルを、位置だけ変えて何個も描くなら、 コマンドは1回で済みます。 

いままで：
  [準備][描け] [準備][描け] [準備][描け] ... × 1000

インスタンシング：
  [準備][1000個まとめて描け]

位置・回転・拡大の情報をまとめて1つのバッファに入れて、 GPUに渡します。 シェーダ側で「自分は何番目か」を見て、対応する行列を使います。

条件インスタンシングできる？
同じモデル必須
同じマテリアル・シェーダ必須
位置・回転・大きさが違う問題なし
色を変えたいインスタンスごとのデータに含めれば可能
別々のアニメーションk2Engine では非対応

04k2Engine での書き方

ModelRender::Init() の 最後のほうにある maxInstance を指定します。 

// 初期化（1回だけ）
m_modelRender.Init(
    "Assets/modelData/star.tkm",
    nullptr,                // アニメーションクリップ
    0,                      // その数
    enModelUpAxisZ,
    true,                   // 影を受ける
    1000);                  // ★ maxInstance
// 毎フレーム：インスタンスごとに位置を渡す
void StarRender::Update()
{
    for (int i = 0; i < m_numStar; i++) {
        m_modelRender.UpdateInstancingData(
            i,                      // 何番目か
            m_positions[i],
            m_rotations[i],
            m_scales[i]);
    }
    m_modelRender.Update();
}

void StarRender::Render(RenderContext& rc)
{
    m_modelRender.Draw(rc);         // ★ これ1回で全部描かれる
}
Sample_22 に動く例があります Sample/Sample_22 の Sphere / SphereRender / Muscle / MuscleRender を見てください。
ゲームパッドの A ボタンで、 インスタンシングあり／なしを切り替えられます。 FPSの違いを、自分の目で見られます。
アニメーション付きのインスタンシングは非対応です Sample/readme.txt にも 「アニメーションありインスタンシング描画のみNG」 と書かれています。
動かない背景オブジェクト、弾、星、草などに使ってください。

05設計のパターン

Sample_22 の構成が、そのまま参考になります。

クラス役割
Sphere 1個ぶんの状態（位置・動き）。描画はしない
SphereRender ModelRender を1つだけ持ち、全部まとめて描く

描画を1か所に集めるのが要点です。 これは 5-06 でやった BulletSystem の形と同じです。 

// SphereRender は、Sphere から位置を集める
void SphereRender::Update()
{
    int i = 0;
    for (Sphere* s : FindGOs<Sphere>("sphere")) {
        m_modelRender.UpdateInstancingData(
            i++, s->GetPosition(), s->GetRotation(), s->GetScale());
    }
    m_modelRender.Update();
}
優先度に注意してください SphereRender は、 Sphere より後の優先度にしてください。
先に動くと、1フレーム前の位置を集めることになります。 （3-10 のカメラと同じ話です）

06ほかにドローコールを減らす方法

方法効き方手間
画面外のものを描かない（カリング） 大きい中
インスタンシング大きい小
遠いものを簡略化（LOD）中大
テクスチャをまとめる（アトラス） 中。2Dで効く中
小さいモデルを1つに統合する中大

いちばん効くのはカリングです。 5-01 の 「そもそもやらない」に当たります。 

void Enemy::Render(RenderContext& rc)
{
    // カメラの後ろにいたら、描かない
    Vector3 toEnemy = m_position - g_camera3D->GetPosition();
    if (toEnemy.Dot(g_camera3D->GetForward()) < 0.0f) {
        return;
    }
    // 遠すぎたら、描かない
    if (toEnemy.LengthSq() > DRAW_DISTANCE * DRAW_DISTANCE) {
        return;
    }
    m_modelRender.Draw(rc);
}
数行で、ドローコールが半分以下になることがあります カメラの後ろにいるものは、全体の半分近くあることも珍しくありません。
内積1回で判定できます（3-11）。

演習2（使う）

自分のゲームで同じモデルを大量に出すもの（弾、背景、星など）を、インスタンシングにする。

解答例を見る（まず自分でやってから）

設計 ― 状態と描画を分ける

// Star.h ― 1個ぶんの状態。描画しない
class Star : public IGameObject {
public:
    bool Start()  override;
    void Update() override;
    // ★ Render を持たない

    const Vector3&    GetPosition() const { return m_position; }
    const Quaternion& GetRotation() const { return m_rotation; }
    const Vector3&    GetScale()    const { return m_scale; }

    void SetPosition(const Vector3& p) { m_position = p; }

private:
    Vector3    m_position = Vector3::Zero;
    Quaternion m_rotation = Quaternion::Identity;
    Vector3    m_scale    = Vector3::One;
    float      m_angle    = 0.0f;
};

void Star::Update()
{
    // くるくる回る
    m_angle += 60.0f * g_gameTime->GetFrameDeltaTime();
    if (m_angle > 360.0f) { m_angle -= 360.0f; }
    m_rotation.SetRotationDegY(m_angle);
}
// StarRender.h ― まとめて描く。1個だけ作る
class StarRender : public IGameObject {
public:
    bool Start()  override;
    void Update() override;
    void Render(RenderContext& rc) override;

private:
    static const int MAX_STAR = 1000;
    ModelRender m_modelRender;
    int         m_numDraw = 0;
};

// StarRender.cpp
bool StarRender::Start()
{
    m_modelRender.Init(
        "Assets/modelData/star.tkm",
        nullptr, 0,
        enModelUpAxisZ,
        false,              // 影は受けない（軽くする）
        MAX_STAR);          // ★ インスタンシング
    m_modelRender.SetShadowCasterFlag(false);
    return true;
}

void StarRender::Update()
{
    const auto& stars = FindGOs<Star>("star");

    m_numDraw = 0;
    for (Star* s : stars) {
        if (m_numDraw >= MAX_STAR) { break; }     // ★ あふれ対策

        m_modelRender.UpdateInstancingData(
            m_numDraw,
            s->GetPosition(),
            s->GetRotation(),
            s->GetScale());
        m_numDraw++;
    }
    m_modelRender.Update();
}

void StarRender::Render(RenderContext& rc)
{
    if (m_numDraw == 0) { return; }
    m_modelRender.Draw(rc);        // ★ 1回
}
// GameScene.cpp
bool GameScene::Start()
{
    for (int i = 0; i < 1000; i++) {
        Star* s = NewGO<Star>(enPriority_Background, "star");
        s->SetPosition(RandomPosition());
    }
    // ★ Star より後の優先度
    NewGO<StarRender>(enPriority_BackgroundRender, "starRender");
    return true;
}

結果の例

                       個別描画    インスタンシング
Draw Call                 1000            1
Frame                   28.4 ms      16.1 ms
FPS                        35           60
FindGOs を毎フレーム呼ぶのは、少しもったいない FindGOs は名前で検索するので、 それ自体にコストがあります。

数が固定なら、StarRender 側に std::vector<Star*> を持たせて、 生成時に登録するほうが速いです。 
void StarRender::Register(Star* s) { m_stars.push_back(s); }
ただし、削除されたときの管理が必要になります。 GOHandle を使うか、 そもそも Star を IGameObject にせず、 StarRender が直接データを持つ（5-06 の形） のが、いちばん速くて安全です。

演習3（減らす）

カリングを入れて、ドローコールがどれくらい減るか測る。F1 の Draw Call を、入れる前と後で比べる。

解答例を見る（まず自分でやってから）

段階1 ― 距離でカリング（いちばん簡単）

namespace {
    const float DRAW_DISTANCE = 3000.0f;
}

void Enemy::Render(RenderContext& rc)
{
    Vector3 toMe = m_position - g_camera3D->GetPosition();
    if (toMe.LengthSq() > DRAW_DISTANCE * DRAW_DISTANCE) {
        return;                       // 遠すぎる
    }
    m_modelRender.Draw(rc);
}

段階2 ― カメラの後ろを除外

void Enemy::Render(RenderContext& rc)
{
    Vector3 toMe = m_position - g_camera3D->GetPosition();

    // ★ 内積がマイナス = カメラの後ろ
    if (toMe.Dot(g_camera3D->GetForward()) < 0.0f) {
        return;
    }
    if (toMe.LengthSq() > DRAW_DISTANCE * DRAW_DISTANCE) {
        return;
    }
    m_modelRender.Draw(rc);
}

段階3 ― 画角も考える（視錐台カリングの簡易版）

void Enemy::Render(RenderContext& rc)
{
    Vector3 toMe = m_position - g_camera3D->GetPosition();
    float dist = toMe.Length();
    if (dist > DRAW_DISTANCE) { return; }

    if (dist > 0.001f) {
        toMe /= dist;                              // 正規化
        float d = toMe.Dot(g_camera3D->GetForward());

        // 画角60度なら、半分の30度。少し余裕をもって cos(45度) で判定
        if (d < 0.707f) { return; }
    }
    m_modelRender.Draw(rc);
}

結果の例（3Dシューティング、敵200体）

段階Draw CallFrame
なし41221.3 ms
距離のみ28817.8 ms
+ 後ろを除外151 13.2 ms
+ 画角9811.9 ms
「後ろを除外」だけで、半分近く減ります コードは1行、内積1回です。

これが 5-01 で言った 「そもそもやらない」が、いちばん効くという意味です。
カリングしすぎて、見えるべきものが消えないように 大きいオブジェクトは、中心がカメラの後ろでも、 一部が画面に映っていることがあります。

判定を「中心」ではなく「中心 ± 半径」でやるか、 判定を少し甘めにしてください。 
// 半径ぶん甘くする
if (toMe.Dot(forward) < -m_boundingRadius) { return; }
「たまに消える」は、「少し遅い」よりずっと悪いです。
影のカリングも忘れずに カメラに映っていなくても、 影がシャドウマップに描かれていることがあります （3-12）。

遠くのものは SetShadowCasterFlag(false) にすると、 シャドウマップのドローコールも減ります。

08確認

  1. ドローコールのコストは、主に CPU と GPU のどちら？
  2. インスタンシングの条件は？
  3. k2Engine でインスタンシングを有効にするには？
  4. ドローコールを減らす方法で、いちばん効くのは？
答え
  1. CPU。コマンドを積む時間。
  2. 同じモデル・同じマテリアルであること。 （k2Engine ではアニメーションなし）
  3. ModelRender::Init() に maxInstance を渡し、 UpdateInstancingData() で位置を渡す。
  4. カリング（画面外のものを描かない）。
