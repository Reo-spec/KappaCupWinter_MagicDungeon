01この章でできるようになること

  • いま生きているゲームオブジェクトを、画面で一覧できる
  • 「消し忘れ」を数字で見つけられる
  • 前の章で学んだ「死亡予約 → 実際の破棄」のズレを、目で確認できる

02開き方

ゲームを実行すると、画面のいちばん上に黒いメニューバーが出ています。 F1 キーで表示・非表示が切り替わります。

  1. メニューバーの GameObject をクリック
  2. GameObject List を選ぶ

04実験1 ― 1フレームだけ DEAD になるのを見る

前の章で学んだ「死亡予約 → 次のフレームで破棄」を、目で確認します。

  1. ゲームを実行して GameObject List を開く
  2. どれかの行の DeleteGO ボタンを押す
  3. その行が赤い DEAD になり、次の瞬間に行ごと消える

速すぎて見えない場合は、Show dead のチェックが入っているか確認してください。 それでも一瞬です。それが正常です。 1フレーム（60分の1秒）しか存在しない状態だからです。

ゆっくり見たいときは ブレークポイントを Enemy の Update() に置いて、 F10 で1フレームずつ進めてください。 止めるたびにパネルの表示も更新されます。 1-18 デバッガを使う でやった操作です。

05実験2 ― 消し忘れを見つける

これがこのパネルのいちばんの使いどころです。 わざと消し忘れたコードを書いて、数字が増えていくのを見ます。 

void Bullet::Update()
{
    m_position.y += m_speed * g_gameTime->GetFrameDeltaTime();

    // わざと消し忘れる。画面の外に出ても DeleteGO しない。
    // if (m_position.y > 600.0f) {
    //     DeleteGO(this);
    //     return;
    // }
}

この状態で弾を撃ち続けて、パネルの Alive を見てください。

  • 撃つたびに Alive が増える
  • 画面から弾が消えても、数字は減らない
  • Filter に bullet と打つと、弾だけが並んで、その多さが分かる

コメントアウトを戻すと、画面外に出た弾がちゃんと消えて、 Alive が一定のところで落ち着きます。

「なんか重い」の正体はだいたいこれです 見えないだけで、消し忘れたオブジェクトは Update され続けています。 ゲームが重いと感じたら、まず Alive を見てください。 増え続けていたら、それが原因です。

06そのほかの使い方

やりたいことやり方
特定の種類だけ見たいFilter に名前の一部を打つ（例：enemy）
優先度ごとの数を見たいGroup by prio にチェック。見出しに個数が出る
あるオブジェクトだけ動きを止めたいDeactivate ボタン。消さずに Update だけ止まる
消したときの挙動を試したいDeleteGO ボタン。コードを書かずに試せる
Deactivate と DeleteGO の違い Deactivate は一時停止、DeleteGO は削除です。 Deactivate() されたオブジェクトは Update/Render が止まるだけで、 メモリにはそのまま残り、Activate() で復活できます。 「ポーズ中だけ敵を止めたい」ようなときに使います。

07演習

演習1（まねる）

実験2をやって、消し忘れたときと直したときで Alive がどう変わるかを見る。

演習2（数字を変える）

自機を Deactivate してみる。動かなくなるが、画面からも消えるはず。 なぜ消えるのか、IGameObject の RenderWrapper() を読んで確かめる。

解答例を見る（まず自分でやってから）

画面からも消えます。理由は IGameObject にあります。 

void RenderWrapper(RenderContext& renderContext)
{
    if (m_isActive && m_isStart && !m_isDead) {   // ← m_isActive を見ている
        Render(renderContext);
    }
}

Deactivate() は m_isActive を false にします。 UpdateWrapper() と RenderWrapper() の両方が このフラグを見ているので、動かなくなると同時に、描かれなくもなります。

「動きだけ止めて、絵は出したままにしたい」（ポーズ画面など）場合は、 Deactivate() ではなく自分でフラグを持って Update() の中身をスキップしてください。

演習3（自分で書く）

自分のゲームを1分間遊んで、Alive が増え続けていないことを確認する。 増えていたら、どのオブジェクトが残っているかを Filter で特定して直す。 本文には答えがありません。

解答例を見る（まず自分でやってから）

手順はこうです。

  1. GameObject List を開いたまま1分遊ぶ
  2. Alive が増え続けていたら、Filter に思い当たる名前を打つ （bullet、enemy、effect など）
  3. 数が増え続けている種類が犯人
  4. そのクラスの Update() に「消える条件」が書いてあるか確認する

よくある犯人

種類消し忘れの原因
弾画面外の判定がない／判定の値が広すぎる
敵画面の下に抜けたあと消していない
エフェクトループ再生になっている
サウンドPlay(true) で鳴らして消していない

増えていなければ、それが正解です。 「問題が無いことを確認できた」も立派な結果です。

08確認

  1. Alive が遊んでいるうちに増え続けていたら、何を疑う？
  2. Dead(waiting) はどういう状態のオブジェクトの数？
  3. Deactivate と DeleteGO の違いは？
答え
  1. DeleteGO の消し忘れ。画面から見えなくても動き続けている。
  2. DeleteGO されたが、まだ delete されていないもの。 次のフレームの先頭で消える。
  3. Deactivate は一時停止（メモリは残り、復活できる）。 DeleteGO は削除（次のフレームで消える）。
